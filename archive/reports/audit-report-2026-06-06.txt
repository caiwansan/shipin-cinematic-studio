1. 安全与认证审计（后端安全/认证）
================================================================================

【严重程度: 高】.env 文件包含明文凭据 —— 密钥硬编码泄漏
  问题: .env 和 .env.bak 文件包含大量生产环境明文 API Key/Secret。
        阿里云 DashScope: sk-fe9bfcb6ce4a45c6b40ccd25381c8617
        火山引擎: e7451bd2-bb62-4a53-a4a7-c0fb1ceb931f
        DeepSeek: sk-1bea5ef7075948d1926a66fd5c0d526d
        MinIO AccessKey/SecretKey: 明文
        PostgreSQL: postgres:postgres 明文
  影响: 数据库、对象存储、AI 模型服务、短信服务均可能被攻破。
  建议: ① 立即轮换所有已暴露密钥 ② 生产环境仅通过环境变量注入，不保留 .env 文件
        ③ 删除 .env.bak

【严重程度: 高】CORS 配置 origin: true（允许所有来源）
  问题: /backend/src/plugins/cors.ts 配置了 origin: true，任何域名可跨域访问 API。
  影响: 所有 API 端点面临 CSRF 攻击风险，OAuth 回调、上传接口均可被利用。
  建议: origin 改为白名单域名列表，生产环境禁止设为 true。

【严重程度: 高】OAuth 回调页面字符串拼接 JWT token（XSS 风险）
  问题: wechat-oauth.ts / qq-oauth.ts 用 "try { document.cookie = 'auth_token=" + token + "'; }" 
        的方式直接将 token 拼入 HTML <script> 块，若 token 含特殊字符可导致 XSS 注入。
  影响: 微信/QQ OAuth 回调页面。攻击者可篡改回调参数窃取用户 token。
  建议: 使用 JSON.stringify(token) 和 Set-Cookie header 代替字符串拼接。

【严重程度: 高】OAuth 新用户 randomUUID 作为密码 —— 账户可被接管
  问题: wechat-oauth.ts / qq-oauth.ts 中 OAuth 新用户密码设为 randomUUID().slice(0,16)，
        且以明文存入 passwordHash（未 bcrypt）。用户无邮箱/手机绑定，无法找回密码。
  影响: 所有微信/QQ 首次登录注册的用户。
  建议: ① OAuth 用户标记为 OAuth-only ② 提供绑定手机号流程 ③ passwordHash 设为 null

【严重程度: 中】JWT Refresh Token 回退同密钥
  问题: auth.ts refresh 端点中 refreshSecret = JWT_REFRESH_SECRET || JWT_SECRET
  影响: 若未设置 JWT_REFRESH_SECRET，refresh token 与 access token 同密钥。
  建议: 强制要求 JWT_REFRESH_SECRET 必须设置且与 JWT_SECRET 不同。

【严重程度: 中】Login 限速仅内存 Map，重启后清零
  问题: auth.ts 登录限速使用 Map<string, {count; blockedUntil}> 存储于内存。
  影响: 后端重启后限速记录清零，攻击者可立即发起爆破。
  建议: 使用 Redis 或数据库记录限速信息。

【严重程度: 中】管理员 API 独立 JWT，缺乏 token 注销能力
  问题: admin-auth.ts 使用独立 verifyToken()，无 tokenVersion 检查。
  影响: 管理员 JWT 泄露后无法主动使其失效。
  建议: 统一使用 fastify.authenticate + tokenVersion 机制。

【严重程度: 中】/api/auth/user-by-email 公开接口无需认证
  问题: 该端点通过邮箱查询用户，返回 memberTier/phone/agentStatus 等敏感字段。
  影响: 攻击者可枚举邮箱获取用户 VIP 等级、代理状态。
  建议: 添加 IP 限速，限制返回字段。

【严重程度: 低】SMS 验证码日限溢出时返回明文字段 debugCode
  问题: sms-auth.ts 中短信日限达到后降级返回完整的 6 位验证码给前端。
  影响: 调试信息泄漏。
  建议: 生产环境移除 debugCode 返回。

【严重程度: 低】OAuth state 参数未校验（CSRF 防护缺失）
  问题: OAuth 回调未校验 state 是否与发出的一致。
  影响: 攻击者可构造回调 URL 诱导用户绑定攻击者账号。
  建议: state 与 session 关联存储并校验。

【严重程度: 低】密码重置接口无登录验证，且无限速
  问题: POST /api/auth/sms/reset-password 只需手机号+验证码，无限速措施。
  建议: 添加 IP 限速，同一手机号每日重置次数限制。

已确认的安全措施（正面）:
  ✅ Prisma Prepared Statement 防御 SQL 注入
  ✅ 密码使用 bcrypt.hash(password, 10) 合理 salt rounds
  ✅ 单设备登录 tokenVersion 检查
  ✅ SMS 验证码 60 秒内禁止重复发送，每日上限 5 条
  ✅ 手机号脱敏显示 maskPhone()
  ✅ 登录 IP 限速 5 次失败封禁 15 分钟
  ✅ 注册验证码尝试限速每分钟最多 5 次

3.3 高并发问题
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【严重程度: 高】数据库连接池严重不足 + 多 PrismaClient 实例
  问题: connection_limit=5，但存在 8 处 new PrismaClient() 独立实例。
        PM2 6 个实例 × 8 PrismaClient = 48 个连接需求，远超 5 配额。
        pool_timeout=30 秒后请求全部出错。
  影响: 用户 >5 并发请求时，数据库连接耗尽，API 全部不可用。
  建议: ① connection_limit 提升至 20~50 ② 废弃分散的 new PrismaClient()，使用单例
        ③ Worker concurrency 降低到 3~5

【严重程度: 高】Worker Runtime 缺少分布式锁，任务可重复执行
  问题: queue-manager.ts enqueueTask() taskId 非必传，worker-runtime.ts persistImageResult
        用 create 而非 upsert，任务被重复执行时产生重复数据。
  影响: 重试时角色/场景/分镜图片表产生重复记录，前端渲染多条相同图片。
  建议: persistImageResult 改用 upsert，enqueueTask 强制要求 taskId。

【严重程度: 中】大文件上传和 base64 传输内存泄漏风险
  问题: multipart 限制 50MB 全读内存，downloadImageLocal 使用 Buffer.concat(chunks)，
        data:image 传输大图 base64 导致内存成倍膨胀。
  影响: 低内存服务器(如 2GB RAM)在高峰时 OOM kill。

【严重程度: 中】PM2 集群下共享文件系统写冲突
  问题: worker-runtime.ts 写入 public/uploads/ 目录，多进程竞争同一路径。
        ffmpeg concat 使用 /tmp/ 临时文件，多进程有文件名冲突风险。

【严重程度: 中】Web Worker concurrency=10 打满数据库连接
  问题: queue-manager.ts concurrency=10，配合 connection_limit=5 必然溢出。

【严重程度: 低】Redis 连接缺少密码认证

3.4 工作流优化
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【严重程度: 高】生成流水线串行依赖过重
  问题: aigc-orchestrator.ts 严格 2 阶段串行（Phase 0→Phase 1→Phase 2）。
        声音设计只依赖角色名，道具设计只依赖角色/场景基本概念，不依赖完整定妆。
  影响: 完整流程 8 个 agent 串行需 30s+。
  建议: 改为 DAG 调度 (Phase 0→Phase 1 并行角色+场景→Phase 2 并行定妆+声音+镜头)

【严重程度: 中】图片→视频→音频可进一步并行化
  问题: TTS 只依赖剧本和角色音色，与图片/视频完全无关，可在角色定妆后立即并行启动。
        视频各段落也可以 Promise.all 并发生成。
  建议: TTS 在角色定妆完成后立即触发，视频段落级并发生成。

【严重程度: 中】帧序列引擎(FFE)并发调用可能打爆 API 配额
  问题: frame-sequence-engine.ts 中 Promise.all(concurrentTasks) 全部并发，同时调用
        50+ 次 image 请求，触发第三方 API 限流(429)。
  建议: 增加 semaphore 控制最大并发数 3~5。

4. 前端安全审计
================================================================================

【严重程度: 高】localStorage + Cookie 双重存储 auth_token
  问题: Cookie 未设 HttpOnly，多处直接 localStorage.getItem('auth_token')。
        token-cache.ts 虽设计了内存闭包，但大量代码绕过该缓存。
  影响: XSS 注入时可窃取 auth_token，盗用用户身份。
  建议: ① Cookie 增加 HttpOnly; Secure ② 所有 token 读取收敛到 token-cache.ts
        ③ 移除前端 document.cookie = 'auth_token=...'

【严重程度: 高】v-html 渲染社区帖子，手写 sanitizer 存在绕过风险
  问题: pages/community/post/[id].vue:63 使用 v-html="renderContent(post.content)"，
        sanitizeHtml 是手写正则，可被换行/大小写/SVG animate 绕过。
  建议: 使用 DOMPurify 替代手写正则，后端存储前做净化。

【严重程度: 高】管理后台仅前端校验 token，后端认证可能不足
  问题: middleware/auth.ts 跳过 admin 路由，admin layout 未在 onMounted 校验 token。
        admin API 失败时 fallback 到 mock 数据而非跳转登录页。
  建议: admin 路由不跳过，增加专用守卫 + onMounted token 有效性检查。

【严重程度: 高】管理后台敏感配置明文显示（云密钥、支付证书）
  问题: sms.vue / wechat.vue / qq.vue / payment.vue / models.vue / cos.vue 等
        admin 页面直接显示 SecretId、API Key、支付密钥等，且可在前端修改。
  影响: 管理员账号泄露 = 全部云密钥/支付凭证被盗。
  建议: ① 密钥前端用 **** 遮盖 ② 独立更新接口不返回完整密钥 ③ 审计日志

【严重程度: 高】完全缺失安全 HTTP 头部
  问题: nuxt.config.ts 未配置 Content-Security-Policy, X-Content-Type-Options,
        X-Frame-Options, HSTS 等安全头部。
  影响: 无法防御 XSS、点击劫持、协议降级等攻击。
  建议: 在 nitro routeRules 中添加安全头部。
  示例:
    Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline';
    X-Content-Type-Options: nosniff
    X-Frame-Options: DENY
    Strict-Transport-Security: max-age=31536000; includeSubDomains

【严重程度: 中】app.vue 的 require polyfill 暴露 token 获取方式
【严重程度: 中】fetch 请求 Authorization header 可能泄露
【严重程度: 中】轮询固定间隔(2s)无指数退避
【严重程度: 中】大文件 base64 导致浏览器 OOM 风险
【严重程度: 中】admin 消息发送接口公开搜索用户
【严重程度: 中】编译期 patch 替换 require 过于激进
【严重程度: 低】VideoGenerationWorkspace.vue 超 3600 行，大量重复代码

5. 数据库与 Schema 审计
================================================================================

【严重程度: 高】AiSpec 系列表缺少 projectId 外键索引
  涉及表: AiEffectSpec, AiActionSpec, AiCameraSpec, AiEmotionSpec, 
         AiFrameDesign, AiPropSpec, AiVoiceConfig, TTsRecord
  影响: 按 projectId 查询时全表扫描，数据 >1 万行时延迟从 ms 级退化到秒级。
  建议: 每个表添加 @@index([projectId])。

【严重程度: 高】UserModelConfigV2 加密存储但未解密使用
  问题: saveUnified.ts 用 AES-256-GCM 加密 API Key 存入，但 voice.ts:250 直接取
        密文作为 apiKey 调用第三方 API，api-keys.ts 也返回密文给前端。
  影响: 所有 TTS/Image/Video AI API 调用传密文 → 401/403 认证失败。
  建议: voice.ts 中调用 decryptKey() 解密后再使用，api-keys.ts 解密后 maskKey()。

【严重程度: 高】ApiKey 表存在明文存储漏洞
  问题: admin-api-keys.ts POST/PUT 直接将用户输入的 keyValue 明文存储。
        而同一项目存在另一路由 admin-models-v2.ts 使用 AES-256-CBC 加密存储。
  影响: 数据库泄露 = 全部第三方 AI 服务 API Key 泄露（直接经济损失）。
  建议: 删除 admin-api-keys.ts 明文实现，统一使用加密路径。

【严重程度: 高】execution-images.ts N+1 循环 + 大事务未拆分
  问题: 循环逐个 DB 写入 + 1000 条 upsert 包在单个 $transaction 中。
       嵌套事务增加连接持有时间，在 connection_limit=5 下饿死其他请求。
