# S1.2C-SM-001 — Workflow Semantics Layer

## 🎯 目标

补充 GEO Workspace 的 **Workflow Semantics Layer**，让状态机从「技术状态机」升级为「语义状态机」。
解决 Entry Closure 和 Exit Closure 两个核心语义缺口。

**不是 UI Sprint，不是 API Sprint，不是重构 Sprint。**
是**纯状态语义 Sprint**。

## 核心洞察

当前状态：
- empty state 在 UI 层存在（GeoEmptyState）
- 但 state-machines.ts 不知道 `empty = ENTRY_START`
- 同样，verification done 后没有 WORKFLOW_COMPLETED 语义

## 改动范围（精确 3 文件）

### 文件 1: `types/state.ts` — 新增语义状态类型

- 新增 `WORKFLOW_SEMANTIC_STATES` 常量
- 新增 `WorkflowSemanticState` type
- 新增 `WorkflowSemanticStateMachine` 接口
- 新增 `SprintScope` 接口（描述当前 Sprint 的入口/出口语义）

### 文件 2: `lib/state-machines.ts` — 新增语义转移矩阵

- 新增 `SEMANTIC_TRANSITIONS` 矩阵（不允许非法语义跳转）
- 新增 `transitionSemantic()` 函数
- 新增 `getSemanticTransitionMatrix()` 工具函数

### 文件 3: `composables/useWorkspaceState.ts` — 整合语义层

- 新增 `createWorkflowSemanticMachine()` 工厂函数
- 在 `WorkspaceState` 上新增 `semantic` 属性
- `isIdle` 计算考虑语义状态

## 语义状态定义

```typescript
ENTRY_START          // 用户在 entry 阶段（无 mission，empty state）
FIRST_MISSION_CREATED  // 用户创建了第一个 mission
WORKFLOW_ACTIVE      // 正在工作流中（有 active mission）
WORKFLOW_COMPLETED   // 已完成 verification，工作流结束
WORKFLOW_EXIT        // 用户选择离开或新起（exit to dashboard / start new mission）
```

## 转移矩阵

```
ENTRY_START ──→ FIRST_MISSION_CREATED ──→ WORKFLOW_ACTIVE ──→ WORKFLOW_COMPLETED ──→ WORKFLOW_EXIT
                              │                                      │
                              └──────────────────────────────────────┘ (可跳过 active 直达 completed)
```

## Mapping to existing states

| Semantic State | Mapped from PageState | 触发条件 |
|---------------|----------------------|---------|
| ENTRY_START | PageState: `empty` | mission === null |
| FIRST_MISSION_CREATED | — | mission created event |
| WORKFLOW_ACTIVE | PageState: `ready` | mission has tasks |
| WORKFLOW_COMPLETED | — | verification passed |
| WORKFLOW_EXIT | — | user action (back/start new) |
