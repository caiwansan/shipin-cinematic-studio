# Sprint S1.2B — Event Producers

**Objective**: Establish a unified event architecture with clean naming, Producer Registry, and Payload Contract.

**Rationale from RC1-AUDIT-002**: Event Architecture scored 5/10 — types exist but zero compliant producers, lowercase naming, duplicate definitions. Cross-page flow (0%) requires real events to work. This sprint is the foundation for S1.2C workflows.

## Scope

Three deliverables, no exceptions:

### D1. Event Contract Cleanup (`lib/events.ts`)

- Remove duplicate `TASK:STARTED`, `TASK:UPDATED`, `TASK:FINISHED` entries
- Remove orphan types: `TASK:PROGRESS_UPDATED`, `TASK:COMPLETED`, `TASK:FAILED` (merge into canonical events)
- Standardize payload shape: `{ projectId, entityId, timestamp, source, payload }`
- Add missing events for the `Discovery → Recommendation → Mission → Verification` flow:
  - `DISCOVERY:COMPLETED` — Discovery report generated
  - `RECOMMENDATION:GENERATED` — Recommendations ready
  - `MISSION:CREATED` — Mission created from recommendation
  - `MISSION:COMPLETED` — Mission completion triggers Verification
  - `VERIFICATION:READY` — Verification page becomes actionable
- Remove `MISSION:TIMELINE_APPEND` (merged into `MISSION:APPEND`)

**DoD**: 
- No duplicate event names
- Every event has a `DOMAIN:VERB` format name
- Every event payload extends `{ projectId: string, entityId: string, timestamp: string, source: string }`
- TypeScript compiles with zero errors

### D2. Producer Registry (`lib/event-producers.ts`)

A single-file registry that documents:
- Each event name
- Producer source (which service/file emits it)
- Consumer source (which listener handles it)
- Payload shape link

This is a **documentation-first** artifact. Producers will be implemented in D3, then the registry is the SSOT.

**DoD**:
- Table covers all events in events.ts
- At least one producer marked for each event
- No dead events (events without a producer)

### D3. Fix MissionCenterShell Producer

Current state: `mission:load`, `mission:loaded`, `mission:error` (lowercase, wrong convention)

Fix:
- `mission:load` → `MISSION:LOADING` with proper payload
- `mission:loaded` → `MISSION:LOADED` with proper payload
- `mission:error` → `MISSION:ERROR` with proper payload
- All payloads follow the new Payload Contract

Bonus: These events are the first real producers. TimelineRepository already listens for `MISSION:APPEND` — wire it so that `MISSION:LOADED` also triggers a timeline entry.

**DoD**:
- MissionCenterShell emits correctly named events
- TimelineRepository consumes new events
- Build zero warnings
- Contract Linter passes (no new uncovered calls)
