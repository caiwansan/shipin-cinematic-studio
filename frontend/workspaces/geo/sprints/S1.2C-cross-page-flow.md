## Phase 1: Workflow Wiring

### 1.1 确认当前现状

检查各 Repository 当前是否已经实现以下方法：

| Repository | 当前状态 |
|------------|----------|
| DiscoveryRepository | 已存在？emit 事件？ |
| RecommendationRepository | 已存在？监听 DISCOVERY:COMPLETED？ |
| MissionRepository | 已存在？监听 RECOMMENDATION:GENERATED？ |
| VerificationRepository | 已存在？监听 MISSION:COMPLETED？ |
| TimelineRepository | 已存在？监听所有事件？ |
| EventBus | 已安装且可用？ |
| Producer Registry | 已注册所有 Repository？ |

**如果某个 Repository/EventBus 完全不存在，则本 Phase 负责创建。**

### 1.2 实现 Workflow Wiring

目标链路：

```
Create Project
  ↓ PROJECT:CREATED
Discovery → DISCOVERY:COMPLETED
  ↓ DiscoveryRepository emits → EventBus
Recommendation auto-refreshes → RECOMMENDATION:GENERATED
  ↓ RecommendationRepository emits → EventBus
Mission Center shows ready → user creates mission → MISSION:CREATED
  ↓ MissionRepository emits → EventBus
Mission completed → MISSION:COMPLETED
  ↓ MissionRepository emits → EventBus
Verification auto-enables → VERIFICATION:READY
```

**实现规则**：
- Repository 是唯一数据入口
- EventBus 是唯一跨页面同步方式
- Store 只负责 UI State，不负责数据获取
- 不允许页面之间直接调用对方 API
- 不允许组件直接修改其它 Domain 的状态
- 每个事件有且仅有一个 Producer（参照 REPOSITORY_OWNERSHIP.md）

## Phase 2: Timeline Integration

Mission Center 不再只是 Mission 的 Timeline。
它需要记录整个 Workspace 的工作流事件。

**Timeline 必须自动追加以下事件（按顺序）：**

```
PROJECT:CREATED
DISCOVERY:COMPLETED
RECOMMENDATION:GENERATED
MISSION:CREATED
MISSION:COMPLETED
VERIFICATION:READY
```

**规则**：
- TimelineRepository 只读，不写
- TimelineRepository 监听 EventBus，自动追加
- Timeline 按 chronological 顺序排列

**不要求**：
- 不要求 Timeline 有复杂的筛选/搜索 UI
- 不要求 Timeline 支持分页
- 不要求 Timeline 有分类标签

当前 Timeline 在 Mission Center Shell 中是一个 Tab（Activity Hub）。如果它现在只显示 Mission 事件，扩展为显示所有事件。

## Phase 3: Golden User Journey（主要验收 Gate）

Sprint 完成后：

**不要先看 Git Diff。不要先跑 Linter。不要先写 Release Note。**

直接执行 Golden User Journey：

| # | 步骤 | 操作 | 预期 |
|---|------|------|------|
| 1 | 创建项目 | 填写表单，点击创建 | Project Card 出现 |
| 2 | 运行 Discovery | 打开 DiscoveryLab，开始扫描 | Discovery Report 渲染 |
| 3 | 查看 Recommendation | 导航到 Recommendations 页面 | 列表自动更新 |
| 4 | 创建 Mission | 点击 "Create Mission" | Mission Center 更新 |
| 5 | 完成 Mission | 标记为完成 | 状态变为 Completed |
| 6 | 打开 Verification | 导航到 Verification 页面 | 页面已就绪 |
| 7 | 检查 Timeline | 打开 Activity Hub | 6 个事件按顺序可见 |
| 8 | 确认无刷新 | 观察浏览器行为 | 全程无页面刷新 |

**验收条件（全部通过才算 Green）**：

- [ ] 全程无需刷新页面
- [ ] Timeline 自动追加全部 6 个事件
- [ ] 事件顺序正确（chronological）
- [ ] Repository 数据一致（不重复、不缺失）
- [ ] 无重复事件（EventBus 不会 double-fire）
- [ ] 无 Console Error
- [ ] 无新增 404（API/Chunk/Page）
- [ ] Build Zero Warning

**任一条件失败 → Sprint 判定失败，进入返工。**

## Phase 3b: Business Gate — 用户知道下一步

在每个步骤完成后，检查用户是否能自然知道下一步做什么。

| 阶段 | 用户看到什么 | 下一步是否明确 |
|------|------------|:------------:|
| Project 创建 | 创建成功提示 | ✅ 有明显的"开始 Discovery"引导 |
| Discovery 完成 | AI 已完成分析 | ✅ 有入口去查看 Recommendations |
| Recommendation 生成 | 推荐已生成 | ✅ 有"创建 Mission"按钮 |
| Mission 完成 | Mission 已完成 | ✅ 有入口去 Verification |
| Verification Ready | 已可验证 | ✅ 有"开始验证"按钮 |

**如果用户在任意步骤需要猜测下一步，Sprint 不通过。**

这是一个 **产品级验收**——不是代码对不对，而是用户会不会用。

## Phase 3c: Recovery Gate — 失败恢复

至少覆盖一个容灾场景：

```
Discovery
  ↓ (模拟) API 返回错误或网络超时
  ↓ 页面进入 Error State（有错误提示 UI）
  ↓ 用户点击 Retry / 重试
  ↓ Discovery 成功
  ↓ 继续 Journey → Recommendation → Mission → Verification
```

**验收条件**：

- [ ] Error State 有明确 UI（不是白屏/无限 loading/console 报错）
- [ ] Retry 后正常恢复
- [ ] Timeline 不产生重复事件
- [ ] Repository 状态保持一致（没有残留的错误数据）
- [ ] 页面无需刷新即可恢复
- [ ] 恢复后能走完剩余 Journey

**这是验证整个 Workflow 不只是 Happy Path 可用，而是真正健壮。**
