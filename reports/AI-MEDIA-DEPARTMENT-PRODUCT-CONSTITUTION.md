## 一、产品定位重构

### 1.1 旧定位（废弃）

**Enterprise Digital Department（企业数字部门）**

> 问题：本质是「企业管理软件 + 数据展示中心」，用户购买后不产生即时价值。用户看到的是空 Dashboard、0 AI 员工、0 渠道。不是价值产品，是监控工具。

### 1.2 新定位（冻结）

**昆仑镜 AI 新媒体运营部门（AI Media Operation Department）**

> 一个由 Hermes Agent Runtime 驱动，由企业用户管理的 **AI 新媒体运营团队**。

核心价值主张：

| 维度 | 旧 | 新 |
|------|-----|-----|
| 用户感知 | "企业管理后台" | "AI 运营团队办公室" |
| 核心动作 | 查看数据 | 指挥 AI 执行运营任务 |
| 价值产生 | 延迟（先配置再等待） | 即时（连接账号→AI 分析→立即出方案） |
| 产品定位 | SaaS 管控工具 | AI Workforce 运营平台 |
| 用户目标 | "管理 AI 员工" | "让 AI 帮我做新媒体运营" |

## 二、核心用户路径

### 2.1 新用户激活路径（30 分钟闭环）

```
用户注册/登录昆仑镜
  ↓
进入「AI 新媒体运营部门」
  ↓
创建企业（或加入已有企业）
  ↓
购买企业套餐（基础/专业/旗舰）
  ↓
连接新媒体账号（抖音/小红书/视频号...）
  ↓
创建 AI 员工（热点分析师 + 内容创作）
  ↓
AI 分析账号 → 生成 7 天运营计划
  ↓
AI 创作内容 → AI 审核 → AI 发布
  ↓
AI 回复用户评论
  ↓
数据反馈 → 持续优化
```

### 2.2 日常运营路径

```
登录 → 进入运营部门
  ↓
查看「今日运营状态」（发布/互动/粉丝）
  ↓
热点分析师输出今日热点
  ↓
内容创作 AI 根据热点生成内容
  ↓
运营总监 AI 审核内容
  ↓
通过 → 发布到授权平台
  ↓
销售顾问 AI 私信/评论回复
  ↓
数据分析师 AI 输出日报
  ↓
调整策略 → 循环
```

## 四、AI 员工岗位设计

### 4.1 第一批 AI 员工（7 个岗位）

| 岗位 | 职责 | 输出物 | 权限等级 |
|------|------|--------|---------|
| **新媒体运营总监 AI** | 制定账号策略、审核内容、管理平台规则 | 运营策略、审核决策、规则报告 | 最高 |
| **热点分析师 AI** | 实时分析各平台热点 | 行业热点、同城热点、竞品热点、内容机会 | 高 |
| **内容创作 AI** | 根据品牌+热点生成内容 | 短视频脚本、图文、公众号文章、音频 | 高 |
| **内容审核 AI** | 发布前质量审核 | 评分报告（平台规则/内容质量/传播潜力/品牌匹配） | 高 |
| **销售顾问 AI** | 私信、评论、企微、社群转化 | 回复话术、跟进策略、客户标签 | 中 |
| **客服 AI** | 售后、FAQ、投诉、用户维护 | 解决方案、FAQ 库、投诉处理记录 | 中 |
| **数据分析 AI** | 同步数据、输出报告 | 日报、周计划、月战略、半年战略 | 高 |

### 4.2 内容审核评分标准

| 维度 | 权重 | 评分项 |
|------|------|--------|
| 平台规则 | 30分 | 违禁词、敏感内容、时长限制、标签规范 |
| 内容质量 | 30分 | 原创性、信息密度、文字质量、视觉呈现 |
| 传播潜力 | 20分 | 情绪价值、话题度、互动钩子、分享动机 |
| 品牌匹配 | 20分 | 品牌调性、产品关联、目标受众契合 |

**发布阈值**：≥ 85 分通过，< 85 分返回修改

## 六、技术架构

### 6.1 组织架构

```
Organization（企业）
  ↓
AI Department（新媒体运营部门）
  ↓
Hermes Agent Pool（共享 Agent 运行时）
  ↓
Sub Agent（每个 AI 员工一个 Sub Agent）
```

### 6.2 每个 AI 员工能力模型

| 能力 | 说明 |
|------|------|
| Agent Identity | 岗位名称、头像、角色描述、权限等级 |
| Agent Memory | 长期记忆（品牌信息、用户偏好、历史决策） |
| Agent Knowledge | 行业知识库、话术库、平台规则库 |
| Agent Permission | 操作权限（发布/回复/分析/审核/管理） |
| LLM Config | 模型选择（DeepSeek/OpenAI/Claude/其他）+ BYOK API Key |

### 6.3 LLM 配置

- 用户自行配置 API Key（BYOK）
- 支持：DeepSeek / OpenAI / Claude / 其他 OpenAI 兼容模型
- API Key 绑定到 Hermes Sub Agent
- 通过 ModelRouter 统一调度
