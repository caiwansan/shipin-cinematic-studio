# P1.7 — True State Clarification

> 附属于 `P1.7-FREEZE-POLICY.md`，解释「受约束运行」与「完全冻结」的区别。

## ❌ 误解版本：冻结系统

```
系统 = 完全不可变
  - schema 不可改
  - code 不可改
  - API 不可动
```

这种状态会导致系统失去实验能力、修复能力和演化能力。

## ✅ 实际版本：受约束运行系统

```
系统 = 可变，但被 guard + 纪律约束
  - v3-schema-guard.ts → 防误改（semantic drift detector）
  - metrics → 只读记录（无 auto-insight）
  - prompt / schema / pipeline → 技术上可改，但穿过 guard + 进入 metrics
```

## 两者的本质差别

```
冻结 = 行为约束 + 变更成本提高
```

P1.7 建立的不是 `immutable system kernel`，而是 **Semantic Stability Layer**：

```
V3 Schema
  ↓
Guard (v3-schema-guard.ts)    ← 检测漂移，不阻止所有变化
  ↓
Runtime Pipeline              ← 技术上可变
  ↓
Metrics Observability         ← 所有变化的结果都进入记录
```

## 这个阶段应该叫

**P1.7 — Constrained Observability Phase**

特征：
- ✅ 行为冻结（纪律）
- ✅ 结构可演化（受控）
- ✅ 所有变化必须穿过 guard
- ✅ 所有结果必须进入 metrics

## 当前真正的系统状态

V3 Semantic IR System：
- Observability Layer — 已建立 ✅
- Guard Layer — 部分建立（v3-schema-guard.ts） ✅
- Metrics Layer — 已稳定运行 ✅
