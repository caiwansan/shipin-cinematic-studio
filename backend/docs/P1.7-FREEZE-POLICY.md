# P1.7 — Constrained Observability Phase

> 生效时间：2026-06-24 13:00（后更正）
> 系统状态：V3 Semantic IR System → Soft Frozen (Constrained Observability)
>
> ⚠️ 本系统不是「完全不可变」的冻结系统，而是「受约束运行」的语义系统。
> 所有变化必须穿过 guard 检测，所有结果必须进入 metrics 记录。
> 区别详见 `docs/P1.7-TRUE-STATE.md`

## 行为约束（不可违反的纪律）

1. **Schema 受 guard 保护** — v3-schema-guard.ts 检测到字段漂移时拒绝启动
2. **Prompt 不改** — 总导演/Frame Designer/Render Spec Builder 技术可改，但不得主动修改
3. **消费链不改** — buildVideoPromptSpec / compilePrompt 保持当前版本
4. **优化暂停** — 不调温度、不调阈值、不加 fallback
5. **禁止基于指标做结构性改动** — 即使字段填充率 < 50%，也不反推 Schema 或 Prompt

## 允许的操作

6. **数据采集与指标分析** — `narrative_v3_metrics` 表的写入与查询
7. **每日健康报告** — 自动生成 Fill Rate / Quality Rate / Semantic Yield（纯输出，无自动解释）
8. **V2 对照组保留** — 旧数据作为 baseline，不做删除或转换

## 禁止的行为

9. **禁止解释型优化** — "数据好看 → 系统变好" 是逻辑陷阱
10. **禁止合并解释指标** — Fill / Quality / Yield 三者必须独立分析，不可加权合并
11. **禁止虚构稳定性** — 系统状态报告必须区分"理想约束"和"实际约束"

## 核心工具

- `v3-schema-guard.ts` — 不是冻结工具，是 **Semantic Drift Detector**
- `narrative_v3_metrics` 表 — 只读观测，不参与决策回路
- `GET /api/v3-metrics/health` — 每日健康报告（无自动 insight 层）

## 下一触发点

积累 100 个 V3 格式的真实剧本后，执行 **P1.8 Perceptual Ground Truth Audit**：
- V3 vs V2 视频感知差异
- 指标系统 vs 人眼感知的一致性验证
- 测试 Semantic Yield 是否能预测人眼评分
- 决定是否从 Constrained Observability Phase 升级为 Verifiable Perceptual Semantic System
