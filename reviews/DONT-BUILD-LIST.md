# FCV-1 Don't Build List（反需求清单）

> **版本**: v1.0 | **用途**: 防止产品方向被少数用户的偏好带偏

---

## 核心规则

### 一条建议进入 Roadmap 的条件

> **至少 3 位不同角色用户，独立提出同一问题，且问题级别为 S0/S1。**

不满足这个条件的需求 → 不纳入 Roadmap，无论听起来多好。

---

## 典型 Don't Build 场景

以下场景即使有用户提出，也不应直接开发：

| 用户说 | 可能的正确回应 |
|---|---|
| "能不能导出 PDF" | 记录行为：用户在哪里想导出？是不是信息呈现方式有问题？ |
| "如果有深色模式就好了" | 记录行为：用户使用环境是否影响了阅读？不是 Dark Mode 问题 |
| "能不能加一个统计报表" | 记录行为：用户在哪里觉得数据不够？是 Dashboard 信息架构问题 |
| "这个颜色我不喜欢" | Severity: S3 → Backlog，不阻塞 |
| "能不能集成 X 工具" | 暂不开发。记录用户工作流中的上下文缺口 |

---

## Check List（每次记录一条需求时回答）

- [ ] 至少 3 位不同角色提出？
- [ ] 问题级别是 S0 或 S1？
- [ ] 修复该问题能提升"无帮助完成率"？
- [ ] 这是用户行为暴露的问题还是用户口头建议？

**如果以上全部为"是" → 进入 Sprint  
如果任意一项为"否" → 不进入 Roadmap**

---

## 最终原则

> **用户行为比用户意见更可信。  
> 三条独立用户行为比一条热门建议更有价值。**
