## 架构总览

### Event Processing Pipeline

```
WeCom Callback
     ↓
 wecom-callback.controller.ts
     ↓
 callback-event.service.ts
     ↓
 ┌──────────────────────────────────────┐
 │ Stage 1: Received (log)              │
 │ Stage 2: Normalize (WeComAdapter)    │
 │ Stage 3: Dedup Check (ProcessedEvent)│
 │ Stage 4: Process (InteractionSync)   │
 │   ↓ Success → Log + Return           │
 │   ↓ Error → Retry (up to 3x)         │
 │   ↓ Exhaust → DLQ                    │
 └──────────────────────────────────────┘
     ↓
 Interaction + Trace + Health
```

### Event Lifecycle States

```
RECEIVED → NORMALIZED → DEDUP_CHECK → PROCESSED (ok)
                                  ↘ DUPLICATE (skip)
             ↓ (error) → RETRY (1..3) → PROCESSED (ok)
                                             ↘ DEAD_LETTERED
```

### DB Tables

| Table | 用途 | Unique Key |
|-------|------|------------|
| `processed_event` | 去重标记 | (event_id, channel_account_id) |
| `dead_letter_event` | 死信队列 | id |
| `event_trace_log` | 可观测性 | (trace_id + stage) |
