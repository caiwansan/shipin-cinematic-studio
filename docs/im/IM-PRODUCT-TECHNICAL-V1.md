## 1. 背景与目标

昆仑镜首页新增**聊天系统**：公共聊天频道 + 群聊 + 私聊，支持图片/短视频/文件，机器人隐形管理员治理内容，内置敏感词即时替换；配套虚拟资产体系（金币/红包/礼物/提现，照搬抖音模式）；首期含 1v1 语音/视频连线，群通话/多人会议二期。

技术底座：**WuKongIM**（开源 Go 即时通讯引擎，Apache 2.0，9 年沉淀，频道模型 + 系统UID + webhook + datasource + 流式消息）。

## 3. 现状审计

### 3.1 WuKongIM（底座）能力盘点

**原生支持（直接用）：**
- 频道模型：个人/群/客服/社区/临时频道，创建/删除/订阅者/黑名单/白名单 API 齐全
- 系统UID（systemUIDs）：系统账号可加入任意频道、给任何人发消息 —— **机器人隐形管理员的天生底座**
- 自定义消息类型 + 流式消息（类 ChatGPT 输出流）
- 指令消息（CMD）：**音视频信令天然通道**（呼叫/接听/挂断/ICE 交换）
- 消息持久化（pebble KV）、多端同步、在线状态、最近会话服务端维护
- 二进制协议：TCP/WS/WSS/TLS1.3；心跳 1 字节
- webhook（消息事件推送 HTTP/gRPC）+ datasource（订阅者/黑名单/白名单/系统UID/频道信息 5 接口对接业务系统）
- 去中心化集群（raft + gossip），节点互备、自动容灾

**缺失/需自建：**
- ❌ 无内置敏感词引擎 → 昆仑镜自建（DFA/Aho-Corasick）
- ❌ 无媒体存储/上传 → 昆仑镜临时中转 + TTL 清理
- ❌ 无用户体系（uid 是业务侧字符串）→ 昆仑镜签发 token、映射用户
- ❌ 连接鉴权半开放（源码 processAuth 被注释，tokenAuthOn 默认关）→ 接入时必须补
- ❌ 无群管理角色/申请流 → 昆仑镜后端业务
- ❌ 无音视频媒体引擎（只做信令）→ WebRTC + STUN/TURN

### 3.2 昆仑镜已有底子（复用，不重复造）

- ✅ 用户/多租户体系：User → Membership → Organization（JWT org 强制校验，租户隔离纪律成熟）
- ✅ 支付：`PaymentOrder`（支付宝 provider、二维码、coins 字段、后台确认）+ PaymentConfig/PaymentSecret
- ✅ 账本：`CoinLog`（金币流水）
- ✅ 收益账户雏形：`CreatorWallet`（totalEarned/balance）
- ✅ AI 员工体系（Hermes Agent + KAOR 生命周期/权限）→ 直接承载机器人管理员
- ✅ 审计体系（auditLog + 双通道）
- ✅ 前端：Nuxt3 + 青花瓷设计体系

## 4. 合规边界（红线，不可逾越）

1. **充值金币不可提现**（防二清/资金池）：用户间流转（红包/礼物）必须用消费币，消费币永不可兑换余额
2. **禁止用户间金币换法币**（私下交易平台不支持、不提供入口）
3. **文本合规留存**：聊天记录留存 ≥ 6 个月（《网络安全法》第 21 条 + 网信办即时通信规定）—— R4 已天然满足
4. **个税代扣代缴**：平台为扣缴义务人，收益提现按劳务报酬预扣率（800 以下免征；20%-40% 累进）
5. **内容治理义务**：敏感词即时替换 + 机器人巡查 + 举报通道（《网络信息内容生态治理规定》）
6. **后续补充**：实名 + 未成年消费限额（直播打赏监管精神），进入正式版前必须

## 5. 总体架构

```
┌─────────────────────────────────────────────────────┐
│ 前端 Nuxt3（首页新增 /chat 聊天页，青花瓷风格）          │
│  WuKongIM JS SDK（长连接/消息） + WebRTC（音视频）      │
└──────────────┬──────────────────────────┬────────────┘
               │ WS/WSS                    │ HTTPS
┌──────────────▼──────────────────────────▼────────────┐
│ WuKongIM (Go, 单机首期→集群二期)  昆仑镜 api-server     │
│  频道/订阅者/消息/系统UID          token签发/群管理/      │
│  webhook→审核/事件                敏感词/红包/礼物/提现   │
└──────────────┬──────────────────────────┬────────────┘
               │                           │
      ┌────────▼───────┐          ┌────────▼────────┐
      │ 临时媒体中转    │          │ PostgreSQL      │
      │ (TTL 自动清理)  │          │ 文本/账本/业务表 │
      └────────────────┘          └─────────────────┘
  coturn (STUN/TURN) — WebRTC 打洞/中继（只转发不存储）
```

**核心链路：**
- 登录 → 昆仑镜签发 wukong token（uid = 昆仑镜 userId，短时效）→ JS SDK 连接 WuKongIM
- 发消息 → 发送链路敏感词即时替换 → 广播（即时，无审核队列）
- 媒体 → 临时中转（校验/哈希）→ 消息带 URL+哈希+TTL → TTL 清理任务自动删除；**发布者本地留源**
- 机器人 → 系统UID 自动入群 → webhook 事件异步复核（防绕过客户端的漏网之鱼）→ 撤回/禁言/踢出 + 审核日志

## 6. 模块设计

### M1 IM 底座（WuKongIM 部署与接入）— ★
- 部署：docker compose 单机（端口规划：TCP 5100 / WS 5200 / HTTP API 5001 / 监控 5300），nginx 反代
- token 签发：`POST /api/im/token`（昆仑镜 JWT 鉴权 → 生成 wukong token）
- **补连接鉴权**：启用 tokenAuthOn + 自研校验中间件（开源版 processAuth 注释，需补）
- uid 映射：昆仑镜 userId（UUID）直用；组织 → 群频道；公共频道 = 固定频道ID（如 `channel_public`）
- 二期：集群扩容（多节点 + 节点互备）

### M2 聊天前端 — ★★★
- 首页新增 `/chat`：会话列表 + 消息窗 + 输入区（文本/图片/短视频/文件/红包/礼物/音视频呼叫）
- 频道类型：公共频道（全员）、群聊（R10）、私聊（1v1）
- 自定义消息类型：`text / image / video / file / red_packet / gift / call / system`
- 组件：消息气泡、图片/视频预览、文件下载（TTL 提示）、红包卡片、礼物特效、未读红点、在线状态
- 移动端适配（响应式，Web 优先）

### M3 机器人管理员（内容治理）— ★★
- 机器人 = 昆仑镜 AI 员工（Hermes Agent）挂系统UID，名「昆仑镜小管家」
- 敏感词库：`ChatSensitiveWord` 表 + 管理界面（增删改查/导入/启用禁用）
- 即时替换：发送链路 DFA 匹配 → `*` 替代（毫秒级，无感知）——客户端+服务端双保险
- 异步复核：webhook 事件 → 机器人扫描（文本/图片审核 API）→ 违规撤回/禁言/踢出 + 通知
- 隐形管理员：新群创建 → 自动加入（不发言、只监听），R9 由系统UID 机制原生保证
- 群管理权限：群主/管理员/成员三级 + 申请流（`ChatGroupApply`）+ 机器人兜底仲裁

### M4 媒体生命周期（R3/R5）— ★★
- 上传 → 临时中转（类型/大小/内容校验 + 哈希）→ 消息携带 `{url, hash, ttl}` 
- TTL：视频 72h / 文档 7d / **图片 168h（7 天）** → 定时任务扫描 `MediaObject` 表 → 删除文件 + 标记过期
- 寻址：消息里只存哈希+寻址信息，平台不做持久副本；发布者本地留源（二期可加 WebRTC 直传加速）
- 合规：文本与审核日志留存在 PG；媒体过期即焚

### M5 金币与收益（抖音模式，R13-R15）— ★★★
**双账户分离（合规必需）：**

| 账户 | 来源 | 用途 | 可提现 |
|---|---|---|---|
| **钻石（统一命名，掌柜拍板）** | 充值（PaymentOrder）/平台赠送 | 发红包、送礼物 | ❌ 充值钻石永不可 |
| **收益余额**（收益钻石） | 礼物分成 65%、创作激励 | 兑换余额 → 提现 | ✅ 代扣个税 |

- **命名定稿：虚拟币统一叫「钻石」**（内部账本区分来源：充值钻石 / 收益钻石）

- 「金币可以兑换余额」落地：**收益钻石**（赚得/获赠）→ 一键兑换人民币余额（**1 钻石 = 0.1 元，掌柜拍板**）；**充值钻石不可兑换**（红线）
- 充值：复用 PaymentOrder + 支付宝（已有）
- 账本：钻石流水 + 收益流水双账本（CoinLog 扩展 type 或新建 CoinLedger）
- ⏳ 命名待掌柜定：统一「金币」内部分消费/收益，或「钻石 + 金币」两套名

### M6 红包（R12）— ★★- 群红包：拼手气/普通，钻石支付
- 表：`RedPacket`（总金额/个数/剩余/状态）+ `RedPacketGrab`（抢记录）
- 并发：事务 + 行锁，防超抢；未领完 24h 自动退回
- IM 联动：红包卡片自定义消息 → 点开调 API 抢 → 结果通知（「XX 抢到 X 钻石」）
- 流水：全部进账本，可对账

### M7 礼物（R13）— ★★
- `GiftCatalog`：礼物目录（钻石定价，🌹💍🚀…）+ `GiftTransfer`：转赠记录
- 送礼：扣钻石 → 收礼人收益余额入账（**收礼人 65% / 平台 35%，掌柜 2026-08-06 拍板**）
- 礼物墙：个人主页展示收到的礼物（后续）

### M8 提现与个税（R14）— ★★★
- 流程：申请 → 后台审核 → 个税代扣（劳务报酬预扣率）→ 打款 → 电子凭证
- 表：`WithdrawalRequest` + `TaxWithholding`（代缴记录）
- 打款通道 ⏳：支付宝企业付款（需商户付款资质）/ 银行卡代付；无资质则人工审核 + 对公转账过渡
- 门槛：**20 元起，掌柜 2026-08-06 拍板**；T+1 审核
- 打款通道：支付宝企业付款（掌柜确认商户为企业账户，**可申请开通付款**）；**开通前人工对公转账过渡**
- 风控：频次/金额/设备指纹/黑名单

### M9 语音/视频 1v1（R11）— ★★★
- 信令：WuKongIM 指令消息（call/accept/reject/hangup/ICE）——原生通道
- 媒体：WebRTC P2P 直连（**内容不过平台**，与 R3 理念一致）
- 基建：coturn（STUN 打洞 + TURN 中继兜底，只转发不存储），半天部署
- UI：来电弹窗/接听/挂断/静音/摄像头切换
- 限制：NAT 穿透失败走 TURN（企业网/校园网），体验略降但可用

### M10 二期（不在首期）
- 群通话/多人会议（SFU：mediasoup/Janus）
- WuKongIM 集群化扩容
- WebRTC 直传媒体加速（纯 P2P 增强）
- 实名 + 未成年消费限额
