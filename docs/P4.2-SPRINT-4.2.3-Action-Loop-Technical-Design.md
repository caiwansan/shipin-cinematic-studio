**Sprint**: 4.2.3 Action Loop
**核心目标**: 让 CEO 的 Decision 能安全地变成一个可负责、可审批、可追踪的 Action
**日期**: 2026-07-16
**Status**: ⏸ PENDING CTO REVIEW
**前置条件**: Sprint 4.2.2 ✅ COMPLETE — Decision Engine 已冻结

---

## 一、设计原则

> **Sprint 4.2.3 的核心目标只有一句：让 CEO 的 Decision 能安全地变成一个可负责、可审批、可追踪的 Action。**

### 边界冻结 — 4.2.3 做什么，不做什么

| ✅ 做 | ❌ 不做 |
|-------|---------|
| Decision → Action 转换 | ❌ AI 自动执行 |
| Action 分配 Owner | ❌ Agent 自主决定执行 |
| Human Approval Gate | ❌ 自动修改企业数据 |
| Action 状态追踪 | ❌ 执行能力本身 |
| 验证完成证明 | ❌ 扩展 Agent Runtime |

### Contract 1: Action Entity Contract

**关系模型：**

```
Decision (1) ──────── (N) Action
```

```typescript
/**
 * Action — 执行项
 * 
 * 一个 Decision 可以产生多个 Action
 * 例如：
 *   Decision: "高价值客户流失风险"
 *   Actions:
 *     - Action 1: "销售联系客户"        Owner: Sales Team
 *     - Action 2: "发送优惠方案"        Owner: AI Agent
 *     - Action 3: "经理复盘原因"        Owner: Sales Manager
 */
interface Action {
  id: string;                    // PK, UUID
  tenantId: string;              // 租户隔离
  decisionId: string;            // FK → EnterpriseRecommendation.id
  
  title: string;                 // 执行标题
  description?: string;          // 详细说明
  
  status: ActionStatus;          // 生命周期状态
  priority: ActionPriority;      // 优先级 (P1/P2/P3/P4)
  
  ownerType: OwnerType;          // OWNER 类型
  ownerId: string;               // OWNER ID (user_id / team_id / agent_id)
  
  // Approval Gate
  approvedBy?: string;           // 审批人 ID
  approvedAt?: DateTime;         // 审批时间
  approvalNote?: string;         // 审批备注
  
  // Execution Tracking
  startedAt?: DateTime;          // 开始执行时间
  completedAt?: DateTime;         // 完成时间
  executionResult?: string;      // 执行结果描述
  
  // Verification
  verifiedAt?: DateTime;         // 验证时间
  verificationResult?: string;   // 验证结果
  
  // Metadata
  dueDate?: DateTime;            // 截止日期
  createdAt: DateTime;
  updatedAt: DateTime;
}
```

### Contract 2: Action Lifecycle Contract

**冻结状态机：**

```
PENDING ──[approval]──→ APPROVED ──[start]──→ EXECUTING ──[complete]──→ COMPLETED ──[verify]──→ VERIFIED

PENDING ──[reject]──→ REJECTED
```

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│  PENDING ──→ APPROVED ──→ EXECUTING ──→ COMPLETED ──→ VERIFIED   │
│     │                                                          │
│     └──→ REJECTED                                              │
│                                                                  │
│  禁止跳状态: PENDING → COMPLETED ❌                              │
│  禁止跳状态: PENDING → VERIFIED ❌                               │
│  禁止跳状态: APPROVED → VERIFIED ❌                              │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

```typescript
enum ActionStatus {
  PENDING   = 'pending',     // 待审批
  APPROVED  = 'approved',    // 已批准（可开始执行）
  EXECUTING = 'executing',   // 执行中
  COMPLETED = 'completed',   // 已完成（待验证）
  VERIFIED  = 'verified',    // 已验证（闭环）
  REJECTED  = 'rejected',    // 已拒绝
}
```

**状态流转规则：**

| From | To | 触发条件 | 操作者 |
|------|-----|---------|--------|
| PENDING | APPROVED | Human Approval | Approver |
| PENDING | REJECTED | Human Rejection | Approver |
| APPROVED | EXECUTING | 开始执行 | Owner / System |
| EXECUTING | COMPLETED | 提交完成 | Owner |
| COMPLETED | VERIFIED | 验证通过 | Approver / CEO |

### Contract 4: Approval Contract

**冻结：**

```typescript
interface ApprovalRecord {
  approvedBy: string;          // 审批人 User ID（必填）
  approvedAt: DateTime;        // 审批时间（必填）
  approvalNote?: string;       // 审批备注（可选）
}
```

**审批流程：**

```
Decision Accepted (decision_status = 'accepted')
        │
        ↓
Action Created (status = 'pending')
        │
        ↓
Human Reviews (CEO / Manager)
        │
        ├──→ Approved → status = 'approved'
        │
        └──→ Rejected → status = 'rejected'
        │
        ↓
Action Approved → Owner 开始执行
```

**审批规则：**
1. `POST /actions/:id/approve` 必须传递 `approvedBy` + `approvedAt`（服务端填充）
2. `approvalNote` 可选（审批意见）
3. 审批后 Action 才可进入 `EXECUTING` 状态
4. 拒绝需要 `rejectReason`（必填）

### Contract 5: Execution Boundary Contract

**Sprint 4.2.3 冻结：**

| 边界 | 说明 |
|------|------|
| ❌ NO Auto-Execute | Action 创建后不自动执行 |
| ❌ NO Agent Trigger | 不触发 Agent Runtime |
| ❌ NO Data Mutation | 不自动修改企业数据 |
| ✅ Create Only | 只创建 Action + 分配 Owner |
| ✅ Assign Only | 只设置 Owner + DueDate |
| ✅ Track Only | 只追踪状态 + 验证结果 |

**执行能力留给后续 Sprint：**
- Sprint 4.2.x: Agent 执行接口（外部触发）
- Sprint 4.2.x: 自动化规则引擎（Policy Engine）

## 十一、Acceptance Criteria

### AC 4.2.3.1: Decision → Action 转换
- ✅ CEO Accept Decision 后，系统自动创建至少1个 Action
- ✅ 一个 Decision 可产生多个 Action
- ✅ Action 默认状态为 PENDING

### AC 4.2.3.2: Action Lifecycle
- ✅ 状态机严格遵循 PENDING → APPROVED → EXECUTING → COMPLETED → VERIFIED
- ✅ 禁止跳状态
- ✅ 拒绝流 PENDING → REJECTED 正常

### AC 4.2.3.3: Ownership
- ✅ Action 必须有 ownerType + ownerId
- ✅ 支持 HUMAN / TEAM / AI_AGENT 三种类型

### AC 4.2.3.4: Approval Gate
- ✅ Approve/Reject 必须记录 approvedBy + approvedAt
- ✅ Approval 后状态才流转

### AC 4.2.3.5: Execution Boundary
- ✅ 不触发 Agent Runtime
- ✅ 不自动执行任何操作
- ✅ 不修改企业数据

### AC 4.2.3.6: Runtime Impact
- ✅ channel.adapter.ts 0 修改
- ✅ agent-scheduler.runtime.ts 0 修改
- ✅ 无新增数据库模型（除 enterprise_action）

### AC 4.2.3.7: Frontend
- ✅ 不新建页面
- ✅ TodayDecisionCard 集成 Action Panel
- ✅ 状态色彩编码正确
