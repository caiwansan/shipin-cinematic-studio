## 1. 昆仑镜用户系统是否已经统一？

### 当前状态：⚠️ 分裂存在两套体系

| 体系 | 表 | 用途 | 状态 |
|------|-----|------|------|
| **User 体系** | `User` / `Membership` / `MemberPlan` | 旧版视频创作平台 | ✅ 运行中 |
| **Governance 体系** | `Tenant` / `GovOrganization` / `GovUser` / `Role` / `SubscriptionPlan` | 新版工作台 | ✅ Schema 已建 |

### 关键发现

**🔴 严重问题：Enterprise Intelligence 使用的是 User.id 作为 TenantId**

```typescript
// frontend/stores/auth.ts Line 17
tenantId: (state) => state.user?.id || '',  // ❌ 用 userId 当 tenantId
```

这意味着：
- 每个用户是一个独立的 "tenant"
- 没有真正的多租户隔离
- `EnterpriseRecommendation.tenantId` 存的实际上是 `userId`
- 与 Governance 体系的 `Tenant` 表不连通

### Governance 体系关系图

```
Tenant (governance_tenant)
  ├── GovOrganization (governance_organization) — 组织架构
  │   └── GovUser (governance_user) — 组织成员
  ├── Role (governance_role) — 角色+权限
  ├── SubscriptionPlan — 套餐
  ├── Quota / UsageRecord / BillingRecord — 计费
  └── AuditLog
```

但 **Enterprise 模块完全不引用 Governance**：

```
EnterpriseRecommendation.tenantId = User.id  ← 不引用 Governance.Tenant
EnterpriseAction.tenantId = User.id          ← 不引用 Governance.Tenant
```

### 结论

| 能力 | 状态 |
|------|------|
| 用户身份认证 | ✅ User + JWT |
| 租户隔离 | ⚠️ User.id 充当 tenantId（伪隔离） |
| 组织架构 | ✅ Governance 有 Schema，❌ Enterprise 未接入 |
| 角色权限 | ✅ Governance 有 Schema，❌ Enterprise 未接入 |
| 套餐订阅 | ✅ Membership + MemberPlan（旧）/ SubscriptionPlan（新）|
| AI 使用额度 | ✅ Quota + UsageRecord |

**🔴 结论：Enterprise Intelligence 没有接入 Governance 体系**

## 3. Enterprise Data Truth Source

### 当前状态：⚠️ 部分有来源，部分靠 AI 生成

| 数据 | SSOT | 来源类型 | 验证 |
|------|------|---------|------|
| **OperationEvent** | `enterprise_operation_event` 表 | ✅ Runtime 写入 | 真实 |
| **Signal** | `enterprise_signal` 表 | ✅ 从 Event 生成 | 真实 |
| **Recommendation** | `enterprise_recommendation` 表 | ⚠️ 部分 AI 生成 | 混合 |
| **Lead Intelligence** | `enterprise_lead_intelligence` 表 | 📊 算法推断 | 估算 |
| **ROI Snapshot** | `enterprise_roi_snapshot` 表 | 📊 算法推算 | 估算 |
| **Content Publish** | `enterprise_content_publish` 表 | ⏸ 无渠道 | 空 |
| **Interaction** | `enterprise_interaction` 表 | ⏸ 无渠道 | 空 |

### 数据源分析

**✅ 真实 Runtime 数据**：
- `EnterpriseOperationEvent` — 由 OperationEventService 从 AgentSchedule/AuditTrail/Onboarding 写入
- `EnterpriseSignal` — 由 SignalService 从 Event 模式检测生成

**⚠️ 算法推断数据**：
- `EnterpriseLeadIntelligence.purchaseProb` — 由 LeadIntelligenceService 用行业模板推算
- `EnterpriseRoiSnapshot.estimatedRevenue` — 由 RevenueIntelligenceService 用预测模型推算
- `EnterpriseRecommendation.priorityScore` — 由 DecisionRankingService 用多因子算

**❌ 无来源数据**：
- `EnterpriseChannelAccount` — 无真实账号绑定
- `EnterpriseContentPublish` — 无发布能力
- `EnterpriseInteraction` — 无渠道数据回捞

### 结论

| Truth Layer | 状态 |
|-------------|------|
| Event → Signal | ✅ 真（Runtime 写入）|
| Signal → Recommendation | ⚠️ 混合（+ AI 排序）|
| Recommendation → Decision | ⚠️ 需要人工判断 |
| Decision → Action | ✅ 真（CEO 决策）|
| Action → Outcome | ❌ 无渠道数据 |
| Outcome → Impact | ❌ 无收入/转化系统 |
| Impact → Learning | ❌ 无反馈闭环 |

**🟡 结论：Outcome Layer 目前没有真实数据来源**

## 4. Action 完成后是否有 Outcome 数据回流？

### 当前状态：❌ 没有

```
Action Lifecycle（已完成）：
  PENDING → APPROVED → EXECUTING → COMPLETED → VERIFIED
                                                    ↓
                                              ❌ 到此为止
```

**`EnterpriseAction` 表字段**：
- `executionResult` — 人工填写的文本结果
- `verificationResult` — 人工填写的验证结果

**缺失**：
- 没有结构化 Outcome（success/failed/partial）
- 没有 Impact 关联（revenue_change / conversion_change）
- 没有自动数据回流（依赖人工填写）

### 销售 Action 示例（CTO 问题）

```
期望链路：
  销售 Action "联系客户"
    → CRM Follow-up Record
    → Deal Status Change
    → Revenue Attribution

实际链路：
  销售 Action "联系客户"
    → executionResult = "已经打了电话"  （人工填写）
    → verificationResult = "已确认"     （人工填写）
    → 结束（没有结构化数据）
```

### 缺失的业务执行系统

| 系统 | 存在？ | 说明 |
|------|--------|------|
| CRM | ❌ | 没有客户管理、Deal 跟踪 |
| ERP | ❌ | 没有订单/收入确认 |
| Order System | ❌ | 只有 RechargeOrder（充值订单）|
| Payment | ⚠️ | 仅有 Agent/Membership 充值 |
| Campaign | ❌ | 没有营销活动管理 |
| Analytics | ❌ | 没有产品行为分析 |

### 结论

**🔴 结论：Outcome Layer 只能人工填写，没有自动数据回流**

### Governance 与 Enterprise 断裂

```
Governance Tenant (governance_tenant)
  ├── GovOrganization   ←─┐
  ├── GovUser            │ 完全独立
  ├── Role               │ 不交叉引用
  └── SubscriptionPlan  ←─┘
  
Enterprise/User (User.id 当 tenantId)
  ├── EnterpriseOperationEvent
  ├── EnterpriseSignal
  ├── EnterpriseRecommendation
  └── EnterpriseAction
  
两套体系互不引用 🔴
```

### 孤立架构清单

| 组件 | 孤立原因 | 影响 |
|------|---------|------|
| `Governance.Tenant` | 没有被 Enterprise 模块引用 | 多租户体系不生效 |
| `Governance.Role` | Enterprise 无权限判断 | 审批 Gate 只用 approvedBy 文本字段 |
| `Governance.Quota` | Enterprise 无额度限制 | 理论上可以无限创建 Action |
| `Governance.AuditLog` | Enterprise Action 有独立 `status_history` | 审计体系分裂 |
| `EnterpriseChannelAccount` | 无适配器实现 | 渠道是空壳 |
| `EnterpriseContentPublish` | 无发布能力 | 无法产生内容数据 |
| `EnterpriseInteraction` | 无渠道数据源 | 线索全由算法生成 |
| `EnterpriseRoiSnapshot` | 收入为推算值 | 不是财务真实数据 |
| `Membership`（旧）| 与 Governance 不连通 | 用户套餐双轨制 |
| `MemberPlan`（旧）| 与 Governance 不连通 | 同上 |
