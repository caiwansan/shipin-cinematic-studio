# Sprint 4.2.5.1 — Channel Governance Alignment — Technical Design

**Status:** CTO Review Required  
**Created:** 2026-07-15  
**CTO Direction:** Channel 必须接回 Enterprise Identity，不允许身份断裂

---

## 一、Goal

Sprint 4.2.5 已完成 Channel Reality Foundation Backend，但暴露了关键的身份断层：

> Channel Account 属于谁？谁可以绑定？谁可以查看 Interaction？谁可以确认 Outcome？

**目标：**

```
Before (Sprint 4.2.5):
  Channel Account → tenantId (软关联)
  Interaction → tenantId (软关联)
  Outcome → Action → User

After (Sprint 4.2.5.1):
  Governance Tenant → Enterprise Context → Channel Account → Interaction → Outcome
         ↑                  ↑                  ↑                ↑
     Organization      GovUser            External        Verified
     Role/Permission   Owner Binding      Customer        Interaction
```

**核心原则：** 数据属于 Tenant，不属于 User。所有查询必须走 `tenantId`，禁止走 `userId`。

## 三、5 Frozen Contracts（开发前冻结）

### Contract 6: Channel Ownership Contract

> Channel Account 必须绑定到具体的 Enterprise Context，不能孤儿存在。

```typescript
// 扩展 EnterpriseChannelAccount
interface ChannelAccountOwnership {
  id: string
  tenantId: string
  governanceTenantId: string        // ← 明确治理租户
  
  // 归属链
  organizationId: string             // ← 属于哪个组织
  createdByGovUserId: string         // ← 哪个 GovUser 创建的
  ownerType: 'gov_user' | 'system'   // ← 所有者类型
  ownerId: string                    // ← GovUser.id（不是 User.id）
  
  // 权限链
  manageRole: 'owner' | 'admin' | 'viewer'  // ← 默认角色
}
```

**规则：**
- 创建 Channel Account 的 GovUser 自动获得 `owner` 角色
- `owner` 可以授权 `admin` 或 `viewer` 给其他 GovUser
- 只有 `owner` 可以解绑（disconnect）Channel Account
- 删除 GovUser 时，其拥有的 Channel Account 自动转给 `system` 或组织的 `owner`

### Contract 7: Channel Permission Contract

> 不是所有企业成员都可以操作 Channel。必须基于 Capability 控制。

```typescript
// 新增 Capability（追加到现有 capability 体系）
enum ChannelCapability {
  'channel.read'         = 'channel.read',          // 查看渠道列表
  'channel.connect'      = 'channel.connect',       // 绑定新渠道
  'channel.disconnect'   = 'channel.disconnect',    // 解绑渠道
  'channel.sync'         = 'channel.sync',          // 手动触发同步
  'interaction.read'     = 'interaction.read',      // 查看互动记录
  'interaction.verify'   = 'interaction.verify',    // 确认互动有效
  'interaction.export'   = 'interaction.export',    // 导出互动数据
  'outcome.verify'       = 'outcome.verify',        // 确认 Outcome
  'outcome.reject'       = 'outcome.reject',        // 拒绝 Outcome
}

// 权限检查流程
async function authorizeChannelAction(
  govUserId: string,
  tenantId: string,
  action: ChannelCapability
): Promise<boolean> {
  // 1. 解析 EnterpriseContext
  const context = await enterpriseContextService.resolve({ govUserId, tenantId })
  
  // 2. 检查 Role → Capability
  const hasCapability = context.role.capabilities.includes(action)
  
  // 3. 检查 Organization 范围
  const inSameOrg = context.organizationId === targetAccount.organizationId
  
  return hasCapability && inSameOrg
}
```

**默认角色权限分配：**

| Role | channel.read | channel.connect | channel.disconnect | interaction.read | interaction.verify | outcome.verify |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| owner | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| admin | ✅ | ✅ | ❌ | ✅ | ✅ | ✅ |
| member | ✅ | ❌ | ❌ | ✅ | ❌ | ❌ |
| viewer | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |

### Contract 8: Interaction Tenant Isolation Contract

> Interaction 属于 Tenant，不属于 User。所有查询必须走 tenantId。

```typescript
// Interaction 查询接口
interface InteractionQuery {
  tenantId: string              // ✅ 必须
  governanceTenantId: string    // ✅ 必须
  channelAccountId?: string     // 可选筛选
  externalCustomerId?: string   // 可选筛选
  interactionType?: string      // 可选筛选
  startDate?: Date
  endDate?: Date
  page: number
  pageSize: number
}

// ❌ 禁止：where userId
// ✅ 正确：where tenantId + governanceTenantId

// ❌ 禁止：返回其他 Tenant 的 Interaction
// ✅ 正确：双重验证 tenantId === context.tenantId
```

**关键规则：**
- `where` 条件必须包含 `tenantId`
- 返回结果中的 `externalCustomerId` 必须在当前 Tenant 的 `customerMapping` 中有对应
- 跨 Tenant 查询直接拒绝（即使物理上在同一数据库）

### Contract 9: Channel Audit Contract

> 所有 Channel 相关操作必须留痕，不可抵赖。

```typescript
// 审计事件类型
enum ChannelAuditAction {
  CHANNEL_CREATE = 'channel.create',
  CHANNEL_CONNECT = 'channel.connect',
  CHANNEL_DISCONNECT = 'channel.disconnect',
  CHANNEL_DELETE = 'channel.delete',
  CHANNEL_CREDENTIAL_UPDATE = 'channel.credential_update',
  INTERACTION_SYNC = 'interaction.sync',
  INTERACTION_VERIFY = 'interaction.verify',
  OUTCOME_VERIFY = 'outcome.verify',
  OUTCOME_REJECT = 'outcome.reject',
  PERMISSION_GRANT = 'permission.grant',
  PERMISSION_REVOKE = 'permission.revoke',
}

// 审计记录写入 enterprise_audit_log（复用 4.2.3.1 的审计体系）
// 双写：audit_log + governance_audit_log
```

**不可跳过的审计点：**
- 绑定时：记录 corpId、agentId（不记录 secret）、谁绑定的
- 解绑时：记录原因、谁操作的
- 同步时：记录同步数量、时间、触发者
- 确认 Outcome 时：记录判断依据、置信度

### Contract 10: External Account Binding Contract

> 外部平台账号必须映射到 Enterprise Context，禁止裸暴露。

```typescript
// 外部客户映射表
interface ChannelCustomerMapping {
  id: string
  tenantId: string
  governanceTenantId: string
  organizationId: string
  
  // 外部标识
  channelType: string
  channelAccountId: string
  externalCustomerId: string      // 外部平台的用户ID
  
  // 内部映射
  internalCustomerId?: string      // 昆仑镜内部的客户ID（如果有）
  internalGovUserId?: string        // 负责的销售/客服 GovUser
  
  // 元数据
  externalName?: string             // 外部显示名
  externalAvatar?: string           // 外部头像（可缓存）
  
  firstInteractionAt: Date
  lastInteractionAt: Date
  interactionCount: number
}
```

**规则：**
- `externalCustomerId` 只在 Tenant 内部跨渠道关联
- 只能通过 `tenantId + externalCustomerId` 查询
- 没有 mapping 的外部客户不能参与 Outcome 流程

## 五、Service 层变更

### 5.1 Channel Account Service 扩展

```typescript
// 新增方法
class ChannelAccountService {
  // 现有方法保持不变，追加权限检查层
  
  // 创建渠道账户（追加 Ownership）
  async createWithOwnership(
    input: CreateChannelAccountInput,
    context: EnterpriseContext  // ← 必须传入 Enterprise Context
  ): Promise<ChannelAccount> {
    // 1. 权限检查
    await this.authorize(context, 'channel.connect')
    
    // 2. 创建（自动绑定 Ownership）
    const account = await this.create({
      ...input,
      organizationId: context.organizationId,
      createdByGovUserId: context.govUserId,
      ownerType: 'gov_user',
      ownerId: context.govUserId,
      manageRole: 'owner'
    })
    
    // 3. 审计
    await this.audit.record({
      action: ChannelAuditAction.CHANNEL_CREATE,
      context,
      targetId: account.id,
      metadata: { channelType: account.channelType }
    })
    
    return account
  }
  
  // 获取当前用户在 Channel 中的角色
  async getUserRole(
    channelAccountId: string,
    govUserId: string
  ): Promise<'owner' | 'admin' | 'viewer' | null> {
    const account = await this.findById(channelAccountId)
    if (!account) return null
    
    if (account.ownerId === govUserId) return 'owner'
    
    // 查询权限表（如果有单独的表）
    // 或者从 governance 体系继承
    
    return null // 默认无权限
  }
}
```

### 5.2 Interaction Service 租户隔离

```typescript
class InteractionSyncService {
  // 所有方法强制 tenantId + governanceTenantId
  
  async queryInteractions(
    query: InteractionQuery,
    context: EnterpriseContext
  ): Promise<InteractionList> {
    // 强制租户隔离
    if (query.tenantId !== context.tenantId) {
      throw new ForbiddenError('Cross-tenant query denied')
    }
    
    // tenantId + governanceTenantId 双重过滤
    const where = {
      tenantId: context.tenantId,
      governanceTenantId: context.governanceTenantId,
      ...query.filters
    }
    
    return this.prisma.enterpriseInteraction.findMany({ where })
  }
}
```

## 六、API 层变更

### 6.1 所有 Channel API 追加前置检查

```typescript
// 在 channelRoutes 的 preHandler 中加入
app.addHook('preHandler', async (request, reply) => {
  // 1. 认证（已有）
  await app.authenticate(request, reply)
  
  // 2. 解析 EnterpriseContext
  const context = await enterpriseContextService.resolve({
    userId: request.user.id,
    tenantId: request.params.tenantId
  })
  
  // 3. 附加到 request
  request.enterpriseContext = context
  
  // 4. 检查全局 channel access
  if (!context.role.capabilities.includes('channel.read')) {
    return reply.code(403).send({
      error: 'forbidden',
      message: '缺少 channel 访问权限'
    })
  }
})
```
