# Sprint 4.2.5 — Channel Reality Foundation — Technical Design

**Status:** Awaiting CTO Freeze  
**Created:** 2026-07-16  
**CTO Direction:** 从「AI 能做什么」→「AI 是否连接真实企业运营结果」

---

## 一、Goal

Enterprise Intelligence Loop 已完整，但 Outcome 主要来自人工填写。

目标：

> 让昆仑镜连接企业真实运营数据，让 Outcome 来自真实世界交互。

**核心转变：**

```
Before:  Action → 人工填写 Outcome
After:   Action → External Channel → Real Interaction → Verified Outcome
```

**CTO 明确：** 不做一个「渠道管理中心」空壳。选一个业务闭环，做深做透。

---

## 二、第一渠道选择

### 🥇 企业微信（WeChat Work）— 推荐 ★★★★★

**原因：**

| 维度 | 企业微信 | 微信公众号 | 抖音/小红书 |
|------|---------|-----------|------------|
| B2B 匹配 | ★★★★★ | ★★★ | ★★ |
| 用户身份稳定 | ★★★★★ | ★★★★ | ★★ |
| 销售闭环 | ★★★★★ | ★★★ | ★ |
| 数据可获取 | ★★★★ | ★★★★ | ★★ |
| 接入复杂度 | ★★★ | ★★★ | ★★★★ |

**企业微信天然连接：** 客户 → 互动 → 销售动作 → 转化 → Outcome

**CTO 裁决：** 企业微信是第一选择。

## 三、5 Frozen Contracts（开发前冻结）

### Contract 1: Channel Account Contract

```typescript
interface ChannelAccount {
  id: string
  tenantId: string
  governanceTenantId: string
  
  channelType: 'wechat_work' | 'wechat_official' | 'other'
  channelName: string
  
  // 凭证（加密存储）
  credentials: {
    corpId?: string
    agentId?: string
    secret?: string        // 加密
    accessToken?: string   // 加密
    tokenExpiresAt?: Date
  }
  
  // 连接状态
  connectionStatus: 'connected' | 'disconnected' | 'expired' | 'error'
  lastConnectedAt?: Date
  lastError?: string
  
  // 归属
  ownerId: string       // GovUser.id
  ownerType: 'gov_user' | 'system'
  
  // 元元数据
  metadata: Record<string, unknown>
  
  createdAt: Date
  updatedAt: Date
}
```

**关键字段：**
- `credentials.secret` — AES-256 加密，不存明文
- `connectionStatus` — 真实反映连接状态，不假装在线
- `ownerId` — 关联 GovUser，不是 User

### Contract 2: Channel Adapter Contract

```typescript
interface ChannelAdapter {
  channelType: string
  
  // 连接管理
  connect(credentials: ChannelCredentials): Promise<ConnectionResult>
  disconnect(): Promise<void>
  testConnection(): Promise<boolean>
  
  // 消息
  sendMessage(req: SendMessageRequest): Promise<SendResult>
  onMessage(callback: (event: ChannelEvent) => void): void
  
  // 客户
  getCustomer(externalId: string): Promise<CustomerInfo>

}

interface ChannelEvent {
  eventType: 'message' | 'contact_change' | 'menu_click' | 'other'
  externalCustomerId: string
  externalCustomerName?: string
  content?: string
  channelType: string
  channelAccountId: string
  rawPayload: Record<string, unknown>
  occurredAt: Date
}
```

**CTO 冻结：**
- 只实现 企业微信 一个 Adapter
- Adapter 必须真实连接，禁止 Mock
- 连接失败必须报告具体错误

### Contract 3: Interaction Event Contract

```typescript
interface EnterpriseInteraction {
  id: string
  tenantId: string
  governanceTenantId: string
  
  // 来源
  channelType: 'wechat_work' | 'wechat_official' | 'other'
  channelAccountId: string
  
  // 外部客户
  externalCustomerId: string
  externalCustomerName?: string
  
  // 交互内容
  interactionType: 'message_in' | 'message_out' | 'contact_add' | 'menu_click' | 'other'
  direction: 'inbound' | 'outbound'
  content?: string
  contentType: 'text' | 'image' | 'link' | 'event' | 'other'
  
  // 关联
  actionId?: string      // 关联 Action（如果有）
  outcomeId?: string     // 关联 Outcome（如果有）
  
  // 原始数据
  rawPayload: Record<string, unknown>
  
  // 时间
  occurredAt: Date
  createdAt: Date
}
```

**CTO 冻结：**
- Interaction 是新的 Event Source
- 必须包含 `direction`（inbound/outbound）
- `actionId` 可空（不是每次交互都关联 Action）

### Contract 4: External Data Trust Contract

```typescript
interface ExternalDataTrust {
  // 数据来源标识
  source: 'wechat_work' | 'wechat_official' | 'manual' | 'system'
  
  // 信任级别
  trustLevel: 'verified' | 'system_reported' | 'human_declared' | 'inferred'
  
  // 验证状态
  verificationStatus: 'pending' | 'confirmed' | 'rejected' | 'expired'
  
  // 原始引用
  externalId?: string           // 外部系统 ID
  externalUrl?: string          // 可验证链接
  externalTimestamp?: Date      // 外部系统时间
  
  // 采集方式
  collectionMethod: 'api_webhook' | 'api_poll' | 'manual_entry' | 'system_inferred'
}
```

**CTO 冻结：**
- 所有外部数据必须标记 `trustLevel`
- `human_declared` 和 `inferred` 不能混为 `verified`
- 未来 Revenue 数据必须有 `externalUrl` 可验证

### Contract 5: Channel → Outcome Mapping Contract

```typescript
interface ChannelOutcomeMapping {
  // 什么渠道事件 → 什么 Outcome
  channelEventType: string       // e.g., 'wechat_work.message_in'
  interactionType: string        // e.g., 'message_in'
  
  // 推断规则
  outcomeType: string            // e.g., 'ENGAGEMENT'
  outcomeStatus: string          // e.g., 'PENDING_VERIFY'
  confidence: number             // 0-100，自动推断的置信度
  
  // 人工确认要求
  requiresHumanVerification: boolean
  autoVerifyIf: {
    // 自动确认条件（例如：回复内容包含关键词）
    containsKeywords?: string[]
    minResponseTime?: number    // 秒
  }
}
```

**CTO 冻结：**
- Channel → Outcome 映射不是 1:1
- 默认 `requiresHumanVerification = true`
- 自动确认规则必须显式配置，不能隐式推断

## 四、Technical Design

### 4.1 Database Changes

```sql
-- ═══════════════════════════════════════════════════════════
-- enterprise_channel_account — 渠道账户（真实凭证）
-- ═══════════════════════════════════════════════════════════

CREATE TABLE enterprise_channel_account (
  id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id               UUID NOT NULL,
  governance_tenant_id    UUID,
  
  channel_type            TEXT NOT NULL DEFAULT 'wechat_work',
  channel_name            TEXT NOT NULL,
  
  -- 凭证（加密 JSONB）
  credentials             JSONB NOT NULL DEFAULT '{}'::jsonb,
  connection_status       TEXT NOT NULL DEFAULT 'disconnected',
  last_connected_at       TIMESTAMPTZ,
  last_error              TEXT,
  
  -- 归属
  owner_id                TEXT NOT NULL,
  owner_type              TEXT NOT NULL DEFAULT 'gov_user',
  
  -- 元数据
  metadata                JSONB NOT NULL DEFAULT '{}'::jsonb,
  
  created_at              TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at              TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  
  CONSTRAINT unique_channel_per_tenant UNIQUE (tenant_id, channel_type)
);

CREATE INDEX idx_channel_account_tenant ON enterprise_channel_account(tenant_id);
CREATE INDEX idx_channel_account_gov ON enterprise_channel_account(governance_tenant_id);
CREATE INDEX idx_channel_account_status ON enterprise_channel_account(connection_status);

-- ═══════════════════════════════════════════════════════════
-- enterprise_interaction — 渠道交互事件（新 Event Source）
-- ═══════════════════════════════════════════════════════════

CREATE TABLE enterprise_interaction (
  id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id               UUID NOT NULL,
  governance_tenant_id    UUID,
  
  -- 来源
  channel_type            TEXT NOT NULL,
  channel_account_id      UUID NOT NULL,
  
  -- 外部客户
  external_customer_id    TEXT NOT NULL,
  external_customer_name  TEXT,
  
  -- 交互内容
  interaction_type        TEXT NOT NULL,
  direction               TEXT NOT NULL,  -- inbound / outbound
  content                 TEXT,
  content_type            TEXT NOT NULL DEFAULT 'text',
  
  -- 关联
  action_id               UUID,
  outcome_id              UUID,
  
  -- 信任
  trust_level             TEXT NOT NULL DEFAULT 'system_reported',
  verification_status     TEXT NOT NULL DEFAULT 'pending',
  collection_method       TEXT NOT NULL DEFAULT 'api_webhook',
  
  -- 原始数据
  raw_payload             JSONB NOT NULL DEFAULT '{}'::jsonb,
  
  -- 时间
  occurred_at             TIMESTAMPTZ NOT NULL,
  created_at              TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  
  CONSTRAINT fk_interaction_channel FOREIGN KEY (channel_account_id) 
    REFERENCES enterprise_channel_account(id) ON DELETE CASCADE,
  CONSTRAINT fk_interaction_action FOREIGN KEY (action_id) 
    REFERENCES enterprise_action(id) ON DELETE SET NULL,
  CONSTRAINT fk_interaction_outcome FOREIGN KEY (outcome_id) 
    REFERENCES enterprise_outcome(id) ON DELETE SET NULL
);

CREATE INDEX idx_interaction_tenant ON enterprise_interaction(tenant_id);
CREATE INDEX idx_interaction_gov ON enterprise_interaction(governance_tenant_id);
CREATE INDEX idx_interaction_channel ON enterprise_interaction(channel_account_id);
CREATE INDEX idx_interaction_customer ON enterprise_interaction(external_customer_id);
CREATE INDEX idx_interaction_action ON enterprise_interaction(action_id);
CREATE INDEX idx_interaction_outcome ON enterprise_interaction(outcome_id);
CREATE INDEX idx_interaction_occurred ON enterprise_interaction(occurred_at);
CREATE INDEX idx_interaction_type ON enterprise_interaction(interaction_type);

-- ═══════════════════════════════════════════════════════════
-- channel_outcome_mapping — 渠道→Outcome 映射规则
-- ═══════════════════════════════════════════════════════════

CREATE TABLE channel_outcome_mapping (
  id                        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id                 UUID NOT NULL,
  
  channel_type              TEXT NOT NULL,
  channel_event_type        TEXT NOT NULL,
  interaction_type          TEXT NOT NULL,
  
  outcome_type              TEXT NOT NULL,
  outcome_status            TEXT NOT NULL DEFAULT 'PENDING_VERIFY',
  confidence                INTEGER NOT NULL DEFAULT 50,
  
  requires_human_verification BOOLEAN NOT NULL DEFAULT TRUE,
  auto_verify_rules         JSONB NOT NULL DEFAULT '{}'::jsonb,
  
  is_active                 BOOLEAN NOT NULL DEFAULT TRUE,
  
  created_at                TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at                TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_mapping_tenant ON channel_outcome_mapping(tenant_id);
CREATE INDEX idx_mapping_channel ON channel_outcome_mapping(channel_type);
```

## 六、CTO 冻结约束（不可违反）

1. ❌ 不接入多个渠道（只做企业微信）
2. ❌ 不实现自动营销/群发
3. ❌ 不实现 Agent 自动回复
4. ❌ 不假装 Revenue 数据
5. ❌ 不存储明文凭证
6. ❌ 不自动确认 Outcome（默认人工确认）
7. ❌ 不做「渠道管理中心」空壳

---

## 七、Out of Scope（CTO 确认）

- ❌ 多渠道管理
- ❌ 自动营销
- ❌ Agent 自动回复
- ❌ Revenue Attribution
- ❌ CRM 完整功能

## 九、Architecture Target

```
Before (4.2.4-A):
  Action → Human Outcome

After (4.2.5):
  Action → WeChat Work → Real Interaction → Verified Outcome
                                      ↓
                              Confidence Feedback
```

**完整链路：**
```
WeChat Event → Interaction → OperationEvent → Signal → Decision → Action → Outcome
                                                                              ↓
                                                                  Channel Verification
                                                                              ↓
                                                                  Confidence Feedback
```

## 十、Risk Assessment

| 风险 | 缓解 |
|------|------|
| 企业微信审核周期 | 先做本地开发测试，后补审核 |
| 凭证安全 | AES-256 + 密钥分离存储 |
| 回调可靠性 | 消息队列 + 重试机制 |
| 数据量增长 | 按 tenant 分片 + 90 天归档 |
| 平台 API 变更 | Adapter 层隔离，不扩散到 Service |
