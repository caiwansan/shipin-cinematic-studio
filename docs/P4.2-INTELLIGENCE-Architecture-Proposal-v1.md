# Phase 4.2 — Enterprise Intelligence Architecture Proposal v1.0

**主题**: Enterprise Intelligence Loop
**核心问题**: 企业已拥有 AI 员工、知识、渠道之后，如何持续产生商业结果？
**日期**: 2026-07-15
**状态**: DRAFT — 待 CTO Review

---

## 一、问题与方向

Phase 4.0-4.1 已建立：
> 企业是什么（Tenant + AI部门 + 渠道 + 知识）

Phase 4.2 要回答：
> 企业如何赚钱（运营事实 → 信号采集 → 决策智能 → 行动闭环 → 收入归因）

**关键原则**: 不造新 Dashboard，只建立 **Enterprise Truth** + **Decision Loop**。

## 二、架构设计

### 2.1 五层模型

```text
┌─────────────────────────────────────────────────────┐
│  Layer 5: Revenue Attribution                       │
│  AI Action → Business Outcome                       │
├─────────────────────────────────────────────────────┤
│  Layer 4: Action Loop                               │
│  Recommendation → Approval → Execution → Verify     │
├─────────────────────────────────────────────────────┤
│  Layer 3: Decision Intelligence                     │
│  Signal → Issue Detection → Impact → Recommendation │
├─────────────────────────────────────────────────────┤
│  Layer 2: Signal Collection                         │
│  Raw Event → Normalization → Signal → Insight       │
├─────────────────────────────────────────────────────┤
│  Layer 1: Operation Reality Model                   │
│  Operation Event Timeline                           │
└─────────────────────────────────────────────────────┘
```

### 2.2 数据流

```text
Operation Events (DB records, API calls)
    ↓
Signal Collector
    ↓
Signal Table (normalized)
    ↓
Decision Engine (rule-based, no LLM dependency)
    ↓
Recommendation (for CEO)
    ↓
CEO Approval (existing task center)
    ↓
Agent Execution (existing runtime)
    ↓
Execution Result → Operation Events (loop closed)
```

## 三、Domain Model

### 3.1 OperationEvent — 运营事件

```typescript
interface OperationEvent {
  id: string                // UUID
  tenantId: string          // Tenant boundary
  eventType:                // 事件类型
    | 'lead_created'        // 商机发现
    | 'lead_status_changed' // 商机状态变化
    | 'content_published'   // 内容发布
    | 'content_interaction' // 内容互动
    | 'channel_connected'   // 渠道连接
    | 'knowledge_uploaded'  // 知识上传
    | 'task_completed'      // 任务完成
    | 'revenue_recorded'    // 收入记录
  actor: {
    type: 'agent' | 'user' | 'system'
    id: string
    name: string
  }
  target?: {
    type: 'lead' | 'content' | 'channel' | 'task'
    id: string
  }
  metadata: Record<string, any>  // 灵活扩展
  createdAt: Date
}
```

### 3.2 Signal — 业务信号

```typescript
interface Signal {
  id: string
  tenantId: string
  signalType:              // 信号类型
    | 'conversion_risk'    // 转化风险
    | 'engagement_spike'   // 互动激增
    | 'channel_decay'      // 渠道衰退
    | 'lead_warmup'        // 商机升温
    | 'knowledge_gap'      // 知识缺口
    | 'task_bottleneck'    // 任务瓶颈
  severity: 'info' | 'warning' | 'critical'
  sourceEvents: string[]   // 溯源到 OperationEvent
  description: string      // 为什么重要
  suggestedAction?: string // 建议行动
  status: 'active' | 'acknowledged' | 'resolved'
  detectedAt: Date
  resolvedAt?: Date
}
```

### 3.3 Recommendation — 决策建议

```typescript
interface Recommendation {
  id: string
  tenantId: string
  signalId: string         // 由哪个 Signal 触发
  category:               // 建议类别
    | 'sales'             // 销售行动
    | 'content'           // 内容策略
    | 'channel'           // 渠道调整
    | 'team'              // 团队调度
  priority: 1 | 2 | 3 | 4 | 5  // 1=最高
  title: string            // CEO 看到的标题
  rationale: string        // 为什么建议这个
  expectedImpact: string   // 预期效果
  actionPlan: string[]     // 行动步骤
  status: 'pending' | 'approved' | 'rejected' | 'executed'
  approvedAt?: Date
  executedAt?: Date
  outcome?: string
}
```

## 五、Database Impact

### 5.1 新增表（3张）

```sql
-- 运营事件表
CREATE TABLE enterprise_operation_event (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES tenants(id),
  event_type VARCHAR(50) NOT NULL,
  actor_type VARCHAR(20) NOT NULL,
  actor_id VARCHAR(100) NOT NULL,
  actor_name VARCHAR(200),
  target_type VARCHAR(50),
  target_id VARCHAR(100),
  metadata JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  INDEX idx_tenant_event (tenant_id, event_type),
  INDEX idx_tenant_time (tenant_id, created_at DESC)
);

-- 业务信号表
CREATE TABLE enterprise_signal (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES tenants(id),
  signal_type VARCHAR(50) NOT NULL,
  severity VARCHAR(20) NOT NULL DEFAULT 'info',
  source_events JSONB DEFAULT '[]',
  description TEXT,
  suggested_action TEXT,
  status VARCHAR(20) NOT NULL DEFAULT 'active',
  detected_at TIMESTAMPTZ DEFAULT NOW(),
  resolved_at TIMESTAMPTZ,
  INDEX idx_tenant_signal (tenant_id, status),
  INDEX idx_tenant_severity (tenant_id, severity)
);

-- 决策建议表
CREATE TABLE enterprise_recommendation (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES tenants(id),
  signal_id UUID REFERENCES enterprise_signal(id),
  category VARCHAR(50) NOT NULL,
  priority INTEGER NOT NULL DEFAULT 3,
  title VARCHAR(500) NOT NULL,
  rationale TEXT,
  expected_impact TEXT,
  action_plan JSONB DEFAULT '[]',
  status VARCHAR(20) NOT NULL DEFAULT 'pending',
  approved_at TIMESTAMPTZ,
  executed_at TIMESTAMPTZ,
  outcome TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  INDEX idx_tenant_rec (tenant_id, status),
  INDEX idx_tenant_priority (tenant_id, priority)
);
```

### 6.3 信号采集规则引擎（MVP 轻量版）

不依赖 LLM，基于规则：

```typescript
// 信号规则示例
const SIGNAL_RULES = [
  {
    type: 'conversion_risk',
    condition: (events) => {
      // 高意向商机超过24小时未跟进
      const hotLeads = events.filter(e => 
        e.eventType === 'lead_status_changed' && 
        e.metadata.temperature === 'hot' &&
        hoursSince(e.createdAt) > 24
      )
      return hotLeads.length >= 3
    },
    severity: 'critical',
    message: (count) => `${count}个高意向商机超过24小时未跟进`
  },
  {
    type: 'channel_decay',
    condition: (events) => {
      // 渠道互动率下降超过20%
      const recent = events.filter(e => 
        e.eventType === 'content_interaction' &&
        hoursSince(e.createdAt) < 24
      )
      const previous = events.filter(e =>
        e.eventType === 'content_interaction' &&
        hoursSince(e.createdAt) >= 24 &&
        hoursSince(e.createdAt) < 48
      )
      return previous.length > 0 && 
        (recent.length / previous.length) < 0.8
    },
    severity: 'warning',
    message: () => '渠道互动率下降超过20%'
  }
]
```

## 八、架构风险与缓解

### ⚠️ Risk 1: Fake Intelligence

**风险**: AI Score = random() / AI Insight = template()
**缓解**: 所有 Signal 必须基于 OperationEvent 数据，禁止随机生成

### ⚠️ Risk 2: Dashboard Proliferation

**风险**: 又造 CEO Dashboard v2 / Sales Dashboard / AI Dashboard
**缓解**: 统一在 CEO Workspace 增加 Intelligence Feed 卡片，不新建页面

### ⚠️ Risk 3: Runtime Contamination

**风险**: 信号采集侵入 agent-scheduler.runtime.ts
**缓解**: Intelligence Layer 独立于 Runtime，通过 OperationEvent 表间接获取数据

### ⚠️ Risk 4: Tenant Boundary Violation

**风险**: Signal 跨租户泄露
**缓解**: 所有查询走 `tenantOnly()` guard，复用 Phase 4.1 验证机制
