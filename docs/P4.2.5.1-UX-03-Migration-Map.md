## 一、Migration Strategy

### 三阶段模型

```
Phase A — Foundation Migration (UX-01 + UX-02)
    |
    | 建立 Shell + Token + 基础组件 + Boundary Contract
    ↓

Phase B — Experience Migration (UX-03 ← 当前)
    |
    | 页面进入 Enterprise Journey
    ↓

Phase C — Intelligence Migration (UX-04 + UX-05)
    |
    | 接入 Signal → Decision → Action → Outcome
```

### 核心原则

```
Legacy Pages
    ↓
Migration Layer (本提交)
    ↓
Enterprise UI Kit
    ↓
Enterprise OS Experience
```

**禁止：**
- ❌ 删除旧页面重新写
- ❌ 一个页面一个页面自由重构
- ❌ 新旧 UI 混合长期存在
- ❌ 页面直接接 Service

## 三、页面职责重新定义

### 旧模式

```
Dashboard
 ├ KPI 卡片（内联硬编码）
 ├ 数据表格（原生 table）
 ├ CRUD 按钮（裸 button）
 └ 无 Intelligence Flow
 └ 无 Decision Context
```

**问题：**
- 不知道用户下一步做什么
- 没有 Intelligence 链路
- 无 Decision 关联
- 无 Outcome 反馈

### 新模式

```
Command Center

Observe — 我看到了什么？
 |
Signals
 |
Understand — 为什么发生？
 |
Recommendations
 |
Decide — 我要选择什么？
 |
Decision Review
 |
Execute — 系统做什么？
 |
Actions
 |
Learn — 结果如何反馈？
 |
Outcome
```

**每个页面必须回答五问：**

| 问题 | 页面响应 |
|------|---------|
| Observe：我看到了什么？ | Signal Feed / KPI |
| Understand：为什么发生？ | Evidence Graph |
| Decide：我要选择什么？ | Decision Queue |
| Execute：系统做什么？ | Action Timeline |
| Learn：结果如何？ | Outcome Loop |

## 五、Data Migration Map

### 核心原则：页面不再拥有数据

**旧模式（禁止）：**
```
Page.vue
   ↓
fetch API
   ↓
state
   ↓
template
```

**新模式（强制）：**
```
API
   ↓
Service
   ↓
Store
   ↓
EnterpriseDataEnvelope { data, source, freshness }
   ↓
Component
```

### 数据所有权表

| 数据 | Source | 消费者 |
|------|--------|--------|
| Signals | OperationEvent | Intelligence / Command Center |
| Decisions | DecisionEngine | Decision Review / Command Center |
| Actions | ActionLifecycle | Execution Center / Command Center |
| Outcomes | OutcomeIntelligence | Command Center / Learning Loop |
| Channels | ChannelSync | Channel Center |
| Customers | CustomerMapping | Channel Center |
| Permissions | EnterpriseContext | All |
| Knowledge | KnowledgeBase | Knowledge Hub |
| Leads | LeadScoring | Growth → Leads |
| Deals | LeadScoring | Growth → Pipeline |
| ROI | OutcomeIntelligence | Growth → ROI |
| Audit | AuditLog | Governance |

### 页面数据模式对照

| 页面 | 旧数据模式 | 新模式 |
|------|----------|--------|
| Command Center | `const signals = 12` | `Envelope<MetricValue>` |
| Decision Center | `fetch('/api/decisions')` | `Envelope<Decision[]>` |
| Execution Center | `this.list = res.data` | `Envelope<ActionProgress[]>` |
| Channel Center | 无（新建） | `Envelope<ChannelStatus[]>` |
| Growth | `tableData.map(x => x)` | `<Envelope<Lead[]>` |

## 七、Migration Rules（冻结）

### Rule 1: 页面数据流

新页面必须：
```
EnterpriseShell
    ↓
Page.vue
    ↓
Store
    ↓
Service
    ↓
API
```

禁止：
```
Page.vue
   ↓
API / Service
```

### Rule 2: 组件数据入口

所有 UI Kit 组件只能：
```
- props
- events
- slots
```

禁止：
```
component.vue
   ↓
import service from '@/services/...'
```

### Rule 3: 数据完整包装

所有展示层数据必须：
```
{ value, source, freshness }
```

禁止：
```
{ count: 12 }
```

### Rule 4: 页面五问

所有页面必须回答：

1. **Observe** — 我看到了什么？
2. **Understand** — 为什么发生？
3. **Decide** — 我要选择什么？
4. **Execute** — 系统做什么？
5. **Learn** — 结果如何反馈？
