# Business Completion 指标

> 替代"代码完成度"，衡量**企业招聘真实业务流**的打通程度。

| # | 业务能力 | 状态 | 验证方式 |
|---|---------|------|---------|
| 1 | 企业注册 | ✅ | 注册即用 |
| 2 | 企业 Onboarding | ✅ | 5步流程完整 |
| 3 | 创建 JD | ⚠️ | API 有，前端无 UI |
| 4 | 收到候选人 | ❌ | **无简历入口** |
| 5 | AI 分析简历 | ❌ | 评分=Random+规则 |
| 6 | AI 面试 | ❌ | 模板匹配，无 LLM |
| 7 | 发送 Offer | ⚠️ | 生成文本，无审批流 |
| 8 | 入职 | ❌ | 无流程 |
| 9 | 支付/订阅 | ❌ | 无 |

**Business Completion: 2/9 = 22%**

> 只有当企业能完成一次真实招聘（从收到候选人到 Offer），这个指标才有意义。

# Beta Roadmap v2.0（按业务价值闭环重排）

## 原则

- 不按功能模块排（A4、A5）
- 按**业务闭环**排：候选人 → AI 分析 → 面试 → Offer → 入职 → 付费
- 每个 Beta 版本必须让企业**多完成一个真实招聘步骤**

---

## Beta 0.3 — Candidate Source（候选人来源）

> **目标：让企业收到真实候选人。**

### 必须完成

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 简历上传 UI | P0 | PDF/DOCX 拖拽上传 |
| Resume Parser 集成 | P0 | 上传 → 解析 → ResumeProfile |
| 候选人自动入库 | P0 | 解析完成 → RecruitmentPipeline |
| Pipeline 候选人添加 | P0 | 手动添加候选人（无简历时） |
| 简历列表页 | P1 | 查看已上传简历 |

### 验收标准

- [ ] 企业上传一份 PDF 简历
- [ ] 系统自动解析出姓名/技能/经验
- [ ] 候选人自动出现在 Pipeline Kanban
- [ ] 可手动添加候选人（姓名+职位）

### 技术要点

- 复用 `ResumeParserAgent`（已存在，需集成）
- 文件存储：本地磁盘或 OSS
- 解析失败时允许手动补全

---

## Beta 0.4 — Real AI Runtime（真实 AI 招聘）

> **目标：让 AI 真正参与招聘。**

### 必须完成

| 功能 | 优先级 | 说明 |
|------|--------|------|
| AI 简历分析 | P0 | 调用 LLM 分析简历 → 评分+理由 |
| AI 面试题生成 | P0 | 基于简历+JD 的 LLM 面试题 |
| AI 招聘 Agent 接入 | P0 | 连接 Runtime，真正运行 |
| Token 成本统计 | P1 | 每次 AI 调用记录 Token 消耗 |
| 成本 Dashboard | P1 | 显示真实 AI 成本 |

### 验收标准

- [ ] 上传简历后，AI 给出评分和理由（非 Random）
- [ ] 生成面试题引用候选人真实经历
- [ ] Dashboard 显示真实 Token 消耗
- [ ] AI 员工状态可见（运行中/空闲/错误）

### 技术要点

- 接入 Hermes Agent Runtime
- 评分逻辑：LLM 分析 → 结构化输出
- Token 计费：按调用记录

## Beta 0.5 — Commerce（商业闭环）

> **目标：让 SaaS 真正收费。**

### 必须完成

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 套餐选择 → 支付 | P0 | 微信/支付宝集成 |
| 用量计费 | P0 | Token 消耗 → 费用 |
| 订阅周期 | P0 | 月/年订阅，到期提醒 |
| BYOK | P1 | 企业自带 API Key |
| 升级/降级 | P1 | 套餐变更 |
| 发票 | P2 | 企业开票 |

### 验收标准

- [ ] 企业选择套餐后完成支付
- [ ] 月底生成账单（Token 消耗 × 单价）
- [ ] 企业可查看当前用量和剩余额度
- [ ] 支持升级套餐

## 版本对比

| 维度 | 旧 Roadmap | 新 Roadmap |
|------|-----------|-----------|
| 排序逻辑 | 功能模块（A4→A5） | 业务闭环（候选人→AI→付费） |
| 成功标准 | "完成开发" | "企业多完成一个招聘步骤" |
| 风险 | 功能堆积，无真实用户 | 每版都有真实业务价值 |
| 可衡量 | 代码完成度 | Business Completion |

## 冻结声明

**A4 AI Runtime Center 开发计划正式冻结。**

原 A4 的"首页运营面板"、"BYOK 配置"、"AI 员工管理"等需求，按优先级拆分到 Beta 0.4 和 Beta 0.5。

**理由：** 没有候选人时，Runtime 面板是空的；没有真实 AI 运行时，BYOK 无意义。
