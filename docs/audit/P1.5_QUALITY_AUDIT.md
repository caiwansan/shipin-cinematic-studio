### 异常端点

1. **`/api/geo/brands` vs `/api/geo/projects`** — 同样的资源（品牌/项目）使用两种命名。`geo-brand.route.ts` 使用 `brands`，而 `geo-project.route.ts` 使用 `projects`。前端 `GEOCreate.vue` 使用 `/api/geo/projects`。
2. **`/api/v1/geo/discovery/*`** — 三个端点使用了 `/api/v1/` 前缀，与主流的 `/api/geo/` 不一致。且**缺少 auth 中间件**。
3. **`/api/geo/reports`（复数）vs `/api/geo/report`（单数）** — `geo-report.route.ts` 使用 `reports`，`geo-deliverable.route.ts` 使用 `report`。
4. **`/api/geo/traces/project/:id/summary`** — 嵌套风格不一致，其他端点使用 `/api/geo/projects/:id/xxx`。
5. **`geo-discovery.route.ts` 无 auth 中间件** — 三个端点都没有 `preHandler: [fastify.authenticate]`，可被未认证请求调用。
6. **`PATCH /api/geo/claims/:id`** 是唯一的 PATCH 方法，其余更新都用 PUT — 不一致的 HTTP 方法选择。

### Response 格式

所有端点都统一使用 `{ success, data }`（或 `{ success, data, error }`）格式。✅ 一致。

### Auth 中间件

- 67/70 个端点配置了 `preHandler: [fastify.authenticate]` ✅
- 3/70 个端点（`/api/v1/geo/discovery/*`）无 auth ❌

### 建议优先修复项（Top 5）

1. **🔴 [严重] 清理 51 个 .bak 残留文件** — 尤其是 `backend/src/services/geo/` 下的 27 个。这些文件不会被编译或运行，但会混淆开发环境、增加安全隐患（旧代码被误用）。
2. **🔴 [严重] 为 `/api/v1/geo/discovery/*` 端点添加 auth 中间件** — 三个端点目前**完全开放**给未认证请求，在生产环境中是安全漏洞。
3. **🟡 [高] 消除 Service 层的 PrismaClient 直接访问** — `geo-persistence.service.ts` 绕过了 Repository 层，违反分层架构。应将 Prisma 操作下放到 Repository。
4. **🟡 [高] 统一 `brands` vs `projects` API 命名** — 同一资源两种命名方式造成前端混乱。`geo-brand.route.ts` 应重命名为 `/api/geo/projects` 风格或作为已废弃标记。
5. **🟡 [中] 为 8 个未分页的列表端点添加分页支持** — 包括 `projects`、`brands`、`scans`、`keywords`、`knowledge`、`entities`、`edges` 等列表接口，避免数据膨胀后的性能问题。

### 次要建议

- 统一前端 Design Token 使用：低分页面（DiscoveryLabPage、ReportCenter、VerificationPage）应迁移到 CSS 变量体系
- 为 frontend 所有 `ref<any[]>` 替换为具名类型定义（预估 3-4 个新增 `.d.ts` 文件）
- 替换 `console.warn/console.log` 为正式的错误处理逻辑（12 处）
- 重构 `geo-brand.route.ts` 和 `geo-dashboard.route.ts` 中的 Repository 直接调用，创建对应的 Service 文件
