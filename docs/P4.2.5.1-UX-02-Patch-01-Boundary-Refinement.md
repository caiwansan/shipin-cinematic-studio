## Patch 1：EnterpriseShell Boundary Contract v1.1

### ❌ 删除旧版 EnterpriseShell Props（第三章定义的完整 props）

### ✅ 替换为精简版：

```typescript
/**
 * EnterpriseShell Boundary Contract v1.1
 * 
 * Shell 只关心视觉状态 + 交互状态。
 * 不关心：谁登录 / 哪个企业 / 有什么权限 / 显示哪些菜单
 */

interface EnterpriseShellProps {
  /** Sidebar 折叠状态 */
  collapsed?: boolean
  /** 移动端 Sidebar 展开状态 */
  mobileOpen?: boolean
}

interface EnterpriseShellEvents {
  /** Sidebar 折叠/展开 */
  (e: 'sidebar-toggle', collapsed: boolean): void
  /** 导航跳转（由 Sidebar 触发） */
  (e: 'navigation-change', path: string): void
  /** 工作区切换（预留） */
  (e: 'workspace-change', workspace: string): void
}

interface EnterpriseShellSlots {
  /** 主内容区 */
  default: void
  /**  Header 右侧扩展 */
  'header-extra': void
  /** Sidebar 底部扩展 */
  'sidebar-extra': void
}
```

### ❌ Shell 禁止清单（新增）

```typescript
// EnterpriseShell.vue 内 ❌ 禁止

// 禁止：知道业务身份
const { tenant, user } = useEnterpriseContext()  // ❌

// 禁止：权限判断
const can = usePermission()  // ❌

// 禁止：自行生成导航
const navItems = generateNavItems()  // ❌

// 禁止：引用业务 Service
import { enterpriseSignalService } from ...  // ❌
import { channelService } from ...  // ❌
import { actionService } from ...  // ❌

// 禁止：直接 fetch
const data = await fetch('/api/...')  // ❌
```

### ✅ 正确数据流

```
AuthStore
    ↓
EnterpriseContext (composable)
    ↓ (提供)
EnterpriseSidebar (自行获取 context)
EnterpriseHeader (自行获取 context)
    ↓ (渲染)
EnterpriseShell (仅接收 collapsed / mobileOpen)
    ↓ (slot)
NuxtPage → Page 自行获取 context
```

**原则：Shell 是哑组件，不包含业务状态。**

## Patch 2：Enterprise Data Envelope Contract v1.1

### 所有 UI-bound 数据必须遵守

```typescript
/**
 * Enterprise Data Envelope
 * 展示层数据的强制包装
 * 
 * 没有 exceptions — 所有展示数据必须包含来源和新鲜度
 */

interface EnterpriseDataEnvelope<T> {
  /** 业务数据 */
  data: T
  /** 数据来源 — 必须是已注册 source 之一 */
  source: string
  /** 数据更新时间 — ISO 8601 format */
  freshness: string
}

// 示例 1：Metric 数据（Single Value + Trend）
interface MetricValue {
  value: number
  trend?: string        // "+20%" or "-5%"
}
type MetricEnvelope = EnterpriseDataEnvelope<MetricValue>

// 实际 payload：
// {
//   "data": { "value": 12, "trend": "+20%" },
//   "source": "OperationEvent",
//   "freshness": "2026-07-15T20:10:00Z"
// }

// 示例 2：列表数据（Paginated）
interface ListData<T> {
  items: T[]
  total: number
  page: number
  pageSize: number
}
type ListEnvelope<T> = EnterpriseDataEnvelope<ListData<T>>

// 示例 3：导航项
interface NavigationItem {
  id: string
  label: string
  path: string
  badge?: number | string
  capability?: string
}
type NavigationEnvelope = EnterpriseDataEnvelope<NavigationItem[]>

// 示例 4：Channel Status
interface ChannelStatus {
  id: string
  connected: boolean
  lastSyncAt: string
  interactionCount: number
}
type ChannelStatusEnvelope = EnterpriseDataEnvelope<ChannelStatus[]>
```

### ❌ 禁止的旧格式

```typescript
// 裸 Metric
{
  "value": 12,
  "trend": "+20%"
}  // ❌ 没有 source，没有 freshness

// 裸列表  
{
  "items": [...],
  "total": 128
}  // ❌ 没有 source，没有 freshness

// 裸导航
[
  { "id": 1, "label": "Command Center" }
]  // ❌ 没有 source，没有 freshness
```

### ✅ Store 强制转换规则

```typescript
// 所有 Store getter 返回前必须包装
const getters = {
  metrics: (state) => {
    const raw = state.metrics
    return {
      data: { value: raw.count, trend: raw.trendPercent },
      source: 'OperationEvent',
      freshness: raw.updatedAt  // ISO 8601
    }
  },
  
  navigationItems: (state) => {
    const raw = state.navigation
    return {
      data: raw.items,
      source: 'EnterpriseContext',
      freshness: raw.loadedAt
    }
  }
}
```

### Component Props 接收规则

```vue
<!-- MetricCard.vue -->
<script setup>
defineProps<{
  metric: EnterpriseDataEnvelope<MetricValue>
}>()
</script>

<template>
  <div class="metric-card">
    <div class="value">{{ metric.data.value }}</div>
    <div class="trend">{{ metric.data.trend }}</div>
    <div class="meta">
      <span class="source">{{ metric.source }}</span>
      <span class="freshness">{{ formatTime(metric.freshness) }}</span>
    </div>
  </div>
</template>
```

### Source 注册清单（第一批）

| Source Name | 数据类别 | 所属系统 |
|-------------|---------|---------|
| `OperationEvent` | Signals / Events | 运营事件 |
| `DecisionEngine` | Decisions / Ranking | 决策引擎 |
| `ActionLifecycle` | Actions / Progress | 执行引擎 |
| `OutcomeIntelligence` | Outcomes / Impact | 结果智能 |
| `ChannelSync` | Channels / Interactions | 渠道同步 |
| `CustomerMapping` | Customer Mappings | 客户映射 |
| `EnterpriseContext` | Tenant / User / Role | 租户上下文 |
| `KnowledgeBase` | Articles / Playbooks | 知识库 |
| `LeadScoring` | Leads / Pipeline | 线索评分 |
| `AuditLog` | Audit Entries | 审计日志 |

### 为什么这是必须的

Enterprise 产品和普通 SaaS 最大区别：

- **普通 SaaS：** "给我一个数字"
- **Enterprise：** "给我一个可信数字，并告诉我 **来源** 和 **更新时间** "

如果 CEO 问："这个数字怎么来的？" → UI 必须能回答。
