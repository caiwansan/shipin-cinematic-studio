## 架构变更

### Before (IMP-01.1)
```
WeComClient
  ├── accessToken (in-memory field)
  ├── refreshPromise (in-memory field)
  ├── getAccessToken() → fetch("gettoken")
  └── fetchAccessToken() → 直接调用 WeCom API
```

### After (IMP-01.2)
```
WeComClient (stateless)
  └── getAccessToken() → TokenService.getToken(accountId)
                           ↓
                       TokenService
                           ├── loadCredential(accountId) → DB
                           ├── TokenCache.get(corpId) → Memory
                           └── fetchToken(credential) → WeCom API
                               ↓
                       TokenCache (Singleton)
                           ├── Map<corpId, TokenEntry>
                           ├── get() / set() / invalidate()
                           └── refreshPromise (并发控制)
```

---

## Token 状态机器

```
No Token → Request Token → Cache Token → Reuse → Expire → Refresh
                                                        ↓
                                              ChannelHealth = ERROR
```

### 状态转换

| 当前状态 | 事件 | 动作 | 下一状态 |
|----------|------|------|----------|
| No Token | API 请求 | fetchToken() → setCache | Cached |
| Cached | get() 命中 | 直接返回 | Cached |
| Cached | Preload 5min | 异步 refresh | Cached (旧 Token 仍可用) |
| Cached | 42001/40014 | invalidate + refresh | Cached (新 Token) |
| Cached | 40001/41001 | invalidate + ERROR | Error |
| Error | 手动 API 调用 | refreshToken | Cached |

## 并发控制

```
Request-1 ──→ TokenService.getToken() ──→ TokenCache.get() → Miss
Request-2 ──→ TokenService.getToken() ──→ TokenCache.getRefreshPromise() → 复用
Request-3 ──→ TokenService.getToken() ──→ TokenCache.getRefreshPromise() → 复用
                 ↓
            只有一个请求调用 WeCom API
                 ↓
            TokenCache.set(corpId, token, expiresAt)
                 ↓
            Request-1/2/3 全部获得同一 Token
```
