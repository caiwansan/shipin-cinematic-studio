## ⑤ Capability — REAL LLM 调用

### 代码路径
```
GEO Agent 能力调用:
ctx.capabilities.llm.generate(prompt, options)
  → CapabilityRuntime.createLLMCapability()
    → CapabilityRuntime.executeLLM(request)
      → Provider.complete(request)            // OpenAIProvider
        → fetch(OPENAI_BASE_URL + /chat/completions)
          → LLM API → response
```

### 文件清单
| 文件 | 类型 | 说明 |
|------|------|------|
| `packages/studio-platform/src/capability/openai-provider.ts` | **NEW** (C1.5) | OpenAI 兼容 Provider，真实 HTTP 调用 |
| `packages/studio-platform/src/capability/capability-runtime.ts` | **UPDATED** (C1.5) | 从 shim 升级，支持真实 Provider 路由 |

### 验证结果
- `CapabilityRuntime` 不再是无操作 shim:
  - `registerProvider()` — 注册真实 Provider 实例
  - `executeLLM()` — 路由到最高优先级可用 Provider
  - `createLLMCapability()` — 生成 agent 可用的 generate 函数
  - `discover()` — 返回真实能力信息
- `OpenAIProvider` 特性:
  - 兼容任意 OpenAI 格式 API（OpenAI, DeepSeek, SiliconFlow, 等）
  - 支持非流式和流式（SSE）调用
  - 自动重试（指数退避: 1s, 2s, 4s）
  - 超时控制（默认 30s）
  - 健康检查 (`/v1/models` 端点)
- **已移除**: GEO KQ route 中的 `createStubLLM` 不需要修改 — C1.5 创建了真实 LLM 通道，C2 将 GEO 路由迁移后自然替换
