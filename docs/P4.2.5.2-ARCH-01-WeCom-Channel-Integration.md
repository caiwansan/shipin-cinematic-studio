# P4.2.5.2-ARCH-01 — WeCom Channel Integration Architecture

> Sprint 4.2.5.2 — WeCom Real SDK
> Status: 待CTO验收
> Type: Architecture Design Document (No Code)

---

## 目标

将 Enterprise OS 从内部 Intelligence Surface 扩展为外部企业连接层。

```text
Sprint 4.2.5.1 (已完成):
  OperationEvent → Decision → Action → Outcome

Sprint 4.2.5.2 (新增):
  WeCom → Channel Adapter → Interaction Intelligence → Enterprise OS
```

---

## 三原则（冻结）

### Rule 1 — Channel ≠ Business Logic

```text
禁止: WeCom SDK → Decision Engine
必须: WeCom SDK → Channel Adapter → Canonical Interaction Model → Enterprise Intelligence
```

### Rule 2 — Provider Isolation

WeCom 只是 Channel Provider 之一。未来支持 Email/WhatsApp/Slack/CRM/WebChat。

### Rule 3 — External Data Must Enter Envelope

所有外部数据必须包装为 `EnterpriseDataEnvelope<T>`，禁止裸数据进入 UI。

---

## 一、WeCom SDK Boundary

```text
WeCom Platform (Message/Customer/Contact/Event)
    ↓
WeCom Adapter Layer (Auth/Token/Signature/Event Normalize)
    ↓
Channel Domain Layer (ChannelMessage/CustomerIdentity/InteractionEvent)
    ↓
Enterprise Intelligence (Signal/Decision/Action/Outcome)
```

---

## 二、Channel Adapter Interface（冻结）

```ts
interface ChannelAdapter<TConfig> {
  connect(config: TConfig): Promise<ChannelConnection>
  disconnect(): Promise<void>
  sync(): Promise<ChannelSyncResult>
  send(message: ChannelMessage): Promise<MessageResult>
  receive(event: ExternalChannelEvent): Promise<void>
  health(): Promise<ChannelHealth>
}
```

---

## 三、Message / Event Mapping

### WeCom → Internal Event

| WeCom Event      | Internal Event          |
| ---------------- | ----------------------- |
| Customer Message | CustomerMessageReceived |
| Customer Added   | CustomerConnected       |
| Customer Removed | CustomerDisconnected    |
| Agent Reply      | AgentResponded          |
| Group Message    | GroupInteraction        |
