## 审计 1: 现有 Tenant 模型是否满足 Activation

### 模型盘点

| 现有字段 | 用途 | 对Activation的支撑 |
|----------|------|-------------------|
| `id` | UUID | ✅ 唯一租户标识 |
| `name` | 企业名称 | ✅ 企业身份 |
| `type` | personal/team/enterprise | ✅ 区分企业租户 |
| `status` | active/expired | ✅ 生命周期 |
| `metadata` | JSON | ⚠️ 可承载行业/目标等，但不结构化 |

### Species

**现有 Tenant 模型对 Phase 4.1 的支撑度：**

| Spec 需求 | 现有能力 | 缺口 |
|-----------|----------|------|
| 创建企业 | ✅ `Tenant.create()` 已实现 | 无 |
| 企业身份（名称） | ✅ `name` 字段 | 无 |
| 行业/目标/市场 | ⚠️ 可存入 `metadata` JSON | 无结构化字段 |
| 企业Logo | ⚠️ 可存入 `metadata` | 无 |
| Demo/生产隔离 | ❌ 无 `mode` 字段 | 需要加 |

### 修复方案

**建议**：为 `governance_tenant` 表增加一个 `mode` 字段：

```sql
ALTER TABLE governance_tenant 
ADD COLUMN IF NOT EXISTS mode VARCHAR(20) DEFAULT 'production'
CHECK (mode IN ('demo', 'production'));
```

- Tesla Demo Tenant 的 `mode` 设置为 `'demo'`
- 所有新建租户默认 `'production'`
- API 层过滤时 `WHERE mode != 'demo'`

**替代方案**：不使用新字段，在代码中硬编码 `DEMO_TENANT_ID` 常量，API层过滤。

**推荐**：优先硬编码常量方案（零数据库变更），后续按需加字段。

### 审计 1 结论：✅ PASS

- 现有 Tenant 模型满足企业创建需求
- Demo 隔离可通过硬编码 `DEMO_TENANT_ID` 实现，无需新增字段
- 行业/目标/市场可在 `Setup Wizard` 流程中通过 **TenantIndustry** 等外部关联表或 metadata 承载

## 审计 3: 现有 Channel 接口真实能力边界

### 阶段盘点

| 接口 | 用途 | 真实能力 | 备注 |
|------|------|----------|------|
| `enterprise-channel.ts` | 渠道账号管理 | DB记录读写 | 无OAuth |
| `channel.adapter.ts` | 统一接口定义 | — | 仅接口定义 |
| `mock.adapter.ts` | 全平台模拟 | ❌ 不存在真实调用 | Mock |
| `extended.adapter.ts` | 抖音/B站/微博 | ❌ 不存在真实调用 | Mock |

### 默认状态修复 — 必须

**当前状态**：`EnterpriseChannelAccount.status` 默认值 `"connected"`

```prisma
status  String  @default("connected") @db.VarChar(20)
```

**这是Trust Gate的核心问题**：
- 字段默认值 = "connected" → 新建渠道记录 → 用户看到"已连接"
- 实际上无OAuth Token、无认证、无法发布

**修复要求**：

```sql
ALTER TABLE enterprise_channel_account 
ALTER COLUMN status SET DEFAULT DEFAULT 'disconnected';
```

**影响范围**：
- 新创建的渠道记录 → `status = 'disconnected'` ✅
- 已有渠道记录 → 需要 UPDATE 重置 → `status = 'disconnected'`
- Tesla Demo 渠道记录 → 保持 `status = 'connected'`（Demo模式）

### 真实OAuth方案（Phase 4.3+）

不在 Phase 4.1 范围。需要：
1. 渠道开发者账号（微信公众号平台/抖音开放平台等）
2. OAuth回调URL配置
3. Token加密存储与刷新
4. 每个渠道的独立Adapter实现

**Phase 4.1 不做**：真实OAuth接入
**Phase 4.1 必须做**：状态默认值修复 + 展示真实状态

### 审计 3 结论：✅ PASS WITH ACTION

- 现有渠道模型能力满足 Activation 需求（DB记录+API完善）
- **唯一阻塞**：默认 `status = "connected"` 必须改为 `'disconnected'`
- 此修改为**数据迁移小改**，不涉及Runtime
