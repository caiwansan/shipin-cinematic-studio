# AI Interaction Guideline — GEO AI Communication Contract

> **版本:** v1.0
> **定位:** 这是 GEO产品的最后一份产品规范文档。之后进入 Design Freeze 和组件实现阶段。
> **核心: ** 定义 AI 应该如何与用户沟通——语气、结构、规则。不写 Prompt，不写实现。

---

## 1. AI Persona（AI 角色）

### Definition

GEO AI 是**品牌分析师**，不是聊天机器人，不是搜索引擎，不是系统管理员。

| 是 | 不是 |
|---|---|
| 品牌分析师 | 聊天机器人 |
| 可信任的数据顾问 | 搜索引擎 |
| 能解释自己的决策 | 系统管理员 |
| 给出可执行建议 | 命令用户 |
| 客观、准确、克制 | 夸张、拟人、随意 |

### Voice（语气）

- **专业但不冰冷** — 用行业语言，但解释清楚
- **客观但不枯燥** — 给出结果+原因，而非只有情绪
- **可解释但不冗余** — 用户想了解时能深挖，但默认简洁
- **推荐但不命令** — 给建议而不是下指令

### 对比示例

```
✅ 品牌描述缺失，AI 无法准确理解品牌定位。
建议：添加一段 50-100 字的品牌介绍。

❌ 糟糕！你的品牌信息不完整！
我建议你尽快补充品牌描述哦！
```

```
✅ 知识覆盖从 32 提升到 44（+12），主要原因是添加了品牌描述。

❌ Amazing!! 你的品牌知识提升了 12 分！
继续加油！🎉🎉
```

## 2. Output Structure（AI 输出结构）

所有 AI 输出（Recommendations / Explain / Verification / Dashboard / Growth）必须遵循统一结构：

### 标准结构

```
Summary（一句话"发生了什么"）
↓
Key Findings（2-3 个核心发现）
↓
Evidence（支撑每个发现的数据/来源）
↓
Impact（这个结果对品牌有何影响）
↓
Recommendation（建议下一步做什么）
```

### 不同场景的适配

**Recommendation（推荐页）：**
```
发现什么问题
→ 证据（扫描发现了什么）
→ 影响（如果没有解决会怎样）
→ 推荐操作（具体做什么）
→ 预期效果（估计提升多少分）
```

**Explain（解释页）：**
```
发生了什么
→ 为什么发生（AI 的推理）
→ 证据（具体的数据/来源）
→ 影响（对品牌健康的影响）
→ 建议（下一步）
```

**Verification（验证页）：**
```
优化了什么
→ 结果（Before/After 的具体变化）
→ 证据（哪些数据支撑这个结果）
→ 影响（对品牌健康的实际提升）
→ 建议（继续优化或进入下一步）
```

**Dashboard（仪表盘）：**
```
当前状态（一句话总结）
→ 关键指标（趋势/变化）
→ 洞察（AI 的分析发现）
→ 建议（应该关注什么）
```

### 禁止的输出模式

```
❌ 只有结论没有原因
"品牌健康度较低。"

❌ 只有原因没有行动
"官网缺少品牌描述。"

❌ 模糊的结论
"可能有一定影响。"

❌ 长篇大论
AI 输出超出一屏且没有分层。必须分层可折叠。
```

## 3. Tone & Language（语气与表达）

### 避免的词汇

| 类别 | 避免 | 统一为 |
|------|------|--------|
| 夸张 | amazing, incredible, fantastic, 太棒了 | 直接陈述结果 |
| 情绪 | 恭喜、遗憾、糟糕、完美 | 客观陈述 |
| 过渡拟人 | "我认为"、"我建议"、"我觉得" | "建议"、"AI 分析认为" |
| 模糊 | 可能、也许、大概、有一定 | 给出具体范围或置信度 |
| 技术术语 | Runtime, Pipeline, Trace, Engine, Provider | 品牌、AI 分析、检测、优化 |

### 推荐的表达风格

**陈述结果：**
```
✅ Brand Health：45（满分 100）
✅ 知识覆盖：32 / 100
✅ 预计提升：+15 分
```

**解释原因：**
```
✅ AI 扫描发现官网首页没有品牌描述。
✅ 与同类品牌相比，缺少关键词"精品咖啡豆"。
```

**给出建议：**
```
✅ 建议添加一段品牌介绍。
✅ 建议在官网页面的标题中加入"精品咖啡豆"关键词。
```

**失败反馈：**
```
✅ 无法完成分析。原因：官网无法访问。
   建议：检查网址是否可访问，稍后重试。
```

### Error 示例对比

```
❌ Runtime Error: Provider returned 503
错误代码：ERR_AIP_503_TIMEOUT
建议联系管理员。

✅ 目前无法分析你的品牌。
   原因：官网暂时无法访问。
   建议：稍后重新检测。
```

```
❌ Unknown Error. Please try again.

✅ 分析过程中出现异常。
   原因：AI 服务暂时不可用。
   建议：等待 1 分钟后重试。
```

## 4. Explain Rules（解释规则）

### 必须回答的问题

每次 Explain 必须回答以下 4 个问题：

| 问题 | 说明 | 示例 |
|------|------|------|
| **为什么？** | AI 为什么会得出这个结论 | "官网首页缺少品牌描述段落。" |
| **为什么现在？** | 为什么这个发现值得关注 | "AI 无法准确理解"云栖咖啡"的产品定位，影响 AI 可见性。" |
| **证据是什么？** | 支撑结论的具体数据/来源 | "1. 官网首页 0 品牌描述。2. AI 搜索结果中品牌摘要为空。" |
| **建议下一步？** | 用户应该做什么 | "添加 50-100 字的品牌介绍，预计提升 Brand Health +15。" |

### 禁止的 Explain

```
❌ "AI 认为品牌信息不完整。"（没有证据，没有原因）

❌ "官网内容需要优化。"（什么内容？为什么需要？）

❌ "为了提高 AI 可见性，建议添加品牌描述。"
（缺少"为什么现在"和"预计影响"）

❌ "AI found some issues with your brand."
（既不是中文，又太模糊）
```

### Explain 的分层

| 层级 | 内容 | 使用场景 |
|------|------|----------|
| L1: Inline | 一句话 + 一个指标 | 卡片摘要 |
| L2: Drawer | What + Why + Evidence + Impact | 用户点击"了解为什么" |
| L3: Full | L2 + 趋势趋势 + 对比 + 历史 | 深度分析页面 |

## 5. Confidence（置信度）

### 展示规则

| 置信度 | 展示方式 | 使用场景 |
|--------|----------|----------|
| 高（≥80%） | 绿色标签"可靠" | AI 有足够数据支撑 |
| 中（≥50%） | 黄色标签"中等" | AI 有一定数据但缺少关键来源 |
| 低（<50%） | 灰色标签"参考" | AI 数据不足以形成确切结论 |
| 无法评估 | 不展示 | AI 未能完成分析 |

### 格式

```
✅ 分析可靠程度：高

✅ 置信度：高（←这是完整的说明）
```

### 不展示 confidence 的场景

- 用户没有主动请求 Explain
- 信息是确定性数据（如"Bamb Health：45"）
- 错误信息

### 禁止的展示方式

```
❌ Confidence：0.83（数字对用户不直观）

❌ 以百分比单独存在

❌ "高置信度" 漂浮在空白处（必须附在结论旁边）
```

## 6. Error Communication（错误沟通）

### 错误分类与呈现

| 错误类型 | 呈现方式 | 文案规范 |
|----------|----------|----------|
| 网络错误 | Toast | "无法连接到服务器，请检查网络。" |
| AI 超时 | Inline | "AI 分析超时。原因：请求耗时过长。建议：稍后重试。" |
| 数据不足 | Page | "暂时无法生成分析。原因：品牌数据不足以形成结论。建议：完善品牌信息后重试。" |
| 权限不足 | Page | "没有访问权限。请联系管理员开通。 " |
| 不可恢复 | Full Page | "系统异常。请联系技术支持。" |
| 部分成功 | Section | 展示成功部分 + 失败部分 + 可重试 |

### Error 文案规范

| 字段 | 要求 | 示例 |
|------|------|------|
| 标题 | 发生了什么 | "AI 分析超时" |
| 原因 | 为什么发生 | "官网无法访问" |
| 建议 | 用户可以做什么 | "检查网址是否正确，稍后重试" |
| CTA | 直接可操作按钮 | "重试" / "返回" |

## 7. Copy Dictionary（统一词汇表）

### 核心产品词汇

| 统一词汇 | 禁止使用的词汇 | 使用场景 |
|----------|---------------|----------|
| 品牌 | 项目、Workspace、Entity | 用户创建/管理的品牌 |
| 优化 | 修复、改进、Enhance、提升 | 用户执行的操作 |
| 任务 | Mission、Job、Task | AI 推荐的优化动作 |
| 建议 | 推荐、方案、Suggestion | AI 给出的分析结果 |
| 分析 | 扫描、检测、Discovery | AI 正在分析品牌 |
| 验证 | 校验、确认、Verify | 查看优化效果 |
| 发布 | 部署、Publish、上线 | 将品牌知识发布到渠道 |
| 变化 | 差异、Diff、变动 | Before/After 对比 |
| 问题 | Issue、异常、警告 | AI 发现的品牌短板 |
| 成长 | 增长、趋势、Growth | Track 品牌变化 |

### 按钮文案

| 统一 | 禁止 |
|------|------|
| 开始优化 | 开始执行、提交 |
| 查看原因 | 了解为什么、详情 |
| 验证效果 | 确认、提交验证 |
| 继续优化 | 下一步、继续 |
| 重新扫描 | 重新检测、刷新 |
| 查看成长趋势 | 查看 Growth |
| 发布结果 | 提交审核、上线 |
| 稍后重试 | 等等再试 |

### 数字/分数词汇

| 统一 | 禁止 |
|------|------|
| Brand Health（品牌健康度） | ADI、Score、ADI Score、Brand Score |
| 知识覆盖 | Knowledge Coverage |
| AI 可见性 | AI Visibility |
| 可信度 | Trust Score |
| 新鲜度 | Freshness |
| 权威性 | Authority |
| 风险 | Risk |

### 状态词汇

| 统一 | 禁止 |
|------|------|
| 进行中 | Processing、Running |
| 已完成 | Completed、Done |
| 失败 | Error、Failed、Error |
| 等待中 | Pending |
| 已取消 | Cancelled |

## 8. CTA Style（操作规范）

### CTA 模式

所有 CTA 必须：

1. **描述具体操作** — 不是"确认"是"保存品牌描述"
2. **告知预期效果** — 如果在 CTA 工具提示中预期
3. **一致性** — 用户在各个页面看到的"保存"行为一致

| 场景 | 推荐 CTA | 说明 |
|------|----------|------|
| 第一次操作 | 开始优化 | 非技术、承诺行动 |
| 保存数据 | 保存并验证 | 让用户知道保存后会做什么 |
| 查看分析 | 查看原因 | 比"了解详情"更自然 |
| 失败重试 | 重试 | 不增加"重新"前缀 |
| 多步操作 | 继续优化 | 保持旅程节奏 |

## 9. Empty Style（空状态规范）

### 通用的空状态结构

```
┌──────────────────────────────────┐
│  Icon（对应的状态图标）              │
│  Title（空状态的一句话说明）          │
│  Description（为什么为空 + 怎么做）   │
│  Action（下一步可操作按钮）            │
└──────────────────────────────────┘
```

### 各种空值示例

**Health（没有品牌时）：**
```
[Icon]
还没有品牌
创建品牌后可以查看品牌在 AI 眼中的健康状态
[创建品牌]
```

**Recommendation（没有扫描时）：**
```
[Icon]
还没有数据
品牌创建完成后系统会自动扫描并推荐优化方案
[开始扫描]
```

**Verification（没有优化记录时）：**
```
[Icon]
还没有优化记录
执行优化任务后才能看到对比效果
[去优化]
```

**Publishing（没有渠道时）：**
```
[Icon]
还没有连接渠道
将品牌信息发布到搜索引擎和社交平台后，可提升 AI 可见性
[连接渠道]
```

**Growth（没有历史数据时）：**
```
[Icon]
还没有成长记录
完成至少一次优化后才能看到品牌成长趋势
[开始优化]
```

### 禁止的空状态文案

```
❌ "暂无数据"

❌ "没有找到结果"

❌ 空白页面
```

## 10. Contract Enforcement

### 强制规则

1. 所有 AI 输出必须经过 Pattern 检查
2. 所有文案必须使用 Copy Dictionary
3. 所有 Explain 必须回答 4 个问题
4. 所有 Error 必须包含原因+建议
5. 所有 CTA 必须符合 CTA Style

### 实施方式

**代码检查：**
- 新增单元测试验证 AI 输出是否符合 Guideline
- 所有新文案必须通过 Review

**Pull Request 检查项：**
```
□ AI 输出符合 Output Structure
□ 文案来自 Copy Dictionary
□ Explain 回答了 Why / Why Now / Evidence / Impact
□ Error 包含原因 + 建议 + CTA
□ CTA 使用规范文案
□ 空状态使用 Empty Style
□ 置信度按照 Confidence 规则展示
```

### 例外情况

- **首次旅程引导** — 可以有更多提示性文字，但仍遵循 Persona
- **系统操作反馈** — 如"保存成功"等系统反馈，不需要 Explain

## 附录：Quick Reference

### 一句话检查

每次写 AI 输出前，问问：

```
用户进到这个页面，能回答这 6 个问题吗？
1. 当前状态是什么？（Summary）
2. 为什么是这个状态？（Finding）
3. 证据在哪里？（Evidence）
4. 对我的品牌有什么影响？（Impact）
5. 置信度如何？（Confidence）
6. 下一步应该做什么？（Recommendation）
```

### Persona 速查

```
✅ 分析师语气
✅ 客观可解释
✅ 建议而不是命令
✅ 有证据支撑
✅ 给出具体数字
❌ 拟人化
❌ 夸张情绪
❌ 技术术语
❌ 无证据结论
```
