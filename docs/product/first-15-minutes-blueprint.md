# First 15 Minutes Blueprint

> **GEO 产品新用户首次体验蓝图**
> 版本：v1.0
> 依据：Product Principles / Product Vocabulary / Product IA / Design System v1.0
> 审计基准：product-readiness-audit.md
> 冻结日期：2026-07-26

---

## 核心原则（本文件的约束）

1. **用户不需要理解任何内部架构** — Runtime / Engine / Planner / Trace / Pipeline 等概念对用户不可见
2. **每一步回答三个问题**：现在在做什么、做完了能得到什么、下一步去哪
3. **每个页面只有一个 Primary Goal**
4. **三秒原则**：进入任何页面，用户三秒内知道在哪、该做什么、做完得到什么
5. **旅程的比喻**：不是"操作一个系统"，而是"跟一个 AI 品牌分析师坐下来对话"

## 1. 用户画像（Persona）

### Persona A：品牌运营负责人

| 属性 | 描述 |
|------|------|
| 姓名 | 林薇（Lin Wei） |
| 职位 | 品牌运营负责人 / 市场总监 |
| 公司 | 中型消费品企业（50-500 人） |
| 技术背景 | 非技术。会使用 Excel、飞书、企业微信。从未写过代码。不知道 API、Runtime、Pipeline 是什么 |

| 核心痛点 | 怀疑品牌在 AI 推荐中"被忽视"或"被误读"——自己搜自己的品牌发现 AI 回答不准确 |

### Persona B：增长运营专员

| 属性 | 描述 |
|------|------|
| 姓名 | 陈明（Chen Ming） |
| 职位 | 增长运营 / 数字营销专员 |
| 公司 | 创业公司（10-50 人） |

> **为什么选择这两种人？** 因为 GEO 的产品原则（P5 — Simplicity Wins）规定"普通市场人员第一次使用，30 秒内完成第一次优化"。如果蓝图能满足非技术背景的运营负责人，技术背景用户只会体验更流畅。

## 2. 十五分钟旅程地图

> 这个旅程设计成一场与 **AI 品牌分析师** 的对话。分析师不说话，但每一帧画面都在回答用户的潜问题。

### Phase 1：第一次接触（0-3 分钟）

**比喻：走进分析师办公室，看到一张大屏幕**

#### 用户看到什么？

用户打开 GEO Workspace（通过邀请链接或 SSO 登录），看到的**第一画面**：

```
┌──────────────────────────────────────────────────────────┐
│                    ✨ 欢迎来到 GEO                         │
│                                                          │
│  让品牌被 AI 理解、被 AI 推荐                               │
│                                                          │
│  添加你的第一个品牌，看看品牌在 AI 眼中的样子                   │
│                                                          │
│  ┌──────────────────────────────────────────┐             │
│  │  品牌名称（如：云栖咖啡）                    │             │
│  │  官方网站（如：www.yunxi-coffee.com）       │             │
│  │                                            │             │
│  │  [ 开始检测 → ]                           │             │
│  └──────────────────────────────────────────┘             │
│                                                          │
│  已有品牌？ [ 登录查看 ]                                    │
└──────────────────────────────────────────────────────────┘
```

**关键决策：不展示空荡荡的 Dashboard，不展示侧边栏，不展示 6 个导航入口。**

为什么？因为 audit 发现当前导航有 7+ 入口，用户难以建立心智模型（Cognitive Load 评分 3/5）。新用户第一次不需要看到全貌，只需要做一件事：**添加品牌**。

#### 系统在做什么？

- 检测用户是否已登录（Token / SSO）
- 如果是已登录用户，检测是否有现有项目
- 如果无项目：显示欢迎页面（如上）
- 如果有项目：跳过欢迎页，直接进入 Health 页面（后文定义）

#### AI 在做什么？

- 尚未介入。用户还没告诉 AI 品牌是什么。

#### 用户的第一个行动是什么？

用户在两个输入框中填写品牌名称和官网 URL，然后点击"开始检测"。

#### 成功标准

用户在 **30 秒内** 理解：
1. 这个产品是做什么的 → "让品牌被 AI 理解"
2. 我需要做什么 → "输入品牌信息"
3. 做完能得到什么 → "看到品牌在 AI 眼中的样子"

**比喻：分析师开始研究你的品牌**

#### 用户创建品牌后的直观反馈是什么？

点击"开始检测"后，页面平滑过渡到**发现的实时状态**：

```

│                                                          │

│  │  🔍 AI 知识检索中...                               │     │
│  │     ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━░░░░  65%       │     │
│  │                                                    │     │
│  │  正在检查：                                          │     │
│  │  ✓ 品牌基本信息                                    │     │
│  │  ✓ 官网内容结构                                    │     │
│  │  ◎ AI 推荐结果中...                                │     │
│  │  ☐ 外部渠道覆盖                                    │     │
│  └──────────────────────────────────────────────────┘     │
│                                                          │
│  首次扫描约 1-2 分钟 · 之后每次检测只需几秒                   │
└──────────────────────────────────────────────────────────┘
```

**关键设计决策：**

1. **不展示"Discovery Lab"、"Discovery Task Gate"等工程命名** — 用户不需要知道内部叫 Discovery。用户只知道"AI 在扫描我的品牌"。
2. **进度条必须真实** — 不是假动画。如果后端无法分阶段推送，至少用 SSE 或轮询更新已完成的检查项。
3. **显示正在检查的项目** — 让用户理解"AI 在做什么"，但使用人类语言（"官网内容结构"而非"Repository Crawl"）。

#### 首次扫描完成后用户看到什么？

扫描完成，进入 GEO 的第一个核心页面——**Health 页面**：

```

│        📤 Publishing     📈 Growth     📚 Knowledge      │

│  │                                                    │     │
│  │         Brand Health                               │     │
│  │                                                     │     │
│  │               45                                    │     │
│  │                                                     │     │
│  │       ⬆ +0 (首次检测)                               │     │
│  │                                                     │     │
│  │  AI 对 "云栖咖啡" 的了解还不够全面                       │     │
│  │  建议优化品牌知识以提升 AI 可见性                        │     │
│  │                                                     │     │
│  │  [ 💡 查看推荐方案 ]                                 │     │
│  │                                                     │     │

│                                                          │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐     │
│  │ 知识覆盖 32   │ │ AI 可见性 28 │ │ 可信度 65    │     │
│  │ 品牌信息不完整  │ │ 未被推荐      │ │ 信息基本准确  │     │
│  └──────────────┘ └──────────────┘ └──────────────┘     │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐     │
│  │ 新鲜度 40     │ │ 权威性 55    │ │ 风险 85      │     │
│  │ 内容待更新    │ │ 来源待完善    │ │ 暂无明显风险  │     │
│  └──────────────┘ └──────────────┘ └──────────────┘     │
│                                                          │
│  [ 💡 查看推荐方案 ]                                     │
└──────────────────────────────────────────────────────────┘
```

**关键设计决策：**

1. **导航栏必须统一展示所有 6 个页面** — 但 Health 是唯一高亮的"你在这里"。这是 Brand OS Design System (DS-2) 规定的统一布局。
2. **Brand Health 45 是故意低调的** — 新用户第一次扫描，分数低是正常的。重点是传达"有提升空间"，而不是打击信心。分数用颜色编码（0-59 = 橙色/红色，60-79 = 黄色，80-100 = 绿色），但首次检测默认不显示红色警示（避免焦虑），而是"有待了解"的中性语气。
3. **6 个维度卡片展示** — 每个维度显示分数和一个简短描述（如"品牌信息不完整"），符合 Product Principle P10（Explain Every Score）。
4. **主 CTA 只有一个** → "查看推荐方案"。这是 Design System (DS-9) 规定的 Next Step Pattern。

为何 Brand Health = 45 而不更低？因为 AI 能理解基础品牌信息（官网存在），但缺乏结构化知识。如果后端确实返回更低分（如 20），UI 应展示"AI 对你的品牌还不太了解"，语气保持建设性而非负面。

### Phase 3：第一次优化（6-9 分钟）

**比喻：分析师说"这里有 3 件事可以做"**

#### 如何呈现第一个推荐？

用户点击"查看推荐方案"后（或在导航栏点击 Recommendations），进入 **Recommendations 页面**。

```
┌──────────────────────────────────────────────────────────┐
│  🏠 Health   💡 Recommendations   ✓ Verification         │
│        📤 Publishing     📈 Growth     📚 Knowledge      │
│                                                          │
│  为 "云栖咖啡" 推荐优化方案                                 │
│                                                          │
│  基于 AI 扫描结果，建议优化以下 3 项以提升 Brand Health：      │
│                                                          │
│  ┌────────────────────────────────────────────────────┐   │
│  │  🔴 优先级 1 · 预期提升 +15 分                      │   │
│  │                                                     │   │
│  │  添加品牌描述                                       │   │
│  │  AI 尚未找到完整的品牌介绍。                           │   │
│  │  添加一段清晰描述，告诉 AI "云栖咖啡是做什么的"。         │   │
│  │                                                     │   │
│  │  [ 开始优化 → ]   [ 了解为什么 ]                     │   │
│  └────────────────────────────────────────────────────┘   │
│                                                          │
│  ┌────────────────────────────────────────────────────┐   │
│  │  🟡 优先级 2 · 预期提升 +8 分                       │   │
│  │                                                     │   │
│  │  补充产品关键词                                     │   │
│  │  在官网中添加 "精品咖啡豆"、"手冲咖啡" 等关键词。       │   │
│  │                                                     │   │
│  │  [ 开始优化 → ]   [ 了解为什么 ]                     │   │
│  └────────────────────────────────────────────────────┘   │
│                                                          │
│  ┌────────────────────────────────────────────────────┐   │
│  │  🟢 优先级 3 · 预期提升 +5 分                       │   │
│  │                                                     │   │
│  │  提交品牌 Logo                                      │   │
│  │  AI 推荐结果中缺少品牌视觉信息。                       │   │
│  │                                                     │   │
│  │  [ 开始优化 → ]   [ 了解为什么 ]                     │   │
│  └────────────────────────────────────────────────────┘   │
│                                                          │
│  预计总提升：Brand Health 45 → **73**                    │
│                                                          │
│  [ 🚀 一键执行全部 3 项 ]                                 │
└──────────────────────────────────────────────────────────┘
```

**关键设计决策：**

1. **每个推荐卡是一个可执行的"Mission"** — 但是不需要用户知道 Mission 这个术语。用户看到的是"添加品牌描述"、"补充产品关键词"、"提交品牌 Logo"——都是人类可理解的操作。
2. **预期提升直观展示** — 每个推荐项有"预期提升 +N 分"，底部汇总"45 → 73"。这是 Outcome First（P3）原则的直接体现。
3. **优先级用颜色和数字双重编码** — 红/黄/绿 + "优先级 1/2/3"。用户不需要思考"先做哪个"。
4. **"了解为什么"按钮** — 点击展开 Explain 抽屉（GeoExplainDrawer 的简化版），展示 AI 为什么推荐这个。但默认不展开，保持列表简洁。这是 Progressive Disclosure（P7）原则。
5. **"一键执行全部 3 项"** — 这是 Trust Before Automation（P11）的关键平衡：AI 建议但用户决定。用户可以用一次点击确认全部，而非一个个确认。

#### 用户如何执行第一个推荐？

用户点击"添加品牌描述"的「开始优化 →」按钮，进入**简单的填写表单**：

```
┌──────────────────────────────────────────────────────────┐
│  ← 返回推荐列表                                           │
│                                                          │
│  添加品牌描述                                             │
│                                                          │
│  AI 建议在品牌介绍中包含以下内容：                            │
│  • 品牌定位（什么样的咖啡？）                               │
│  • 核心产品（卖什么？）                                    │
│  • 品牌调性（给人什么感觉？）                               │
│                                                          │
│  ┌────────────────────────────────────────────────────┐   │
│  │  品牌描述：                                          │   │
│  │  ┌──────────────────────────────────────────────┐   │   │
│  │  │ 云栖咖啡是一个专注云南精品咖啡豆的品牌。           │   │   │
│  │  │ 我们从云南普洱产区直采阿拉比卡咖啡豆，               │   │   │
│  │  │ 为咖啡爱好者提供新鲜烘焙的单品咖啡。                 │   │   │
│  │  └──────────────────────────────────────────────┘   │   │
│  │                                                     │   │
│  │  [ 保存并验证 → ]                                   │   │
│  └────────────────────────────────────────────────────┘   │
│                                                          │
│  不需要理解 AI 怎么处理，填完内容点击保存即可                  │
└──────────────────────────────────────────────────────────┘
```

**关键设计决策：**

1. **不渲染 Mission Center / Execution / Runtime 概念** — 用户只是"填写描述"，不需要知道这个描述会经过 Planner → Runtime → Execution 链。Audit 指出 MissionCard 绕过 service 层直接 fetch，这个问题在用户体验层面不需要暴露。
2. **AI 给出写作建议** — 空白处有 placeholder 提示，告诉用户"建议包含这些内容"。这是"Recommendation, Not Configuration"（P8）原则。
3. **操作后的反馈必须是即时且确定的** — 点击"保存并验证"时，按钮变为 loading 状态，文案变为"AI 正在验证..."，完成后直接显示结果。

当用户点击"了解为什么"时，弹出一个侧边面板（Explain Drawer）：

│                                                │

│  • 云栖咖啡是一家什么公司                           │

当前 Explain（GeoExplainCard）的 Confidence 范围假设可能不匹配后端格式，这是 P1 修复项。但在产品体验层面，Explain 的核心是回答"为什么这个推荐"和"做了会怎样"。

### Phase 4：第一次验证（9-12 分钟）

**比喻：分析师说"来看看效果"**

#### 用户如何验证优化效果？

用户填写品牌描述并点击"保存并验证"后，系统自动进入 **Verification 页面**（或展示验证结果 overlay）。

```
┌──────────────────────────────────────────────────────────┐
│  🏠 Health   💡 Recommendations   ✓ Verification         │
│        📤 Publishing     📈 Growth     📚 Knowledge      │
│                                                          │
│  验证结果：品牌描述已更新                                   │
│                                                          │
│  ┌──────────────────────────────────────────────────┐     │
│  │   Brand Health                                    │     │
│  │                                                    │     │
│  │     45  ─────────────────────────▶  60              │     │
│  │                ⬆ +15                                │     │
│  │                                                    │     │
│  │  优化前                       优化后                  │     │
│  │  品牌描述不完整                 品牌描述已完善          │     │
│  └──────────────────────────────────────────────────┘     │
│                                                          │
│  维度变化：                                                │
│  ┌──────────────┐ ┌──────────────┐                       │
│  │ 知识覆盖      │ │ AI 可见性    │                        │
│  │ 32 → 44 (+12) │ │ 28 → 31 (+3)│                        │
│  │ 品牌信息更完整  │ │ 被理解更准确  │                        │
│  └──────────────┘ └──────────────┘                       │
│                                                          │
│  建议下一步：                                              │
│  📌 优化较多，建议继续补充产品关键词（预期 +8）               │
│                                                          │
│  [ 返回推荐列表 ]  [ 查看成长趋势 ]                         │
└──────────────────────────────────────────────────────────┘
```

**关键设计决策：**

1. **Verification 不展示"技术验证"** — 不展示 Claim / Evidence / Verification Engine 等概念。用户看到的是"优化前 vs 优化后"的 Brand Health 变化。这是 Outcome First（P3）。
2. **Before/After 对比是视觉上最突出的** — 使用箭头变化图，45 → 60 的动画效果（DS-1.6 motion 规范，normal 200ms）。
3. **维度变化单独展示** — 只有受影响的维度显示变化。未变化的维度不展示，减少认知负担。
4. **建议下一步明确** — "继续补充产品关键词（预期 +8）"，并且按钮之一是"返回推荐列表"，用户知道还能继续优化其他项。
5. **解决 Audit 中的 P0 问题**：当前 VerificationPage 首次加载完全空白，无 Loading 骨架屏。本蓝图要求 Verification 页面**从不**展示空白——如果无验证结果，展示"尚未优化，去推荐列表开始"的引导状态。

#### Verification 如何工作？（用户视角）

用户不需要知道 Verification 在后台做了什么。用户只需要看到：

| 用户操作 | 用户看到 |
|---------|---------|
| 填写品牌描述 → 点击保存 | 按钮变成"AI 正在验证..." |
| 等待 2-5 秒 | 进度指示 + 当前状态（"AI 正在重新理解品牌..."） |
| 验证完成 | Before/After 对比 + 分数变化 + 下步建议 |

如果验证失败（例如网站打不开）：
```
AI 暂时无法验证品牌描述的效果
可能的原因：官网暂时无法访问
建议：稍后重试，或检查网站是否正常
[ 稍后重试 ]  [ 返回推荐列表 ]
```

## 3. 每个阶段的详细规格

### Phase 1：第一次接触（0-3 分钟）

| 字段 | 规格 |
|------|------|
| **User Goal** | 理解产品价值 + 添加第一个品牌 |
| **System Action** | 检测登录状态，检查是否有现有项目。无项目 → 展示欢迎页；有项目 → 跳转 Health |
| **AI Action** | 暂不介入 |
| **Success Feedback** | 用户填写品牌名称 + 官网，点击"开始检测"，页面顺利过渡到扫描状态 |
| **Next CTA** | "开始检测"（主按钮）+"登录查看"（次要） |
| **3-second Check** | ✅ "我在哪" → 欢迎页；"该做什么" → 输入品牌信息；"能得到什么" → 看到品牌在 AI 眼中的样子 |
| **Empty State** | 无。这是首屏，不允许出现空白 |

### Phase 2：第一次发现（3-6 分钟）

| 字段 | 规格 |
|------|------|
| **User Goal** | 等待 AI 完成品牌扫描，看到品牌健康状态 |
| **System Action** | 创建项目 → 触发 Discovery 扫描（调用 AI 引擎）→ 轮询或 SSE 更新进度 → 完成后聚合数据 → 渲染 Health 页面 |
| **AI Action** | 扫描品牌官网、AI 搜索结果、社交媒体。产出：Brand Health 总分 + 6 维度评分 + 诊断描述 |
| **Success Feedback** | 扫描进度 0% → 100%，最终展示 Health 页面，显示 Brand Health 45（或实际值） |
| **Next CTA** | "查看推荐方案"（主） |
| **3-second Check** | ✅ "我在哪" → 品牌健康首页；"该做什么" → 查看品牌状态；"能得到什么" → 了解品牌在 AI 眼中的健康度 |
| **Empty State** | 扫描完成但无数据 → 显示"AI 暂时无法全面了解你的品牌"，给出重试或手动填写建议 |

### Phase 3：第一次优化（6-9 分钟）

| 字段 | 规格 |
|------|------|
| **User Goal** | 选择并执行第一个品牌优化动作 |
| **System Action** | 加载推荐列表（优先级排序）→ 用户点击"开始优化" → 展示填写表单 → 用户提交 → 后端触发 Mission 执行 → 实时返回进度 |
| **AI Action** | 生成推荐项（每项含：行动描述、为什么推荐、预期提升、影响维度）→ 用户提交后 AI 执行优化验证 |
| **Success Feedback** | 表单提交成功 + "AI 正在验证"过渡 → 自动进入 Verification（Phase 4） |
| **Next CTA** | "开始优化"（列表页）→ "保存并验证"（表单页） |
| **3-second Check** | ✅ "我在哪" → 推荐列表 / 优化表单；"该做什么" → 执行优化；"能得到什么" → Brand Health 提升 |
| **Empty State** | 推荐列表为空 → 显示"AI 正在分析，请稍后查看"，而不是空白列表。永不展示空推荐。 |

### Phase 4：第一次验证（9-12 分钟）

| 字段 | 规格 |
|------|------|
| **User Goal** | 确认优化效果，看到 Brand Health 的变化 |
| **System Action** | 执行 Verification 引擎 → 对比优化前后 → 计算维度变化 → 渲染 Before/After 对比 |
| **AI Action** | 重新评估品牌知识覆盖 → 生成变化报告（哪些维度提升了多少）→ 给出置信度 |
| **Success Feedback** | Before/After 可视对比 + "Brand Health +15" + 维度变化明细 |
| **Next CTA** | "返回推荐列表"（继续优化）+ "查看成长趋势"（进入 Growth） |
| **3-second Check** | ✅ "我在哪" → 验证结果页；"该做什么" → 查看效果；"能得到什么" → 看到优化带来的 Brand Health 提升 |
| **Empty State** | 验证失败 → 显示失败原因 + 重试选项。验证无结果 → "AI 还在分析中"（仅限过渡状态，不应超过 10 秒） |

### Phase 5：第一次闭环（12-15 分钟）

| 字段 | 规格 |
|------|------|
| **User Goal** | 看到完整价值、知道接下来该做什么 |
| **System Action** | 聚合所有历史优化 → 计算 Brand Health 累计变化 → 渲染更新后的 Health 页面 + Growth 趋势 |
| **AI Action** | 生成品牌成长轨迹 → 预测未来趋势（如果继续优化）→ 生成下一步推荐 |
| **Success Feedback** | Health 页面的 Brand Health 已更新（45 → 60），Growth 页面显示了时间线 + 趋势图 |
| **Next CTA** | "继续优化"（回到 Recommendations）→ "发布品牌知识"（进入 Publishing）→ 入口始终可见 |
| **3-second Check** | ✅ "我在哪" → 品牌健康首页 / 成长趋势；"该做什么" → 继续优化或发布；"能得到什么" → 品牌持续成长 |
| **Empty State** | 无历史优化 → 显示"还没有优化记录，开始你的第一次优化"。但 15 分钟旅程结束时不应出现此状态 |

## 4. 断裂点分析

### 4.1 从代码 Audit 中提取的断裂点

以下断裂点直接从 product-readiness-audit.md 的"用户旅程断裂点"相关部分提取：

| 编号 | 断裂点 | 描述 | 影响 | 改造建议 |
|------|--------|------|------|----------|
| **G1** | VerificationPage 首次加载完全空白 | Audit P0 #2。无 Loading 骨架屏，用户看到白屏 | 用户在 Phase 4 看到白屏，会认为系统卡顿或出错，直接跳出旅程 | 增加 Skeleton 骨架屏；如果无验证历史，显示引导状态"你还没有优化记录，去 Recommendations 开始" |
| **G2** | GrowthPage 伪图表 | Audit P0 #5。使用 CSS div 模拟图表，无法交互 | Phase 5 展示成长趋势时，用户看到的是一条 CSS 线，无法悬停、缩放，破坏信任感 | 替换为 ECharts 或 Chart.js 的真实图表组件。Brand OS Design System 中已有 TrendChart 组件的定义 |
| **G3** | HealthPage ADI/Health 概念混用 | Audit P0 #3。页面标题与内容不一致 | Phase 2 用户看到 Health 页面时，不确定"ADI"和"Health"是什么关系，破坏三秒原则 | 统一为"Brand Health"和 6 个标准维度（Knowledge Coverage / AI Visibility / Trust / Freshness / Authority / Risk） |
| **G4** | GEOCreate 无初始化 Loading | Audit P1 #9。仅按钮 spinner 兜底 | Phase 1 用户点击"开始检测"后，如果品牌创建请求慢，用户看不到反馈 | 增加页面级 Loading 过渡（Skeleton 或扫描动画），而非仅在按钮上显示 spinner |
| **G5** | MissionCenterShell 首次加载闪烁 | Audit P1 #13。自动选择首个品牌 + 异步加载导致 UI 闪烁 | Phase 3 用户在推荐列表中看到闪烁，破坏"三秒"内的确定感 | 在推荐列表数据完全就绪前，始终显示 Skeleton 列表（3 个灰条卡片）而非零数据→闪烁→渲染 |
| **G6** | KnowledgePage 声明点击是 stub | Audit P0 #1。`handleStatementClick` 仅 `console.warn` | 如果用户在 15 分钟内进入 Knowledge 页面，点击任何条目无反应，严重破坏信任 | 实现声明编辑 modal 或至少显示确认对话框。此修复不影响核心旅程（用户前 15 分钟可能不到 Knowledge 页面），但仍需修复 |
| **G7** | Dashboard 无 API fallback | Audit P0 #7。聚合 API 单点故障导致整个页面不可用 | Phase 5 Health 页面或 Dashboard 加载失败时，用户什么也看不到 | 实现分块加载 + 容错：Brand Health 分数、各维度卡片、趋势图分别加载，任一失败不影响其他区块 |
| **G8** | PublishingPage retryRecord 为 stub | Audit P1 #20。重试功能 stub | Phase 5 用户发布失败后，"重试"按钮不可用，流程中断 | 实现完整的重试逻辑：显示发布失败原因 → 提供"重试"按钮 → 重试时显示进度 |
| **G9** | useWorkflowStore goNext 失败无 UI 反馈 | Audit P1 #15。工作流下一步失败时无反馈 | 用户在各个页面间流转时，如果状态切换失败，用户不知道发生了什么 | 所有页面切换操作增加 Toast 反馈。成功后轻提示，失败时明确显示原因（"无法切换到 Verification，请重试"） |

### 4.2 从 First 15 Minutes 视角推断的潜在断裂点

以下断裂点是从本 Blueprint 的"15 分钟旅程"视角推断的，代码 Audit 未直接涉及：

| 编号 | 断裂点 | 描述 | 影响 | 改造建议 |
|------|--------|------|------|----------|
| **U1** | 无 15 分钟旅程路径 | 当前导航是 7+ 入口并列，用户不知道该按什么顺序操作 | 新用户进入后迷失——从 Health 跳到 Knowledge 又跳到 Publishing，从未完成一个闭环 | 首次用户引导（Walkthrough）增加"旅程模式"：页面底部显示 5 步进度条，当前在第几步，下一步去哪。这不是永久导航，仅在首次 3 次登录内可见 |
| **U2** | 扫描期间无有意义的信息 | 当前扫描是"技术化"状态显示，用户不知道 AI 具体在做什么 | Phase 2 用户在等待期失去耐心，以为卡住了 | 扫描状态用人类语言分阶段展示（
