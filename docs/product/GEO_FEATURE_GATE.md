# GEO 功能门禁（Feature Gate）

**依据**：《昆仑镜 GEO 产品白皮书 v1.0》第八章（工程开发原则）
**生效**：2026-07-21
**定义**：任何 GEO 开发进入 Sprint 前的强制审查项，六项门禁全部通过方可开始开发。

---

## 六项门禁

### Gate 1：对应白皮书章节

任务必须明确对应白皮书哪个章节。

> 示例：❌ "优化建议排序功能"
> 示例：✅ "第四章第四阶段（Optimize）— 优化建议排序"

**不通过条件**：无法找到对应的白皮书章节，或对应章节不包含该功能。

---

### Gate 2：用户价值

任务必须明确"用户为什么要使用这个功能"。

> 示例：❌ "后端增加排序 API"
> 示例：✅ "用户能优先看到最重要的优化建议，提高决策效率"

**不通过条件**：用户价值无法用一句话清晰描述，或描述中使用技术术语。

---

### Gate 3：UI 入口

任务必须明确"用户在哪个页面操作这个功能"。

> 示例：❌ "无，后端逻辑"
> 示例：✅ "Insights Tab — 优化建议列表 — 排序切换按钮"

**不通过条件**：用户找不到操作此功能的位置，或入口不符合现有工作台布局。

---

### Gate 4：API 端点

任务必须明确"后端 API 是什么"。

> 示例：❌ "后端自行实现"
> 示例：✅ "`GET /api/geo/learning/signals?projectId=&sortBy=priority`（新增参数）"

**不通过条件**：后端 API 不存在且无设计方案，或 API 设计暴露内部表结构。

---

### Gate 5：验证方式

任务必须明确"如何验证功能正常"。

> 示例：❌ "代码跑通"
> 示例：✅ "用户选择项目→切换到 Insights Tab→看到建议按优先级降序显示→浏览器无报错"

**不通过条件**：验证方式不是面向用户的可视化验证。

---

### Gate 6：验收标准

任务必须明确"什么样算完成"。

> 示例：❌ "功能开发完成"
> 示例：✅ "建议列表按权重降序排列，权重高于 0.5 的建议置顶"

**不通过条件**：验收标准无法客观判断是否完成。

---

## 门禁卡模板

任何 GEO 开发任务在进入 Sprint 前，必须填写以下门禁卡：

```markdown
## Feature Gate 审查

### Gate 1：白皮书章节
[填写对应章节]

### Gate 2：用户价值
[一句话描述]

### Gate 3：UI 入口
[具体页面和操作位置]

### Gate 4：API 端点
[端点路径和方法]

### Gate 5：验证方式
[用户可操作的验证步骤]

### Gate 6：验收标准
[可客观判断的完成条件]
```

---

## 门禁执行流程

```
新任务提出
     │
     ▼
填写 Feature Gate 卡
     │
     ▼
六项门禁检查
     │
     ▼
全通过 ──→ 进入 Sprint Backlog
     │
     有未通过
     │
     ▼
补充/修改 → 重新审查
     │
     ▼
第三次不通过 → 任务暂缓，由产品负责人裁决
```

---

## 门禁例外

以下情况可免除门禁审查：

1. **Bug 修复**：仅限修复已有功能的异常行为，不得涉及新增能力。
2. **安全修复**：安全漏洞修补。
3. **性能优化**：不影响用户感知的后端优化（需说明"对用户无感知"）。

以上例外仍需记录在 Backlog 中。

---

*本门禁生效后，任何未通过六项审查的 GEO 开发任务不得实施。*
