# GEO Global Product Pattern Language

> **定义 GEO 所有页面的统一产品模式 —— 回答"页面应该长什么样"**
>
> 版本：v1.0
> 依据：First 15 Minutes Blueprint v1.0 · Navigation Architecture v1.0 · Interaction Architecture v1.0 · Product Readiness Audit
> 冻结日期：2026-07-26

---

## 本文件的目的

这不是 UI Kit。本文件不定义颜色（绿色 #10B981 还是 #22C55E）、字体（Inter 14px 还是 16px）、间距（16px 还是 24px）。那属于 Design System。

本文件定义的是**产品模式**——回答：

- **什么时候用这个模式？** — 什么场景触发
- **为什么用？** — 解决什么用户问题
- **怎么用？** — 结构和行为规则
- **什么情况下不用？** — 边界条件

**以后新页面默认遵守这些模式，不需要重新讨论。**

## 1. Product Philosophy（产品哲学）

所有 Pattern 都基于以下八个设计哲学。如果一个 Pattern 与任一哲学冲突，重新思考 Pattern 而不是妥协哲学。

### P1: 用户不需要理解系统架构

用户不关心 Runtime、Engine、Pipeline、Planner、Trace。用户只关心"我的品牌在 AI 眼中怎么样"和"接下来该做什么"。

**在产品中意味着：**
- 所有技术命名对用户不可见
- 所有内部概念（Discovery Engine、Mission Engine、Verification Engine）降级为二级描述或完全隐藏
- 如果用户需要理解一个概念才能使用产品，那就是产品设计失败

**审计证据：** Navigation Architecture 中 7+ 引擎命名入口导致 Cognitive Load 评分 3/5。15 分钟蓝图明确定义了"用户不需要理解任何内部架构"。

### P2: 每个页面只有一个 Primary Goal

一个页面只回答一个问题。如果页面需要回答两个问题，拆成两个页面或两个 Tab。

**在产品中意味着：**
- Health 页面只回答"品牌现在怎么样"——不在这里做优化操作
- Recommendations 页面只回答"AI 建议做什么"——不在这里看趋势
- Verification 页面只回答"优化有没有效果"——不在这里发布

**例外：** Dashboard/Growth 聚合页是唯一允许展示多维度信息的页面，但其 Primary Goal 始终是"品牌成长了吗"——每个区块的数据都在回答这个问题的一个侧面。

### P3: Outcome First

先展示结果，再展示操作。用户不需要理解系统工作方式，只需要看到结果并决定是否行动。

**在产品中意味着：**
- AI 操作完成后，第一屏展示结果（Summary），不是展示操作按钮
- 每个操作按钮旁边标明预期结果（"+15 分"）
- 用户做决策时，基于结果做决策，而不是基于操作描述

**具象化：**
```
❌  [ 优化品牌描述 ]  → 用户不知道做了有什么效果
✅  优化品牌描述 · 预期 +15 分  → 用户知道做了能得到什么
```

### P4: Progressive Disclosure

默认简单，需要时深入。用户在当前层次获取足够信息前，不展示下一层。

**在产品中意味着：**
- 默认展示 L0（一句话总结）和 L1（卡片摘要）
- 用户主动点击后展示 L2（Drawer 详情）
- 极端场景下进入 L3（完整页面）
- 永远不默认展示 L4（原始数据）

### P5: Recommendation, Not Configuration

AI 建议但用户决定。AI 扮演分析师角色，不是管理员角色。

**在产品中意味着：**
- AI 给出推荐方案和预期提升，但由用户点击执行
- "一键执行全部"是推荐包，用户有权在确认前检查每一项
- 每个推荐项旁边有"了解为什么"——AI 解释自己的推理过程
- 核心体验是"跟 AI 品牌分析师对话"，不是"操作一个配置系统"

### P6: Explain Every Score

每个分数、每个变化都附带"为什么"。用户永远不需要猜测数字的含义。

**在产品中意味着：**
- Brand Health 分数旁边始终有简短解释（"AI 对你的品牌还不够了解"）
- 分数变化旁边有原因（"+15 — 因为添加了品牌描述"）
- 维度得分旁边有典型行为引导（"建议补充官网信息"）
- 置信度展示在需要时（"AI 对此分析的确定度高"）

### P7: Trust Before Automation

用户先验证 AI 的正确性，再接受自动化操作。

**在产品中意味着：**
- 首次执行任何 AI 操作前，用户看到 Explain
- Explain Drawer 展示证据来源，让用户决策
- 用户完成至少一次手动操作并验证效果后，才展示"一键执行全部"
- 自动化操作前总是有确认步骤（即使用户可以勾选"不再询问"）

### P8: Continuous Growth

用户每次回来都有新建议。产品随着使用变好，不随着使用变旧。

**在产品中意味着：**
- 每次登录检查品牌是否有新的优化机会
- 趋势图展示"过去 vs 现在 vs 未来（预测）"
- 旧建议完成后生成新建议
- 品牌的外部状态变化自动触发重新分析
- Growth 页面不是静态仪表板，而是"品牌正在变好"的叙事弧线

## 2. Layout Pattern（布局模式）

### 2.1 统一布局模板

所有面向用户的页面（不包含登录、注册等前置页面）遵循以下模板：

```
┌──────────────────────────────────────────────────────────────────┐
│  Header: [品牌 Logo/名称]        [旅程进度] [通知] [用户设置]     │
├────────────┬─────────────────────────────────────────────────────┤
│            │  Page Header: 页面目标 + 一句话说明                   │
│  Sidebar   │  ─────────────────────────────────────────────────  │
│  (导航)    │  Summary: 关键数据/状态摘要                          │
│            │  ─────────────────────────────────────────────────  │
│            │  Primary Content: 页面核心功能区                     │
│            │                                                    │
│            │  ┌─────────────────────────────────────────────┐    │
│            │  │  AI Explain (下方嵌入面板或右侧 Drawer)       │    │
│            │  └─────────────────────────────────────────────┘    │
│            │  ─────────────────────────────────────────────────  │
│            │  Next Action: 下一步推荐                            │
└────────────┴─────────────────────────────────────────────────────┘
```

### 2.2 各区域详细规范

#### Header

| 属性 | 值 |
|------|-----|
| **职责** | 品牌标识 + 全局入口（通知、设置） + 首次旅程进度提示 |
| **展示条件** | 始终可见。无品牌时仍显示（不显示品牌名） |
| **隐藏条件** | 永不可隐藏（浏览器视口宽度 < 320px 时压缩图标） |
| **内容** | 左侧：品牌 Logo/名称。右侧：通知图标(🔔)、设置(⚙)、用户头像 |
| **高度** | 固定（不应超过 56px） |
| **首次旅程特殊行为** | 底部显示旅程进度条 Banner（5 步进度），可手动关闭 |

#### Sidebar

| 属性 | 值 |
|------|-----|
| **职责** | 导航入口 + 品牌选择器。回答"我去哪里" |
| **展示条件** | 始终可见（桌面端）。有品牌时品牌选择器可用 |
| **隐藏条件** | 视口 < 768px 时折叠为汉堡菜单。创建品牌页面的欢迎页无 Sidebar |
| **宽度** | 固定（200-240px），折叠后 0 |
| **内容** | 品牌选择器（顶部）→ 5 个一级导航入口 → 帮助/反馈（底部） |

#### Page Header

| 属性 | 值 |
|------|-----|
| **职责** | 回答"我在哪里"和"这个页面做什么"。唯一 One-Liner 描述 |
| **展示条件** | 所有页面 |
| **内容** | Breadcrumb（可选）+ 页面标题（Brand Health） + 一句话说明（"查看品牌在 AI 眼中的健康度"） |
| **字数限制** | 标题 ≤ 8 字，说明 ≤ 25 字 |

#### Summary

| 属性 | 值 |
|------|-----|
| **职责** | 回答"现在怎么样了"。页面的最高优先级信息 |
| **展示条件** | 始终可见。无数据时展示对应 Empty State |
| **内容** | 依赖于页面类型（见表 2.3） |
| **高度** | 可变（内容自适应，超过 200px 不应出现） |

#### Primary Content

| 属性 | 值 |
|------|-----|
| **职责** | 承载页面核心功能。用户为了这个东西来到这个页面 |
| **展示条件** | 始终可见。无数据时展示对应 Empty State |
| **内容** | 依赖于页面类型（列表/卡片/表格/表单） |
| **滚动** | 内容可垂直滚动。避免水平滚动 |

#### AI Explain

| 属性 | 值 |
|------|-----|
| **职责** | 为当前页面内容提供 AI 解释。回答"为什么是这个结果" |
| **展示条件** | 有 AI 生成内容时展示 |
| **表现形式** | L1：Inline（嵌入在内容旁）。L2：Drawer（右侧滑出） |
| **位置** | 默认在 Primary Content 下方嵌入。用户点击"了解为什么"后打开 Drawer |

#### Next Action

| 属性 | 值 |
|------|-----|
| **职责** | 回答"接下来该做什么"。推荐下一步操作 |
| **展示条件** | 页面非 loading 态且有数据时展示 |
| **表现形式** | 底部卡片 + 主 CTA"去执行" + 次级"稍后再说" |
| **隐藏条件** | 无品牌、loading、ai_working 状态时隐藏 |

### 2.3 页面类型 → 各区域内容映射

| 页面 | Page Header | Summary | Primary Content | Explain | Next Action |
|------|------------|---------|-----------------|---------|-------------|
| **Health** | 品牌健康 · "查看品牌在 AI 眼中的样子" | Brand Health 总分 + 一句话描述 | 6 维度卡片网格 | Explain Link 在分数右侧 | "查看推荐方案" |
| **Recommendations** | 推荐方案 · "AI 建议优化以下内容" | 可优化项总数 + 预计总提升 | 优先级排序的推荐 Card 列表 | Explain Drawer 每个 Card"了解为什么" | "一键执行全部" 或 "验证效果" |
| **Verification** | 验证结果 · "查看优化效果" | Before/After 对比 + 变化值 | 维度变化明细 + 时间线 | Explain Drawer "了解为什么变化" | "继续优化" 或 "查看成长趋势" |
| **Publishing** | 发布管理 · "让品牌知识触达更多渠道" | 渠道状态摘要 | 渠道列表 + 发布按钮 | Explain Drawer "了解发布机制" | "发布到所有就绪渠道" |
| **Knowledge** | 品牌知识 · "AI 知道的品牌信息" | 知识覆盖率 | 声明列表（Card 或表格） | Explain Drawer "AI 如何理解这些信息" | "编辑知识" |
| **Dashboard** | 数据总览 · "品牌全景" | 关键指标卡片行 | 图表 + 列表混排 | Explain Link 在趋势旁 | "查看健康" |
| **Growth** | 成长趋势 · "品牌随时间的变化" | 累计变化 + 趋势方向 | 趋势图 + 里程碑列表 | Explain Drawer "为什么上升/下降" | "继续优化" |

### 2.4 区域间关系

| 关系 | 规则 |
|------|------|
| Summary 变化 → Primary Content 更新 | Summary 显示状态摘要，Primary Content 是详细内容。如 Health Summary 显示总分 45，Primary Content 展示各维度明细。总分变化时（如 45→60），Primary Content 自动重新计算各维度数据 |
| AI Explain → Action | Explain 展示后，Action 区域自动推荐基于解释的操作。"了解为什么后可以去做什么" |
| Next Action → Primary Content | Next Action 的推荐基于 Primary Content 的状态。Primary Content 变化后，Next Action 重新计算 |
| Page Header → Summary | Page Header 一句话说明是 Summary 的上下文。用户读了"查看品牌在 AI 眼中的样子"后再看分数 |

### 2.5 布局异常处理

| 场景 | 处理方式 |
|------|---------|
| 视口宽度 768-1024px (Tablet) | Sidebar 折叠为汉堡菜单。Primary Content 从 2/3 列变为 1 列 |
| 视口宽度 320-767px (Mobile) | Sidebar 隐藏。Header 压缩。Summary 变为横向可滚动。卡片 1 列。Next Action 固定在底部 |
| < 320px | 不提供支持（最小支持宽度 320px） |
| 内容超长 | Primary Content 可滚动。Summary 和 Next Action 永远固定在视口内（sticky） |

## 3. Information Hierarchy（信息层级）

### 3.1 优先级顺序

每个页面上信息的展示优先级（自上而下、由主到次）：

```
1. 状态信号        → 成功/失败/进行中
2. 关键指标        → 分数/变化/进度
3. 主体内容        → 列表/卡片/表格
4. AI 解释         → 为什么是这个结果
5. 操作入口        → 下一步可以做什么
6. 辅助信息        → 详情/历史/设置
```

### 3.2 层级详细说明

#### 层级 1：状态信号

| 属性 | 值 |
|------|-----|
| **什么样的内容** | 操作结果（成功/失败/部分成功/进行中/超时/取消）、页面状态（已加载/Empty/Error） |
| **视觉关系** | 页面最顶部、最突出的视觉元素。颜色编码：成功=绿、失败=红、进行中=蓝、部分=黄 |
| **规则** | 用户进入页面的前 200ms 必须看到状态信号。无状态信号意味着页面未准备好（需 Loading 态） |
| **例子** | ✓ 优化成功，Brand Health +15 分。✗ 验证失败，官网无法访问 |

#### 层级 2：关键指标

| 属性 | 值 |
|------|-----|
| **什么样的内容** | 总分、变化值（Before/After）、进度百分比、时间戳 |
| **视觉关系** | 紧接状态信号之后。字号大于等于主体内容。数字型指标使用特殊样式（加粗、大字号） |
| **规则** | 关键指标必须附带层级 4（基础 Explain）。如"45"旁边必须有"AI 对你的品牌还不够了解" |
| **例子** | Brand Health 45、\+15 分、3/5 渠道就绪 |

#### 层级 3：主体内容

| 属性 | 值 |
|------|-----|
| **什么样的内容** | 推荐卡片列表、维度卡片网格、渠道列表、验证对比图、趋势图、声明表格 |
| **视觉关系** | 页面中间区域，占据最大空间。容器样式统一（白色背景卡片或轮廓容器） |
| **规则** | 主体内容中的每个可交互元素必须提供层级 4 入口（Explain Link） |
| **例子** | 6 个维度卡片、3 个推荐 Card |

#### 层级 4：AI 解释

| 属性 | 值 |
|------|-----|
| **什么样的内容** | 为什么是这个结果、数据来源、置信度 |
| **视觉关系** | 嵌入在内容旁（L1 Inline）或侧边 Drawer（L2）。L1 使用较小字号（0.875em）、不同颜色（灰色）。L2 使用标准字号 |
| **规则** | 每一个 AI 输出的数字或结论必须附带层级 4。层级 4 默认部分隐藏（需要用户点击展开） |
| **例子** | "+15 — 因为添加了品牌描述"（Inline）、Explain Drawer 展示完整推理链 |

#### 层级 5：操作入口

| 属性 | 值 |
|------|-----|
| **什么样的内容** | Primary CTA、Secondary CTA、批量操作、Next Action |
| **视觉关系** | 页面底部或内容区底部。Primary CTA 使用高对比度按钮，Secondary 使用边框按钮 |
| **规则** | 页面上鼓励用户执行的唯一操作是 Primary CTA。多个操作时使用 Action Pattern 优先级规则 |
| **例子** | [开始优化] [查看推荐方案] [发布到所有就绪渠道] |

#### 层级 6：辅助信息

| 属性 | 值 |
|------|-----|
| **什么样的内容** | 历史记录、设置入口、详情链接、帮助入口 |
| **视觉关系** | 页面最底部或最不显眼的位置。使用文字链接或小图标 |
| **规则** | 不应干扰前 5 个层级的展示。仅在用户主动寻找时可见 |
| **例子** | "查看历史优化记录"、"管理品牌设置"、"帮助文档" |

### 3.3 层级间的视觉关系

| 层级对 | 视觉距离 | 关系说明 |
|--------|---------|---------|
| 1 ↔ 2 | 相邻（5-8px） | 状态信号和关键指标是"发生了什么"的完整回答 |
| 2 ↔ 3 | 相邻（8-12px） | 关键指标是主体内容的导引 |
| 3 ↔ 4 | 嵌入 | 层级 4 嵌入在层级 3 中（每项内容旁都有 Explain） |
| 3 ↔ 5 | 分离（24-32px） | 操作入口独立于内容区，避免被误认为内容的一部分 |
| 5 ↔ 6 | 分离（24-32px） | 辅助信息在最底部 |

### 3.4 极端情况

| 场景 | 处理 |
|------|------|
| 大量关键指标 | 最多展示 5 个指标，其余折叠到"查看更多"。6 维度指标使用 2×3 网格 |
| 无主体内容 | 展示 Empty State Pattern，层级 3 被 Empty State 替代 |
| 过多的操作入口 | 仅保留 1 个 Primary + 1-2 个 Secondary，其余移到"更多操作"菜单 |
| 屏幕空间有限 | 优先级 6 可完全隐藏（汉堡菜单或设置入口）。优先级 1-3 始终可见 |

## 4. Card Pattern（卡片模式）

### 4.1 统一 Card 结构

所有 GEO 卡片共享以下结构：

```
┌──────────────────────────────────────────────┐
│  Priority Badge (优先级/状态/类别)             │
│  Title (卡片标题 · 最大 30 字)                 │
│  Summary (一句话摘要 · 最大 60 字)              │
│  Metrics (相关数字指标, 如 +15 分 / 45→60)     │
│  Explain Link ("了解为什么")                   │
│  Action Button (主要操作 / 查看详情)            │
└──────────────────────────────────────────────┘
```

**结构规则：**

| 元素 | 是否必须 | 展示条件 |
|------|---------|---------|
| Priority Badge | 是 | 始终展示。无优先级时展示类别（如"推荐"、"已完成"） |
| Title | 是 | 始终展示 |
| Summary | 是 | 始终展示。描述内容 |
| Metrics | 否 | 有数字性指标时展示。如预期提升、分数变化 |
| Explain Link | 否 | 内容由 AI 生成时展示。内容为用户输入时不展示 |
| Action Button | 是 | 始终展示。无操作时展示"查看详情" |

### 4.2 Card 类型

#### HealthCard

| 属性 | 值 |
|------|-----|
| **使用场景** | Health 页面的维度卡片（知识覆盖、AI 可见性、可信度等） |
| **结构变体** | Priority Badge → 维度名称，Metrics → 分数（0-100 圆形进度），Summary → 状态描述，Action → "查看详情" |
| **例子** | 知识覆盖 · 32 · 品牌信息不完整 · [查看详情] |
| **展示方式** | 2×3 网格（桌面）、1 列（移动） |

#### RecommendationCard

| 属性 | 值 |
|------|-----|
| **使用场景** | Recommendations 页面的推荐项卡片 |
| **结构变体** | Priority Badge → 优先级颜色（红/黄/绿）+ 数字，Metrics → 预期提升（+N 分），Summary → 操作说明，Explain Link → "了解为什么"，Action → "开始优化" |
| **变体** | PriorityBadge 为红色时，卡片左边框红色强调 |
| **例子** | 优先级 1 · 添加品牌描述 · +15 分 · [了解为什么] [开始优化] |

#### MissionCard（执行卡）

| 属性 | 值 |
|------|-----|
| **使用场景** | 点击"开始优化"后的表单/确认卡 |
| **结构变体** | Priority Badge → 状态（进行中/已完成），Title → 任务名称，Summary → 表单或填写提示，Action → "保存并验证" |
| **状态** | idle（可编辑）/ loading（按钮禁用 + spinner）/ success（绿色边框 + ✓）/ failure（红色边框 + ✗ + 重试） |
| **与现有组件映射** | `kmki-ui/ActionCard/index.vue` — 需改造以对齐本结构 |

#### VerificationCard

| 属性 | 值 |
|------|-----|
| **使用场景** | Verification 页面的验证结果卡片（每项优化一条） |
| **结构变体** | Priority Badge → 优化项名称，Metrics → Before→After 变化（如 32→44），Summary → 描述，Explain Link → "了解为什么变化"，Action → "查看详情" |
| **状态** | success（绿色）/ failure（红色 + 重试按钮）/ loading（Skeleton） |

#### PublishingCard

| 属性 | 值 |
|------|-----|
| **使用场景** | Publishing 页面的渠道发布卡片 |
| **结构变体** | Priority Badge → 渠道类别（官网/AI 搜索/社交媒体），Metrics → 状态（已同步/就绪/需手动更新），Action → "发布"或"查看" |
| **状态** | ready（可发布）/ synced（已同步绿色标记）/ pending（待确认）/ error（红色 + 原因） |

#### KnowledgeCard（声明卡）

| 属性 | 值 |
|------|-----|
| **使用场景** | Knowledge 页面的品牌声明项 |
| **结构变体** | Priority Badge → 类别标签（名称/描述/联系方式），Title → 声明名称，Summary → 声明内容预览，Action → "编辑" |
| **状态** | verified（已验证）/ pending（待验证）/ outdated（已过时） |

### 4.3 Card 交互状态

| 状态 | 视觉表现 | 限制 |
|------|---------|------|
| **default** | 白色背景，浅灰边框，标准阴影（0 1px 3px） | — |
| **hover** | 阴影加深（0 4px 12px），边框变亮色（轻微蓝色 15% 透明），光标变 pointer | 仅可交互卡片支持 |
| **active/pressed** | 阴影略微缩小，背景变浅蓝（5% 透明），无边框变化 | 仅按钮区域 |
| **loading** | 内容区显示 Skeleton 动画（脉冲 keyframe），按钮禁用 + spinner | 所有操作禁用 |
| **success** | 绿色左边框（3px），绿色 ✓ 标记在右上角，轻微弹出动画（200ms） | 操作不再可用 |
| **error** | 红色左边框（3px），红色 ✗ 标记在右上角，抖动动画（300ms） | 显示重试按钮 |
| **disabled** | 灰色调（所有元素透明度 50%），无阴影 | 不可交互 |

### 4.4 响应式断点行为

| 断点 | 行为 |
|------|------|
| ≥ 1024px（桌面） | 推荐卡片 1 列（每个卡片完整展示）。维度卡片 2×3 网格 |
| 768-1023px（平板） | 推荐卡片 1 列。维度卡片 3×2 网格或 2 列 |
| 320-767px（移动） | 所有卡片 1 列。卡片左右填充 +16px。Metrics 和 Action Button 换行展示 |

**关键规则：卡片永不水平溢出。宁可从网格变为 1 列，也不允许水平滚动或截断内容。**

### 4.5 卡片分组

当多个卡片需要分组时：

- **列表** — 纵向排列，每个卡片独立。卡片间间距 12px。适用于推荐列表
- **网格** — 多列网格排列。间距 16px。适用于维度卡片
- **堆叠** — 带分组标题的纵向排列。分组标题灰色加粗。适用于按渠道分组的发布卡片

所有分组类型支持"加载更多"（如果有超过 10 个卡片需要展示）。

## 5. AI Result Pattern（AI 结果模式）

### 5.1 统一结构

所有 AI 输出结果遵循以下结构：

```
┌──────────────────────────────────────────────┐
│  AI Summary (一句话"发生了什么")               │
│  ──────────────────────────────────          │
│  Key Findings (2-3 个核心发现)                │
│  ──────────────────────────────────          │
│  Evidence (支撑每个发现的数据/来源)             │
│  ──────────────────────────────────          │
│  Confidence (AI 对自己结果的确定度)             │
│  ──────────────────────────────────          │
│  Recommendation (基于结果建议)                 │
└──────────────────────────────────────────────┘
```

### 5.2 各元素规范

#### AI Summary

| 属性 | 值 |
|------|-----|
| **内容** | 一句话总结 AI 操作的结果。使用"发生了什么"的句式 |
| **字数** | ≤ 20 字 |
| **展示条件** | 始终展示。这是 AI 结果的第一屏 |
| **语气** | 确定、事实性。使用完成时态（"已更新"、"已验证"） |
| **示例** | "品牌描述已更新，Brand Health +15 分"、"AI 对云栖咖啡的了解还不够全面" |

#### Key Findings

| 属性 | 值 |
|------|-----|
| **内容** | 2-3 个核心发现。每个发现一句话 |
| **字数** | 每个 ≤ 25 字 |
| **展示条件** | 有 1 个以上核心发现时展示。0 个发现时隐藏 |
| **格式** | 无序列表，每个发现前有 bullet 或 ✓/✗ |
| **示例** | `✓ 官网已收录` · `✗ 首页缺少品牌介绍段落` · `✗ About 页面返回 404` |

#### Evidence

| 属性 | 值 |
|------|-----|
| **内容** | 支撑每个发现的数据来源或链接 |
| **展示条件** | 默认隐藏（用户点击"查看证据"后展开）。展示条件同 Key Findings |
| **格式** | 与 Key Findings 一一对应。来源名 + URL（如可链接） |
| **示例** | "来源：官网首页 /about 页面 / 社交媒体简介" |

#### Confidence

| 属性 | 值 |
|------|-----|
| **内容** | AI 对自己结果的确定度。非技术性展示 |
| **展示条件** | 始终展示。但用小型标签（Badge）形式 |
| **格式** | HIGH → "高"（绿色 Badge）。MEDIUM → "中等"（黄色）。LOW → "低"（灰色 Badge） |
| **重要** | 不对用户展示 "confidence" 这个技术词。使用"AI 对此分析的可靠程度：高" |

#### Recommendation

| 属性 | 值 |
|------|-----|
| **内容** | 基于结果的建议。用户接下来可以做什么 |
| **展示条件** | 有可操作建议时展示。无建议时不展示 |
| **格式** | 一句话建议 + CTA 按钮 |
| **示例** | "建议优化品牌描述以提升知识覆盖" + [开始优化] |

### 5.3 展示模式

| 模式 | 展示内容 | 使用场景 |
|------|---------|---------|
| **Compact（紧凑）** | Summary + Confidence + Recommend | 列表页中的每项 AI 结果（如 Recommendations 每个卡片） |
| **Standard（标准）** | Summary + Key Findings + Confidence + Recommend | AI 操作的直接结果展示（如扫描完成、验证完成） |
| **Expanded（完整）** | Summary + Key Findings + Evidence + Confidence + Recommend | 用户点击"查看详情"或 Explain Drawer 内的完整 AI 结果 |

### 5.4 折叠/展开规则

| 场景 | 默认状态 | 用户操作 |
|------|---------|---------|
| AI 结果显示在页面主体 | 展开 Standard 模式 | 无折叠操作 |
| AI 结果显示在卡片内 | Compact 模式（只展示 Summary） | 点击"了解为什么"展开至 Standard |
| AI 结果显示在 Explain Drawer | Expanded 模式（完整展示） | Evidence 部分默认折叠，需点击展开 |

### 5.5 什么时候不展示

| 场景 | 替代展示 |
|------|---------|
| AI 不可用 | 展示 Error Empty State（"AI 服务暂时不可用"） |
| AI 正在计算 | 展示 Loading Pattern（Skeleton 或 Progress） |
| 无 AI 输出内容 | 展示 Empty Result（"AI 暂时无法分析，建议稍后重试"） |
| 内容是用户输入（非 AI 生成） | 不展示 AI Result Pattern |

## 6. Explain Pattern（Explain 模式）

### 6.1 三种 Explain 层级

#### L1: Inline Explain（行内解释）

| 属性 | 值 |
|------|-----|
| **形式** | 一句话，展示在结果旁边 |
| **字数** | ≤ 15 字 |
| **使用场景** | 列表项、Card 摘要、分数旁边、关键指标旁 |
| **视觉** | 灰色小字（0.75em-0.875em），紧跟在结果右侧或下方 |
| **交互** | 纯文本（不可点击）。信息不足时使用"了解为什么"链接引导到 L2 |
| **示例** | "+15 — 因为添加了品牌描述" / "45 — AI 对你的品牌还不够了解" |

#### L2: Drawer Explain（侧边栏解释）

| 属性 | 值 |
|------|-----|
| **形式** | 从右侧滑出的 Drawer。宽度 min(540px, 90vw) |
| **使用场景** | 用户点击"了解为什么"后 |
| **内容结构** | What (发生了什么) → Why (为什么) → Evidence (证据来源) → Impact (影响维度) |
| **与 Interaction Architecture 对接** | Interaction Architecture Step 4（Explain）的完整实现 |
| **打开** | 点击"了解为什么" → 200ms ease-in-out 滑入 |
| **关闭** | 点击 ✕ 或遮罩层 → 200ms ease-in-out 滑出 |
| **Drawer 内 CTA** | 关闭 Drawer 并执行对应操作 |

**L2 Drawer 内容模板：**

```
┌──────────────────────────────────────────────┐
│  ✕ 关闭                                        │
│                                                │
│  为什么推荐"添加品牌描述"？                        │
│                                                │
│  ── 发生了什么 ──                                │
│  AI 扫描发现云栖咖啡的官网首页缺少品牌介绍段落。        │
│                                                │
│  ── 为什么 ──                                    │
│  没有品牌描述，AI 无法在推荐时准确理解云栖咖啡：        │
│  • 不知道云栖咖啡是一家什么公司                     │
│  • 不知道产品特点是什么                           │
│  • 不知道应该推荐给什么样的用户                     │
│                                                │
│  ── 证据来源 ──                                   │
│  ✓ 官网首页 — 无品牌介绍段落                       │
│  ✓ About 页面 — 返回 404                          │
│  ✓ 社交媒体简介 — 不完整信息                       │
│                                                │
│  ── 影响维度 ──                                   │
│  知识覆盖 (+12) + AI 可见性 (+3) = **+15 分**       │
│  预期 Brand Health 从 **45 → 60**                │
│                                                │
│  [ 开始优化 ]                                    │
└──────────────────────────────────────────────┘
```

#### L3: Full Explain（完整解释页）

| 属性 | 值 |
|------|-----|
| **形式** | 独立页面（非 overlay），可从导航或 Drawer 进入 |
| **使用场景** | 深度分析、对比历史、趋势追踪 |
| **内容** | 包含 L2 所有内容 + 趋势图 + 对比数据 + 历史变化时间线 |
| **何时使用** | 用户需要了解品牌变化的历史全貌时。例如 Growth 页面、完整的 Verification 报告 |
| **URL** | 独立路由，可分享可收藏 |

### 6.2 三种层级的适用场景

| 内容类型 | 默认层级 | 可切换至 |
|---------|---------|---------|
| Health 页面总分 | L1（Inline） | L2（Drawer） |
| 维度卡片分数 | L1（Inline "了解为什么"） | L2（Drawer） |
| Recommendation 卡片 | L1（Compact Summary） | L2（Drawer） |
| Verification 对比 | L1（数量变化） | L2（Drawer）→ L3（完整页） |
| Mission 执行结果 | L1（Inline "+15"） | L2（Drawer） |
| Growth 趋势变化 | L1（Inline "上升因为..."） | L3（完整页） |
| Publishing 发布状态 | L1（Inline 状态标签） | L2（Drawer） |
