## 二、当前断裂状态 vs 目标状态

### 当前（崩溃）

```

    ↓
Governance.Tenant ← 完全孤立
```

```
    ↓ 1:1 bridge

    ↓ context read
Governance.Role.capabilities → Approval Permission

    ↓
OperationEvent 覆盖所有关键业务动作
```

## 三、5 条 Frozen Contracts

### Contract 1: Tenant Identity Bridge

**核心**：Enterprise `tenantId` 与 Governance `Tenant.id` 的渐进式桥接

```
Phase 1: ADD COLUMN
  Enterprise核心表新增 governanceTenantId TEXT nullable

Phase 2: DUAL WRITE  
  写入时：tenantId = userId（旧）+ governanceTenantId = lookup(userId)（新）

Phase 3: READ SWITCH
  读取走 governanceTenantId
  tenantId 作为 legacy 保留

Phase 4: BACKFILL（可选）
  已有的 Enterprise 记录，通过 userId → GovUser.tenantId → Tenant.id 回填
```

**规则**：
- `governanceTenantId` 不可为空后，旧 `tenantId` 只读不写
- 不删除旧 `tenantId` 列（向后兼容）
- Migration 可回滚

### Contract 2: Enterprise Context

**核心**：请求上下文传入 Governance Tenant，不再隐式假设

```typescript
// BEFORE（当前）
const tenantId = authStore.tenantId  // = userId
await service.method(tenantId, ...)

// AFTER（目标）
const ctx = await enterpriseContext.resolve(authStore.userId)
// ctx = { userId, governanceTenantId, organizationId, roleCodes }
await service.method(ctx, ...)
```

### Contract 3: Approval Permission

**核心**: Action Approval 关联 `GovUser` + 权限校验来自 `Role.capabilities`

**字段变更**：
```
EnterpriseAction:
  + approvedByGovUserId TEXT nullable  → 关联 governance_user.id
  - approvedBy TEXT → 保留为显示名冗余（不删）
```

**逻辑**：
```typescript
async function approveAction(actionId, govUserId) {
  // 1. 查找 GovUser
  const govUser = await prisma.govUser.findUnique({ where: { id: govUserId }})
  if (!govUser) throw new GovUserNotFoundError()
  
  // 2. 查找 Role
  const role = await prisma.role.findUnique({ where: { id: govUser.roleId }})
  
  // 3. 校验 Capability
  const caps = JSON.parse(role.capabilities || '[]')
  if (!caps.includes('action.approve')) {
    throw new PermissionDeniedError('action.approve required')
  }
  
  // 4. 写入
  await prisma.enterpriseAction.update({
    where: { id: actionId },
    data: {
      approvedByGovUserId: govUserId,
      approvedBy: govUser.name,  // 冗余显示名
      approvedAt: new Date(),
    }
  })
}
```

### Contract 4: Audit Integration

**核心**: Action 状态变更同步写入 `Governance.AuditLog`

**规则**：
- `status_history` JSONB **保留**（快速查询历史）
- 每次变更**同步插入** `Governance.AuditLog` 表（企业统一审计）
- 字段映射：
  ```
  AuditLog.tenantId = action.governanceTenantId
  AuditLog.actorId = 操作者GovUser.id
  AuditLog.actorType = 'gov_user'
  AuditLog.action = 'action.status_change'
  AuditLog.targetType = 'enterprise_action'
  AuditLog.targetId = action.id
  AuditLog.metadata = { from: oldStatus, to: newStatus }
  ```

### Contract 5: Migration Strategy

**核心**：不破坏现有数据，渐进式迁移

```
Step 1: 新增 nullable 列 + 索引（不锁表）
Step 2: 双写（旧代码读旧列，新代码读新列）
Step 3: 后台 Job 回填旧记录 governanceTenantId
Step 4: 切换读取路径
Step 5: 观察 7 天后，决定是否删除旧列
```

**回滚**：
- 每步都有对应 down migration
- governanceTenantId nullable → 可以随时清空回退
- 双写期间可以关掉新列写入

## 五、Service 变更

### 5.1 新增 Service: `enterprise-context.service.ts`

```typescript
interface EnterpriseContext {
  userId: string
  governanceTenantId: string | null
  organizationId: string | null
  roleCodes: string[]
}

class EnterpriseContextService {
  async resolve(userId: string): Promise<EnterpriseContext>
  async getGovernanceTenantId(userId: string): Promise<string | null>
}
```

**逻辑**：
```
resolve(userId):
  1. 查找 User
  2. 查找 GovUser（userId → govUser.tenantId）
  3. 找不到 → 检查是否有 Membership.tenantId 映射
  4. 返回 context
```

### 5.2 修改 Service: `action-approval.service.ts`

新增方法：
```typescript
async function approveActionWithPermission(
  actionId: string,
  govUserId: string
): Promise<EnterpriseAction>
```

修改现有 `approveAction`：
- 保留旧签名（向后兼容）
- 新增 `@approveActionWithPermission` 为推荐入口
- 旧入口标记 `@deprecated 4.2.3.1`

### 5.3 修改 Service: 4 个核心 Service 加 governanceTenantId
