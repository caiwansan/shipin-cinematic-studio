## Case 3: 无 BYOK 用户 Fallback 日志

#### 运行时日志（重启后）

```

```

这些是全局模型同步的日志，不是 Career Agent 相关的。

#### 代码层面

`resolveRuntimeConfig.ts` Section 6:
```
env fallback: 写 [MODEL_RUNTIME_FALLBACK] 日志, reason=USER_MODEL_CONFIG_MISSING
```

但此日志需要用户实际调用 Career Agent 并触发 LLM 请求时才写入。目前无 `05d00ac2` 用户的实际聊天日志。

#### 平台层 API Key

启动日志有：
```
[startup] Loaded API key: career_advisor Business AI Key (business_type_career_advisor)
```

这是 **career_advisor**（免费层）的 API Key，走的是 `JobCareerEngine`（processWithEngine），不是 Hermes Runtime。

Career Agent 的 Runtime 不读取这个 key — 它走用户 BYOK 或 fallback 到 `env_default`（全局环境变量 DEEPSEEK_API_KEY / OPENAI_API_KEY）。

#### 结论

✅ 代码路径定义清晰：
```
无 BYOK + career_agent → 跳过 3 层 → 环境变量 fallback → [MODEL_RUNTIME_FALLBACK] 日志
```

⏳ 需要用户 `05d00ac2`（已购买无配置）实际发送一条消息来触发 fallback 日志。

## Case 4: 到期行为记录

### 审计方法：数据库 + 代码

#### 当前到期处理

系统中**无任何到期自动处理**：
- 无 cron 检查 `governance_subscription.endDate`
- 无 lifecycle 状态变化逻辑（`PAUSED` / `STOPPED` 只用于企业 AI 员工手动管理）
- 无到期通知

到期后各场景行为：

| 场景 | 校验入口 | 到期后 |
|------|---------|--------|
| F1 路由 → `hasCareerAgent()` | 只看 record 存在 | ✅ chat 继续工作 |
| Orchestrator `getOrCreateAgentContext()` | 只看 `getCareerAgent()` 返回 | ✅ 继续工作 |
| 激活端点 | `checkProvisionEntitlement()` → subscription status | ⛔ 403 ENTITLEMENT_REQUIRED |
| `createAndDeploy()` | `checkProvisionEntitlement()` | ⛔ 创建被阻止 |
| `checkProvisionEntitlement()` | 查询 governance_subscription | ❌ subscription 不 active |

#### 当前到期数据

订阅表中最近到期记录：
```sql
-- 3 个活跃订阅，无过期记录
-- 管理员通过手动 confirm 创建订阅
```

#### Decision Record

| 问题 | 当前状态 | 影响 |
|------|---------|------|
| 到期后 Agent 是否继续运行？ | ✅ 继续运行（代码层面不阻止） | 用户可继续使用已购服务 |
