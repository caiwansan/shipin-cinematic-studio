### 1.2 Hero 区设计

| 元素 | 内容 | 目标 |
|------|------|------|
| **问候语** | "早上好，[Company Name] 的 AI 部门已运行 [X] 天" | 建立归属感 |
| **关键 KPI** | Signals / Decisions / Actions / Outcome 四卡片 | 3秒理解全局 |
| **主操作** | "Review 3 Decisions" 一键跳跃 | 缩短决策路径 |
| **信息层级** | Intelligence → Decision → Execution → Outcome | 遵循 Observe→Act→Learn |

### 1.3 核心 KPI（今日智能）

```
Signals:    12    (↑ 3 from yesterday)  — 从 Channel Interaction 检测到
Decisions:  3     (2 pending approval)  — 需要 CEO 判断
Actions:    8     (4 completed, 4 active) — AI 员工执行中
Outcome:    +15%  (vs last week)        — 学习反馈
```

### 1.4 主操作入口

| 角色 | 第一眼操作 | 路径 |
|------|-----------|------|
| CEO | "3 decisions need your review" | → Decision Center |
| 部门负责人 | "4 actions pending approval" | → Approval Center |
| 运营人员 | "24 new interactions" | → Interaction Center |
| 管理员 | "System healthy" | → Governance |

### 2.1 IA 设计原则

| 原则 | 实现 |
|------|------|
| **Observe → Understand → Decide → Act → Govern → Learn** | 左侧导航按此顺序排列 |
| **信息 scent** | 每个 Section 图标 + 标签 + 数字徽章 |
| **渐进披露** | 三级以内到达任何功能 |
| **角色感知** | CEO 默认见 Command Center；运营人员默认见 Execution |

## 六、Design System 审查

### 6.1 当前 Design System 资产

| 类别 | 当前状态 | 问题 |
|------|---------|------|
| **Color Palette** | ⚠️ 部分 CSS 变量 | 缺乏 Enterprise 专用暗色主题 |
| **Typography** | ⚠️ 字体不统一 | 缺少层级系统 (h1-h6 + body + caption) |
| **Spacing** | ⚠️ 硬编码 尾风/内联 | 未统一 spacing scale (4/8/12/16/24/32/48) |
| **Card** | ❌ 无统一 Card 组件 | 每个页面用不同样式 |
| **Button** | ❌ 无统一 Button 组件 | 内联 button + 不同 class |
| **Badge/Tag** | ❌ 无统一 Badge 组件 | 各处临时实现 |
| **KPI/Metric** | ❌ 无统一 Metric 组件 | 数字展示方式不统一 |
| **Icon** | ⚠️ 混合使用 emoji + SVG | emoji 不适合企业级产品 |
| **Loading State** | ⚠️ 部分骨架屏 | 不统一 |
| **Empty State** | ⚠️ 部分实现 | 缺少情感化设计 |
| **Data Visualization** | ❌ 无统一 Chart 组件 | 缺少 ApexCharts/ECharts 集成 |

## 七、Enterprise 高级感审查

### 7.1 当前感知 vs 目标感知

| 维度 | 当前（后台管理系统） | 目标（AI 企业驾驶舱） |
|------|-------------------|---------------------|
| **视觉** | 白色背景 + 表格堆叠 | 暗色主题 + 数据可视化 |
| **信息** | 平铺所有功能 | 层次化信息架构 |
| **交互** | CRUD 表单为主 | 命令式交互 + 智能建议 |
| **语言** | "管理XX" | "Command · Intelligence · Governance" |
| **反馈** | 手动刷新 | 实时 Signal + 推送 |
| **移动端** | 不响应 | 适配 CEO 手机查看 |

### 7.2 视觉语言升级

**当前（Admin UI 风格）：**
- 白色背景 `#ffffff`
- 黑色文字 `#333`
- 蓝色链接 `#1890ff`
- 表格 + 表单

**目标（Command Center 风格）：**
- 深蓝黑背景 `#0a0e1a`
- 数据高亮（蓝/紫/绿/琥珀）
- 卡片化信息展示
- 实时指标趋势
- 微动画（Signal 脉冲、Outcome 进度环）

### 7.3 「AI 企业驾驶舱」特征清单

| 特征 | 实现 | 当前状态 |
|------|------|---------|
| **Hero 区 Today Intelligence** | 四 KPI 卡片 + 趋势图 | ❌ 缺失 |
| **实时数据流** | Signal 实时更新 | ⚠️ 手动刷新 |
| **决策建议流** | "AI recommends..." 卡片 | ❌ 缺失 |
| **执行进度条** | Action 完成度可视化 | ⚠️ 文本显示 |
| **Outcome 学习环** | 反馈循环可视化 | ❌ 缺失 |
| **渠道健康图** | Connected/Sync/Error 状态 | ⚠️ 简单标记 |
| **风险 + 机会** | 异常检测 + 机会提示 | ❌ 缺失 |

### 7.4 情感化设计

## 八、Gate 5 — Enterprise Experience Gate

### 8.1 验收流程

```
用户登录
  ↓
进入企业首页（Command Center）
  ↓
3秒内回答："我的企业今天状态如何？"
  ↓
点击一个 Decision
  ↓
看到证据 + 理解 AI 的推荐理由
  ↓
接受/拒绝 Action
  ↓
看到执行状态实时更新
  ↓
看到结果反馈（Outcome）
  ↓
理解系统如何从反馈中学习
```

### 8.2 验收检查表

| # | 检查项 | 通过标准 | 当前状态 |
|---|--------|---------|---------|
| 1 | **3 秒理解** | 用户登录后 3 秒内能看到 Today Intelligence 四卡片 | ❌ |
| 2 | **Decision 路径** | 从首页到 Decision Detail ≤ 2 次点击 | ❌ |
| 3 | **Evidence 可见** | Decision 页面能直接看到 Evidence Graph | ❌ |
| 4 | **Action 追踪** | Action 从 approved → executing → completed 状态可见 | ⚠️ 部分 |
| 5 | **Outcome 反馈** | Outcome 验证后能看到对下次决策的影响 | ❌ |
| 6 | **Channel 实时** | Interactions 同步后 30s 内反映到 Signal | ❌ |
