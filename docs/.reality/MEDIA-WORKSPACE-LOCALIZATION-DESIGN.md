## 一、定位结论

> **新媒体运营 = 昆仑镜第一个本地 AI 应用生态示范产品（Kunlun Media App）**

它同时验证四条生态能力：
1. **应用市场**（Kunlun Media 作为可安装应用）
2. **本地运行时**（Electron + 本地浏览器控制）
3. **插件模式**（AI 新媒体运营经理 = 第一个 agent 插件）
4. **订阅商业**（免费应用 + 付费插件）

**不是**「继续修补旧线上设计」——线上账号体系继续存在（Online First），但**登录/浏览器/凭证的落地位置从服务器迁向用户本地设备**，这是解决登录稳定性问题的根本路径而非补丁。

## 二、为什么新媒体适合第一个本地应用（复盘根因）

| 线上痛点（已实锤） | 本地化的根治 |
|-------------------|-------------|
| 服务器 IP（数据中心）触发平台风控——快手 cp.kuaishou.com 登录态多次失效（rest result=109） | 本地家庭/办公 IP 登录，风控概率大幅下降 |
| 服务器端长驻浏览器资源昂贵、进程易被回收 | 本地 Chromium，用户设备承载，随开随用 |
| 凭证存服务器，安全边界大 | 凭证本地加密存储（系统钥匙串），线上仅存授权引用 |
| 扫码会话被服务端重启/风控破坏 | 本地浏览器会话由用户自己设备持有，生命周期可控 |
| 多账号矩阵受服务器资源限制 | 本地多 profile 天然隔离，资源按需 |

**核心认知转变**：新媒体登录不是 OAuth 服务端授权，而是**设备级会话管理**——设备在用户手里，会话才稳定。这正是「Local 只是发行形态」原则的例外补充：**业务逻辑仍在线上，但设备会话在本地**。

## 四、能力归属划分（免费 vs 插件）

## 五、账号安全设计（新媒体专属）

### 5.1 凭证分层

```
线上（SSOT，仅存引用）：
  EnterpriseChannelAccount：externalAccountId / accountName / 状态 / 加密引用
  credentialEncrypted：仅存「本地凭证索引」（deviceId + vaultKeyId），不存平台 cookie

本地（设备）：
  Credential Vault：平台 cookie/会话，AES + 系统钥匙串加密
  绑定：deviceId + 账号 → 只有授权设备可解
```

### 5.2 授权模型（复用并强化）

- **设备绑定**：账号 ↔ 设备指纹（本地登录的账号绑定到该设备），换设备需重新扫码验证。
- **访问控制**：沿用 ChannelAccessService 的 owner ∪ share 模型（已实锤修复 IDOR/串号问题），MANAGE 权限才可管理凭证。
- **退出即清**：退出登录 = 本地 vault 清除 + 线上 credential 销毁 + workspace DESTROYED（生命周期闭环已实现）。
- **风控应对**：本地 IP + 单账号单 profile + 登录频率限制 + 异常登录检测（异地设备扫码需短信确认）。

### 5.3 与线上一致性

- 本地登录成功 → 线上同步「已连接 + 身份 + 最近验证时间」——**刷新页面/换设备仍可见账号**（SSOT 不变）。
- 本地离线时：线上显示「设备离线」，账号不消失（区别于旧版「刷新丢失」问题）。

## 六、本地浏览器管理

| 项 | 设计 |
|----|------|
| 内核 | 本地 Chromium（Electron 内嵌 / 独立安装） |
| Profile | 每账号独立 profile 目录（本地，非服务器），路径 `~/kunlun-media/profiles/{platform}/{accountId}` |
| 会话 | 本地持久化登录态；线上只记录「已连接」状态 |
| 多开 | 单账号单 profile；多账号多 profile 隔离（防串号，复用 FIX-03 经验） |
| 升级 | Chromium 随应用升级；profile 兼容性检测 |
| 清理 | 退出登录 → 清 profile；异常残留 → 应用内「环境清理」工具 |
| 遥测 | 登录成功率/风控拦截率上报（脱敏），用于平台侧登录稳定性看板 |

## 七、线上商城授权闭环（本地 ↔ 云端）

**在线授权（技术总监强调：到期必须续订，防永久破解）**：

```
用户在商城（线上）购买「AI内容运营经理」订阅
  → 生成 License（绑定用户+设备数）
  → 本地 App 启动 → Hermes（KAOR）启动 → 连接昆仑镜 License Server
  → 校验：用户身份 + 订阅状态 + 插件授权
  → 通过 → 插件加载（能力解锁，本地 agent 实例 + 云端权限闸门）
  → 订阅到期 → 插件进入 Expired（能力暂停，数据保留 30 天）
  → 应用基础功能继续（免费能力不受影响）
```

- **插件执行位置**：AI 员工编排在云端 Hermes（账号数据/指标在线上），浏览器/凭证操作在本地 Device Bridge——云端与本地协同，插件 Manifest 声明需要哪些本地能力。
- **计费**：模型调用走 Model Gateway 自动记账（订阅内含额度，超出按量）。

## 八、Reality Gate（新媒体本地化验收标准）

| # | 验收项 | 判定 |
|---|--------|------|
| 1 | 本地安装 Kunlun Media → 注册/登录线上账号 | 通过 |
| 2 | 本地扫码连接快手 → 线上账号列表出现 CONNECTED + 身份 | 通过 |

| 4 | 退出登录 → 本地凭证清空 + 线上 LOGGED_OUT + 环境清理 | 通过 |

| 6 | 安装付费插件 → License 生效 → 能力解锁 | 通过 |
| 7 | 取消订阅 → 能力暂停，数据保留 | 通过 |
| 8 | 换设备 → 需重新扫码授权（设备绑定生效） | 通过 |
| 9 | 线上刷新/重启 → 账号不丢（SSOT 持久化） | 通过 |
