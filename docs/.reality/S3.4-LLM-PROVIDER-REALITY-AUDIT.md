## 2. Gateway Invoke Path（invokeAI 流程）

```
invokeAI(envelope)
  → gatewayGuard（内存速率/并发限制）
  → userModelResolver.resolve(capability, userId)   ← BYOK V2
  → null → failEnvelope("用户未配置模型")           ← 硬失败, 无平台默认 fallback
  → 选 adapter（aliyun/volcengine/deepseek/openai）
  → 执行（超时 30s + 重试 2 次）
  → InvocationLog 审计
```

关键事实：**gateway 无平台默认 Key fallback**——`resolve()` 返回 null 即失败。

## 3. BYOK 现状（UserModelConfigV2）

- schema 存在（llmProvider/llmApiKey/llmModel/llmEnabled, apiKey 加密存储）
- **表未迁移**（`relation "userModelConfigV2" does not exist`）
- → 任何用户 resolve 都返回 null → 所有 invokeAI 调用失败

## 4. 阻断结论（两层）

```
L1: 环境无可用 LLM Key（DEEPSEEK 未配 / OPENAI 占位 / 无 ollama）
L2: 即使有 env Key, Gateway 强制 BYOK（用户配置表未建）→ 仍需用户级配置
```

**D3「使用已有平台 env Key」前置假设不成立**——这是 Reality First 原则的正确拦截。
