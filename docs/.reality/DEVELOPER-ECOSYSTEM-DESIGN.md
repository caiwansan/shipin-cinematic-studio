## 一、目标

任何开发者（个人/团队/企业）可以：**开发 AI 员工 → 提交审核 → 商城发布 → 订阅收益**。

### 1.1 开发者画像

| 类型 | 能力 | 典型产出 |
|------|------|---------|
| 独立开发者 | 会调 LLM API、写 Prompt | AI 员工插件（低代码模板化） |
| 团队开发者 | 会写 TS/Node | Tool 插件 + Workflow 插件 |
| 企业开发者 | 有行业 know-how | 行业垂直 AI 员工（法律/医疗/电商） |
| 集成商 | 有客户资源 | 定制工作台 + 插件组合 |

## 二、开发者中心（Developer Center）流程

```
开发者注册（个人实名 / 企业认证）
    ↓
创建插件（选择类型：agent/tool/workflow）
    ↓
SDK 开发（Hermes SDK + CLI 脚手架）
    ↓
本地测试（沙箱模拟器）
    ↓
提交审核（自动化 + 人工）
    ↓
商城发布（灰度 → 全量）
    ↓
收益分成（订阅收入月度结算）
```

### 2.1 关键环节设计

| 环节 | 设计 |
|------|------|
| **注册认证** | 个人：手机号+实名；企业：营业执照（复用 gov 体系 OrgMember） |
| **脚手架** | `kunlun plugin init media-manager` 生成项目骨架 + Manifest 模板 + 本地沙箱调试器 |
| **SDK** | `@kunlun/hermes-sdk`（见 HERMES-RUNTIME-EVOLUTION-DESIGN 接口契约）+ `@kunlun/platform-sdk`（身份/权限/模型/存储） |
| **模拟器** | 本地沙箱：模拟 Hermes 运行时 + 平台 API 桩，开发者离线调试 |
| **测试环境** | 云端测试租户（隔离正式数据），自动跑 Reality Gate 脚本（安装/运行/计费/审计） |
| **审核** | 自动化（Manifest 校验、权限扫描、病毒扫描、依赖漏洞）+ 人工（功能抽查、合规） |
| **发布** | 灰度白名单 → 观察指标（安装/崩溃/退款率）→ 全量 |

## 三、开发者工具链

```
CLI（kunlun）
  ├─ plugin init / dev / test / build / upload / version
  ├─ 本地沙箱调试（hot reload）
  └─ 提交审核 / 查看审核状态

开发者控制台（/developer）
  ├─ 我的插件（列表/状态/版本）
  ├─ 数据看板（安装量/订阅收入/退款率/评分）
  ├─ 收益（RevenueRecord 明细/钱包/提现）
  ├─ 审核记录
  └─ API 密钥管理（模型调用额度）
```

## 四、开发者收益与激励

| 机制 | 设计 |
|------|------|
| 分成 | 订阅收入 50%（见 PLUGIN-MARKETPLACE-DESIGN 分账模型） |
| 首月加速 | 新插件首月平台分成降至 10%（扶持期） |
| 优秀插件 | 商城首页推荐位 + 平台联合推广（流量位） |
| 开发者等级 | 基于累计收入/插件质量分级，高级别享更优分成与支持（客服/联合营销） |
| 认证开发者 | 企业认证开发者可申请「企业专属插件」（私有商城） |

**禁止**：开发者之间刷量、虚假订阅、诱导好评——平台审计 + 惩罚（冻结分成/下架）。

## 五、插件质量体系

| 维度 | 指标 | 门槛 |
|------|------|------|
| 功能 | Reality Gate 全链路通过 | 强制 |
| 稳定性 | 运行崩溃率 < 0.5% | 审核 + 灰度观察 |
| 安全 | 权限扫描 0 高危 | 强制 |
| 体验 | 安装成功率 > 99% | 灰度观察 |
| 商业 | 退款率 < 10% | 灰度观察 |
| 维护 | 版本活跃（180 天内更新） | 长期未更新降权 |

## 六、风险与治理

| 风险 | 治理 |
|------|------|
| 低质插件泛滥 | 质量门槛 + 评分体系 + 下架机制 |
| 恶意插件（窃数据） | 沙箱 + 权限最小化 + 审计 + 举报 |
| 开发者流失 | 分成吸引力（50%）+ 低门槛 SDK + 扶持期 |
| 平台与开发者争利 | 平台只做「发行+基础设施」，不自研竞争性插件（平台插件走同一审核流程） |
